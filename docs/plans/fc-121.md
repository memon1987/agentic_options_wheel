**The lazy imports are the risk.** A missed one does not fail at import or at service start; it fails the first time that code path runs (a sim submit, a battery Saturday). T-1 exists for exactly this.

**`engine_identity` hashes every file under `src/`** (`scenarios/engine_identity.py` module docstring). Any `src/**` edit — including a comment — moves it: every stored `sweep_key` misses once and the next Saturday battery replays cold. `deploy/`, `main.py`, `tests/`, `docs/`, `dashboard/` and `cloudbuild.yaml` are outside the hash. This is what decides the PR split.

## Goals

1. No screen-only code, endpoint, CLI command, test, or config reference remains in the tree.
2. The sim service, the sweep CLI/Job, the backfill and the battery behave exactly as before; `ENGINE_VERSION`'s **value** does not change; replay numerics do not change.
3. `ENGINE_VERSION` has ONE engine-side declaration (plus the deliberate dashboard duplicate).
4. The live GCP footprint matches the tree: no `backtest-screen` Job, no `monthly-performance-review` scheduler, the Job-failure policy watches only Jobs that exist.

## Non-goals

- **`options_wheel.backtest_runs` is kept** (D-1). No DDL, no data change.
- **`evaluate.py` and `--command backtest` stay.** They are the single-symbol evaluate mode, not the screen; `scenarios/runner.py:98` imports `_score` and the haircut constants from `evaluate`, and plans use `--command backtest` for no-lake identity proofs.
- **User-facing report strings are NOT edited** — `scenarios/report.py:108/750/758/941` and `dashboard/backend/services/sweep_report_text.py:82` say a sweep never writes to `backtest_runs`. Still true (the table exists), and editing them moves report bytes and their golden fixtures. Code comments only.
- **`ENGINE_VERSION` is not bumped.** A bump declares a new measurement; this is a move and a delete.
- No change to the simulator's `_failed_symbols` snapshot/restore (`engine/simulator.py:1002–1012`) — it also protects multi-replay processes (sweeps). Comment only.
- Not the `options-wheel-roll-friday` scheduler's docs (it has none beyond `docs/CLAUDE.md:137`, which already says it is to be deleted) — its deletion is an operator ride-along below.

## Proposed approach

Two PRs, split by blast radius and by the identity boundary. **PR-1 must merge before PR-2** (PR-1 removes the route that lazily imports `run_screen`; PR-2 deletes `run_screen`).

### DD-1 — why two PRs and not one
PR-1 changes the LIVE trading server file (`deploy/cloud_run_server.py`) and monitoring config, nothing under `src/**`, no identity move. PR-2 changes the sim stack's imports and moves the identity. Different services, different rollback: reverting a broken re-home must not resurrect the endpoint, and vice versa. Rejected: one PR (one review cycle, but a single revert unit across the trading service and the sim service). **Caveat (rev 3, review A):** the independence is one-directional. Once PR-2 merges, a revert of PR-1 would resurrect a route and three test classes that import the deleted `src.backtesting.screen`, so PR-1's revert window closes at PR-2's merge — which is why R-0 below must pass before PR-2 is cut.
