## Context

The monthly screen was retired on 2026-10-02: the operator paused `monthly-performance-review` after seven full runs produced identical, never-acted-on verdicts that the weekly battery already writes to `scenario_runs` (`docs/BACKTEST_ENGINE.md` §Track D; FC-091 closeout). Its code, endpoint, Job, scheduler and policy references are still in the tree. The operator's instruction is to remove them: the codebase is growing and dead code should not sit around.

It is **not** a clean delete. `src/backtesting/screen.py` and `src/backtesting/reporting/bq_writer.py` each carry something the LIVE sim stack imports. Line numbers below are at `39a74c9`.

**The lazy imports are the risk.** A missed one does not fail at import or at service start; it fails the first time that code path runs (a sim submit, a battery Saturday). T-1 exists for exactly this.

**`engine_identity` hashes every file under `src/`** (`scenarios/engine_identity.py` module docstring). Any `src/**` edit — including a comment — moves it: every stored `sweep_key` misses once and the next Saturday battery replays cold. `deploy/`, `main.py`, `tests/`, `docs/`, `dashboard/` and `cloudbuild.yaml` are outside the hash. This is what decides the PR split.

## Goals

1. No screen-only code, endpoint, CLI command, test, or config reference remains in the tree.
2. The sim service, the sweep CLI/Job, the backfill and the battery behave exactly as before; `ENGINE_VERSION`'s **value** does not change; replay numerics do not change.
3. `ENGINE_VERSION` has ONE engine-side declaration (plus the deliberate dashboard duplicate).
4. The live GCP footprint matches the tree: no `backtest-screen` Job, no `monthly-performance-review` scheduler, the Job-failure policy watches only Jobs that exist.

## Non-goals

- **`options_wheel.backtest_runs` is kept** (D-1). No DDL, no data change.
- **`evaluate.py` and `--command backtest` stay.** They are the single-symbol evaluate mode, not the screen; `scenarios/runner.py:98` imports `_score` and the haircut constants from `evaluate`, and plans use `--command backtest` for no-lake identity proofs.
- **User-facing report strings are NOT edited** — `scenarios/report.py:108/750/758/941` and `dashboard/backend/services/sweep_report_text.py:82` say a sweep never writes to `backtest_runs`. Still true (the table exists), and editing them moves report bytes and their golden fixtures. Code comments only.
- **`ENGINE_VERSION` is not bumped.** A bump declares a new measurement; this is a move and a delete.
- No change to the simulator's `_failed_symbols` snapshot/restore (`engine/simulator.py:1002–1012`) — it also protects multi-replay processes (sweeps). Comment only.
- Not the `options-wheel-roll-friday` scheduler's docs (it has none beyond `docs/CLAUDE.md:137`, which already says it is to be deleted) — its deletion is an operator ride-along below.

## Proposed approach

Two PRs, split by blast radius and by the identity boundary. **PR-1 must merge before PR-2** (PR-1 removes the route that lazily imports `run_screen`; PR-2 deletes `run_screen`).

### DD-1 — why two PRs and not one
PR-1 changes the LIVE trading server file (`deploy/cloud_run_server.py`) and monitoring config, nothing under `src/**`, no identity move. PR-2 changes the sim stack's imports and moves the identity. Different services, different rollback: reverting a broken re-home must not resurrect the endpoint, and vice versa. Rejected: one PR (one review cycle, but a single revert unit across the trading service and the sim service).

### DD-2 — `ENGINE_VERSION`'s single home is `scenarios/engine_identity.py`
It already declares a copy (`:85`), is stdlib-only by design, and its docstring already carries the bump discipline. Every engine-side importer switches to `from src.backtesting.scenarios.engine_identity import ENGINE_VERSION`. The version-history comment at `screen.py:36–51` (FC-068 / FC-069 boundaries, the FC-048 timestamp-only wart) moves there verbatim; the "DUPLICATED rather than imported" comment at `engine_identity.py:74–84` is rewritten to say this is the declaration. The dashboard copy stays (the dashboard image does not ship the engine); update its two comments (`sweeps.py:25`, `:100`) to name the new home. Rejected: a new `src/backtesting/version.py` — a third location for one constant.

### DD-3 — `DEFAULT_LOOKBACK_DAYS` moves to `scenarios/identity.py`
Beside `DEFAULT_STARTING_CASH`, which `main.py:823` already imports on the adjacent line. It is a spec default (the window a sim gets when none is given), and `identity.py` is stdlib-only. Keep the value (365) and reword the comment: it is no longer "a screening run's" lookback.

### DD-4 — `LAKE_COUNTERS` + `accumulate_lake_summary` move to `data/chain_store.py`
Next to `ChainStore.summary()` (`:877`), whose keys the tuple must track. Drop the `_LAKE_COUNTERS` / `_accumulate_lake` back-compat aliases — their only users are tests in this PR. `_log_lake_run_summary` and its two events (`chain_lake_run_summary`, `chain_lake_degraded`) are **deleted**: only the screen emitted them, and no alert policy, regression check or dashboard query consumes either (verified by grep over `deploy/monitoring/`, `tools/`, `dashboard/backend/`, `src/` at `39a74c9`; the builder re-verifies). Sweeps already persist the lake summary on the `scenario_sweeps` row and the backfill has its own exit-code rule, so no signal is lost.

### DD-5 — `config_hash` moves to a new `reporting/config_hash.py`; `bq_writer.py` is deleted
Function body moved **verbatim** (including the FC-069 hash-discontinuity comment and the `try/except` per key, and its two lazy imports of `evaluate.DEFAULT_FILL_HAIRCUT` and `metrics.fitness`). Output must be byte-identical for both profiles. Rejected: keeping `bq_writer.py` with only the hash in it — a writer module that writes nothing is the stale naming this FC removes.

### DD-6 — the screen test file is split, not deleted wholesale
`tests/test_backtest_screen.py` holds three kinds of test: endpoint tests (PR-1 deletes), screen/row tests (PR-2 deletes), and tests of surviving behaviour that merely live there (PR-2 **moves**): the four `config_hash` tests (`TestProvenance::test_config_hash_*` ×2, `TestConfigHashCoversScoring` ×2) → new `tests/test_config_hash.py`; `TestAnalyticsIsolationIsThreadLocal` (it tests `src.data.analytics_writer` thread-locality, nothing screen-specific) → `tests/test_backtest_simulator.py`, verbatim.
