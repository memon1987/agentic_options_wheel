## Context

The backtesting engine was built alongside the original bot and has never worked. A full audit (July 2026) found:

**It has never produced a trade.** Every saved artifact in `backtest_results/` shows `Total Trades: 0`. Root cause: `src/backtesting/historical_data.py:161` requests historical option bars with `feed='iex'` — but Alpaca serves options from OPRA (and the historical bars endpoint takes no feed param at all), so every chain fetch returns empty, no put ever passes the filters, and runs "succeed" with zero activity.

**The empty-data path masks latent crashes.** With real data it would break immediately:
- `backtest_engine.py:1141` reads `self.portfolio.positions` — an attribute that doesn't exist (`BacktestPortfolio` has `stock_positions`/`option_positions`). The exception is swallowed, so **covered calls can never open** — the second half of the wheel is dead code.
- `backtest_engine.py:1802` calls `self._calculate_summary_metrics(...)` — **a method that is not defined anywhere**. The first run that produces ≥1 trade crashes during result assembly.
- `backtest_engine.py:767` computes `datetime - date` (a `TypeError`), silently caught — so early profit-taking and stop-losses never fire.

**It diverges from the live strategy.** It never calls `PutSeller`/`CallSeller`/`RiskManager`; it reimplements entry selection with different scoring, hardcodes different sizing, has no call rolling, prices calls with a homemade Black-Scholes path while puts use (empty) chain data, and fabricates greeks from moneyness buckets. There are actually three divergent wheel implementations in the repo (engine, `research/experiments/monday_only_backtesting/`, live).

**One component emits fabricated data.** `tools/backtesting/scheduled_backtest.py` imports two modules that don't exist, catches the `ImportError`, and then returns hardcoded fake results (`overall_return: 0.087`, `sharpe_ratio: 1.85`, per-symbol numbers derived from `hash(symbol)`). The Cloud Run `/backtest` endpoint (`deploy/cloud_run_server.py:1271`) also wires into the broken engine.

**Data-source reality (verified against Alpaca docs/SDK/forums, July 2026):**
- Alpaca historical options data exists **only since Feb 2024** (~2.4 years as of today — enough for the 1–2 year lookback goal, but a single vol regime).
- Available free (Basic plan, 200 req/min): expired-contract discovery via `GET /v2/options/contracts?status=inactive`, and per-contract **trade-derived bars/trades** via `/v1beta1/options/bars|trades`.
- **Not available from Alpaca at any price:** historical bid/ask quotes (endpoint 404s; no `OptionQuotesRequest` in alpaca-py), historical greeks/IV, point-in-time open interest, point-in-time chain snapshots (the chain endpoint is latest-only). Bars are trade aggregates, so illiquid contracts have **no bar on no-trade days** — a real concern for 0.10–0.20-delta weeklies.
- Internal data can't fill the gap: BigQuery holds only *traded/assigned* legs (`trades`, `trades_from_activities`) plus daily stock/equity history; the GCS opportunity store purges after 24h. (FC-017 would fix this going forward, not backward.)
- Paid vendors that do have real historical chains with bid/ask + greeks: ThetaData (2012+, ~$25–80/mo), ORATS near-EOD (2007+, $99/mo or $599 one-time history), Polygon/Massive (5+ yr, $29–199/mo).

**Purpose of the rebuilt engine** (from the product goal, not the old code): given a symbol, replay **our live strategy rules as they sit** over a 1–2 year lookback with historical options premiums and point-in-time share prices, simulating the full wheel — CSP entry → expire-worthless or assignment → covered calls (with cost-basis floor, drawdown pause, rolling) → called away — and report whether the symbol is a good fit. Two consumption modes: (a) on-demand evaluation of candidate symbols, (b) scheduled re-screening of the current universe to flag symbols for demotion.

Research notes informing this plan (best practices, vendor landscape, synthetic-pricing bias, prior art) are summarized in the appendix at the bottom of this file.

## Goals

- A backtest run **replays the live strategy code**, not a reimplementation of it — same put/call selection (`MarketDataManager.find_suitable_puts/calls`), same risk gates (`RiskManager`, `GapDetector`), same wheel state machine (`WheelStateManager`), same dynamic profit targets, same rolling rules (`CallRoller`). Backtest == live by construction.
- Real historical option premiums and point-in-time chains (reconstructed contract universe; no lookahead), real daily stock prices; honest fill modeling (mid-minus-haircut with bid-fill sensitivity bound), OCC assignment rules, fees, dividends, and a real cash ledger with CSP collateral.
- A **per-symbol fitness report**: option-leg vs stock-leg attribution, comparison vs buy-and-hold of the same symbol, win rate, assignment frequency, premium capture, time-underwater holding shares, per-cycle table, worst-cycle analysis, max drawdown, annualized return on collateral.
- Two operating modes: `evaluate` (single symbol, on demand, CLI) and `screen` (whole universe on a cadence, results to BigQuery, demote/keep flags).
- A **data-quality gate**: before trusting any symbol's result, the engine reports chain coverage (candidate contracts found per decision day, bar availability at target deltas) so thin data is surfaced, not silently smoothed over.
- Delete the broken/fabricated code paths.

## Non-goals

- **Not** a parameter-optimization framework (no delta/DTE grid search) — v1 answers "is this symbol a fit for the strategy as configured." Sensitivity runs are limited to fill assumptions (mid vs bid).
- **Not** intraday/tick simulation. One decision point per trading day on EOD data (see Open questions).
- **Not** pre-2024 synthetic-premium regime extension in v1. Explicitly deferred to FC-037 (filed; research appendix documents the method: Yang-Zhang RV × calibrated IV-premium factor + skew bump — and its large error bars).
- **Not** modeling dead config knobs the live bot doesn't enforce (IV-rank filters, `earnings_avoidance_days`) — the backtest must mirror what the code *does*, not what the YAML implies.
- **No changes to live trading behavior.** Any seams added to live classes (constructor injection, clock) must be behavior-preserving no-ops in production.

### Strategy replay (the heart of the rebuild)

`PutSeller`, `CallSeller`, `CallRoller`, `MarketDataManager`, and `GapDetector` already take `alpaca_client` via constructor injection — `BacktestAlpacaClient` slots straight in. Remaining seams, all behavior-preserving:

1. **`WheelEngine.__init__`** hardcodes `AlpacaClient(config)`. Add an optional `alpaca_client=None` parameter (default constructs the real one). This lets the simulator reuse the *actual staged pipeline* (`_find_new_opportunities` stages 1–9, covered-call-before-put priority, duplicate guards) instead of duplicating it.
2. **Clock.** Strategy code calls `datetime.now()` for DTE, `min_hold_hours`, entry times. Introduce `src/utils/clock.py` with a module-level `now()` that the simulator can freeze/advance; live default is `datetime.now()`. Replace call sites in strategy/risk modules mechanically.
3. **`WheelStateManager`** already supports no-bucket operation; backtest constructs it with `storage_bucket=None` (in-memory).
4. **`CallSeller` cost-basis floor** falls back to a BigQuery OPASN lookup; in backtest the wheel-state path (first in its resolution chain) always has the assignment strike, so BigQuery is never reached. Guard it so backtest mode can't silently query production BQ (inject a flag or a null client).
5. **Analytics/logging side effects** (`analytics_writer`, structlog events): the simulator injects a no-op analytics writer; log events remain (useful for debugging) but tagged `backtest=true`.
6. **`EarningsCalendarService`** (Finnhub) has no historical earnings-calendar API on our tier. v1: earnings gating uses a static historical earnings-date table fetched once per symbol (Finnhub `earnings_calendar` supports past ranges; if not on our tier, fall back to yfinance earnings dates) and the adapter serves point-in-time answers. The rolling blackout (2 days) is the only earnings gate actually wired in live, so this is small.

The simulator's day loop then is: advance clock → serve marks → process expirations/assignments via broker → call `wheel_engine.run_strategy_cycle()` (unmodified logic) → Friday 3pm: `run_rolling_cycle()` → record daily equity/state.

### Data: Alpaca-first, vendor-agnostic, quality-gated

Phase 1 builds the provider interface + Alpaca implementation and immediately runs the **coverage report** for the current 14-symbol universe over Feb 2024→today, answering empirically:

- On what fraction of decision days does each symbol have ≥1 candidate contract with a bar at our delta band (computed via BS from bar close)?
- How stale are bars for the strikes we'd pick (no-trade-day gaps)?

**Decision rule:** if coverage is good (target: ≥90% of decision days usable for the liquid names), ship v1 on free Alpaca data with synthetic spreads. If coverage is poor at our low-delta strikes, buy ThetaData or ORATS ($25–99/mo) and implement a second provider — the interface is designed for this, and everything downstream is unchanged. This defers the spend decision until we have data instead of guessing.

Because Alpaca has no historical quotes, IV/delta are **computed** (Black-Scholes from bar close + underlying close + dividend yield; existing `calculate_option_greeks` math is the starting point, applied properly), and bid/ask is **modeled**: calibrate a spread model per symbol/moneyness/DTE bucket from *current live chain snapshots* collected over a few weeks (and any FC-017 data as it accumulates), rather than the old fabricated flat ±2%. Both are labeled as modeled in reports.

Chains are persisted to a local parquet cache and (screen mode) to BigQuery, so re-runs don't re-hit the API (the 200 req/min free tier makes cold ingestion of one symbol-year ~minutes, and caching makes iteration fast).

### Fill, fee, and accounting conventions (spintwig-style, documented in the report)

- **Fills:** sell at `mid − 0.25 × half-spread` (configurable); every run also reports the **bid-fill worst case** — if fitness flips between mid and bid, the report says so.
- **Fees:** $0 commission (Alpaca) + $0.04/contract regulatory pass-through (configurable); $0 assignment/exercise.
- **Assignment:** OCC exercise-by-exception — ITM by ≥$0.01 vs the official close at expiration ⇒ 100% assigned. Short calls: early assignment the day before ex-div when ITM and extrinsic < dividend.
- **Cash:** CSP collateral = strike × 100 reserved; premium credited at open; dividends credited while holding shares; return denominators reported both on committed collateral and on total equity. No margin (`buying_power = cash`, unlike the old engine's fictional 2×).

### Fitness report (per symbol)

Headline: **total return vs buy-and-hold of the same symbol over the same window**, with option-leg vs stock-leg attribution (the research's flagship finding: in published SPY wheel studies ~94–99% of return came from the stock leg — our report must never hide this). Plus: annualized return on collateral, max drawdown, Sharpe/Sortino, put win rate (counting expired-worthless correctly), premium capture rate, assignment frequency, cycle table (premium, stock P&L, days, annualized), time-underwater-below-cost-basis (the wheel's signature failure mode — AMZN's 62-day drawdown pause is the live existence proof), worst cycle deep-dive, largest-historical-gap stress note, and the data-quality block. Verdict line: fit / marginal / unfit with the reasons.

`screen` mode writes one row per symbol per run to `options_wheel.backtest_runs` (run metadata, config hash, metrics, verdict) so demotion candidates are queryable and the dashboard can consume them later.

## Risks & mitigations

- **Risk:** Alpaca bar sparsity at 0.10–0.20-delta weeklies makes chains unusable for some symbols.
  - **Mitigation:** Phase 1 coverage gate decides Alpaca vs paid vendor *before* engine work depends on it; provider interface makes the swap cheap.
- **Risk:** Modeled spreads/greeks bias results (premiums from trade prints, not quotes).
  - **Mitigation:** calibrate spread model from live chains; report bid-fill worst case on every run; label modeled fields in output.
- **Risk:** Seams in live code (clock, injection) alter production behavior.
  - **Mitigation:** defaults preserve current behavior exactly; existing unit tests must pass unchanged; changes are mechanical and reviewed in isolation (own commit).
- **Risk:** 2024–2026 is a single vol regime — fitness verdicts overfit to a calm market.
  - **Mitigation:** report regime context (realized-vol percentile of the window) and the largest-historical-gap stress note; synthetic pre-2024 extension deferred to FC-037 rather than silently baked in.
- **Risk:** Replaying live components is slower than a purpose-built vectorized sim.
  - **Mitigation:** acceptable — one symbol-year is ~250 decision loops; parquet cache removes API latency. Target <1 min per symbol-year warm.
- **Risk:** Live code makes unexpected network calls mid-replay (Alpaca account, BigQuery, Finnhub).
  - **Mitigation:** adapter implements the full consumed surface and raises on any unmocked call in backtest mode (fail loud, not silently live).

**Phase 1 gate — RUN 2026-07-09. Decision: stay on free Alpaca data; Phase 3 proceeds.**

Full results and reasoning: [`docs/investigations/fc-032-coverage-gate.md`](../investigations/fc-032-coverage-gate.md).

The gate did not run as written — it failed on all 14 symbols and exited 0. Four defects were found and fixed first (`b923137`, `a0bb6c5`, `4d95e45`, `9583099`, `1d3ee1d`):

1. **Real-time entitlement.** Requests ran through `end 23:59:59`; when `end` is today that reaches into the undelayed window, which we are not entitled to — SIP for stocks, real-time OPRA for options. Both endpoints 403'd. Clamped to `now - 20min` (the buffer the live client has always used) and the current session's partial bar is dropped.
2. **`poor` vs `no-data`.** A symbol with zero decision days scored `usable_fraction = 0.0` → verdict `poor` — the verdict wired to "buy a $99/mo vendor". Absence of measurement is now `no-data`.
3. **Silent success.** The tool wrote `coverage.json = []` and exited 0 after every symbol errored. It now refuses to write and exits non-zero.
4. **Adjusted contracts.** Alpaca's contracts endpoint returns re-rooted contracts (`1AAPL240429P00170000`) whose deliverable is not 100 shares; its data endpoint rejects them, 400-ing the whole bars chunk. Excluded at discovery (with a logged count) — correct on the merits, not just a crash fix: the wheel cannot sell a put that delivers something other than 100 shares.

The first real rows then exposed a **design** flaw: the gate collapsed "no priced put at our deltas" (a data gap a vendor fixes) and "the put pays less than our $0.50 floor" (a fact about the symbol no vendor changes) into one verdict — and that verdict drove the purchase decision. `quality.py` now reports `in_band_fraction`, `premium_shortfall_days` and `limiting_factor() -> data | premium | none`.

**Outcome:** `days_with_bar = 122/122` for **all 14 symbols**. **0 data-limited, 12 premium-limited** — though the data/premium split is a bare-majority call, so the margins are now tabulated in the investigation. The only close one is F (+8 days, and 43% of its days had no in-band put at all); it is moot because F cannot clear the premium floor either way, and every symbol the strategy actually trades runs 92–100% in-band. The plan's flagship risk — bar sparsity at 0.10–0.20-delta weeklies — did not materialize. No vendor purchase is warranted on availability grounds.

**Independent validation:** the gate predicts F/PFE/KMI (0 usable days) and VZ (2) are unsellable under the current config. Against 588 live `FILL` activities, the bot has **never** sold a put on any of the four, and has traded exactly the symbols the gate rates usable. The data layer reproduces production behavior it was never shown.

**Caveat carried forward:** the gate measured *availability*, not *fidelity*. Alpaca still has no historical quotes, so bid/ask stays modeled and greeks stay computed. A vendor would improve fidelity, not coverage. If a fitness verdict flips between mid-fill and bid-fill (Phase 4 reports both), revisit the vendor decision on those grounds.

**Follow-up (not blocking, belongs in its own FC):** F, PFE, KMI, VZ are structurally untradeable under `min_put_premium: $0.50`. A fixed *dollar* premium floor is not scale-free — it is a far harsher filter on a $12 stock than a $600 one. Re-expressing the floor as a fraction of strike (or as annualized return on collateral) is a live-strategy change and out of scope here.

**Phase 2 — Simulation kernel (done 2026-07-07).** Built the time seam and the authoritative ledger:

**Phase 3 — Strategy replay (core done 2026-07-09; rolling + parity check outstanding).**

- `src/utils/clock.py` seam wired into 38 call sites (`dd6b035`). Two traps the plan's "mechanical replacement" framing missed: `src/utils/option_symbols.py` computes DTE from the wall clock and lives outside `src/strategy`/`src/risk`, yet its `dte` drives `_get_profit_target_for_dte()` in *both* sellers; and `call_seller.py` had three `datetime.now(timezone.utc)` reads that an exact match on `datetime.now()` does not catch. Because every downstream component already takes the client by constructor injection, one seam redirects the whole graph; tests assert the injected client reaches `market_data`/`put_seller`/`call_seller`/`gap_detector`, not merely `engine.alpaca`.
- `BacktestAlpacaClient` (`468edbb`): no lookahead (every read served as of the frozen clock, including our own ledger); fail-loud `__getattr__` (covers `wheel_engine.py`'s reach-through to the raw `.trading_client`, which the plan's surface list missed); and mirrors live rather than improving on it — `open_interest: 0` exactly as live hardcodes it, which is what makes the live liquidity gate reduce to "volume must be non-zero". - `Simulator` day loop (`b501b45`). The golden-path test found three defects that would each have produced a plausible-but-wrong backtest:
  1. **`run_strategy_cycle()` only *finds* opportunities.** Production executes them in a second phase (`/execute` → `ExecutionEngine`). The plan's day loop would have placed zero trades and reported a flawless zero-trade backtest — the exact failure this FC exists to kill.
  2. **Settlement must run *after* the decision.** Settling first removed the expiring position before the scan, so stage 6's duplicate guard waved through a fresh put expiring the same day, which then never settled.
  3. **The adapter's stock-bars index must be tz-aware UTC.** A naive index makes `GapDetector` raise, swallow, and conservatively block every trade — silently.
  Plus a warm-up window: `GapDetector` needs ~30 bars and blocks everything on a cold first day.
- Production side effects neutralized and restored on exit even when a run raises: analytics singleton (`set_analytics_writer`, additive), `TradeJournal` (`ExecutionEngine` builds a real one by default), `CallSeller`'s BigQuery cost-basis fallback, `WheelStateManager`'s GCS bucket.
- End-to-end on a scripted −30% crash: put sold → assigned at 92 → cost-basis floor correctly refuses to sell calls below basis → wheel −4.19% vs buy-and-hold −30%. Equity reconciles to cash + marked shares. Full suite **379 passed**.

**Phase 4 — Metrics & evaluate mode (done 2026-07-17, `be64e85`).**

Running the CLI end to end immediately exposed three more defects, each of which produced a plausible-but-wrong backtest:

1. **Stale chain cache.** `MarketDataManager` caches the chain with a *wall-clock* TTL (`time.time()`, 300s). A replay passes hundreds of simulated days in seconds of wall time, so the cache never expired and the strategy saw day one's chain forever — on 2025-10-20 it proposed a contract that had expired 17 days earlier, labelled `dte=1`. One trade in 91 days. The `datetime.now()` sweep missed it because `time.time()` is a different function. Cache ages now use `clock.now()`; NVDA October went from 1 trade to a proper weekly cadence of 5. The adapter's fail-loud `no_quote` is what surfaced it.
2. **`reconcile_positions()` was never called.** `run_strategy_cycle()` doesn't call it — production runs it as pre-trade housekeeping. It is what teaches `WheelStateManager` that a put expired or was assigned. Same class as the execution-phase bug.
3. **`get_stock_bars(days=N)` is N *calendar* days**, not N bars. Slicing bars gave ~43% more history, changing every windowed statistic — `GapDetector`'s gap frequency is a ratio over exactly that window, and the longer window blocked NVDA for all of Nov 2025 (18.6% vs a 15% limit) while live traded it on 7 days.

Also closed a test-hygiene hole: three `test_call_seller` tests were passing only because BigQuery auth was broken on the machine. Once `gcloud auth login` succeeded, `CallSeller`'s cost-basis fallback queried **production BigQuery from a unit test** and returned a real AAPL strike ($305) in place of the fixture's $160. A conftest autouse fixture now stubs it for every test.

Delivered: `metrics/cycles.py` (cycles rebuilt from the ledger; option and stock P&L never collapsed; open cycles reported, not dropped), `metrics/fitness.py` (attribution, buy-and-hold benchmark, drawdown, time-underwater, verdict with explicit reasons; `option_pnl_share` is `None` when the legs have opposite signs), `reporting/report.py` (markdown + JSON, always with a known-bias footer), and `main.py --command backtest` with the mid-vs-bid sensitivity pass.

**Justified deferrals** (CLAUDE.md option (b) — recorded rather than fixed):

1. **Dividends are not credited.** `broker.credit_dividend` exists but is unwired, so the Dividends row is structurally zero. Deferred because it needs a dividend data source and its own testing. **This is not neutral: it flatters the wheel.** The buy-and-hold benchmark holds shares every day and forgoes the entire dividend stream, while the wheel holds them only intermittently — worth roughly 15 points on a 6.5%-yield name over 2.4 years, enough to flip the beat-buy-and-hold line on the income-heavy symbols. Disclosed in every report's bias footer with that magnitude.
2. **Ex-dividend early assignment is not modeled.** `broker.assign_call_early` is likewise unwired. Short ITM calls are held to expiry, so the replay keeps shares a live account would have lost — optimistic, and concentrated on the same dividend payers. Disclosed in the bias footer.

Both should be taken together with a dividend feed, and both are worth doing before `screen` mode drives demotion decisions on income names.

**Discovered production bug:** the replay reproduced, faithfully, that Stage-4's execution gap check can never fire — Alpaca stamps daily bars 04:00 UTC, so `_get_previous_close` returns *today's* partial bar; the gate then measures a ~20-minute pre-market drift rather than the overnight gap (NOT a constant 0.0% — a nonzero reading is what makes it look healthy). Verified against the live client. Filed as **FC-036**; deliberately *not* "fixed" in the adapter, since that would make the replay more conservative than production.

**Phase 5 — Screen mode (2026-07-18, separate PR).**

- `src/backtesting/screen.py` — runs the universe through the Phase 4 engine, one row per symbol to `options_wheel.backtest_runs`, demote/keep flags. `python main.py --command screen` and `POST /backtest/screen`.
- `src/backtesting/reporting/bq_writer.py` — the writer deliberately does **not** follow `AnalyticsWriter`'s fire-and-forget pattern. Losing an analytics row is cheaper than blocking a trade; losing a screen row produces a partial table that reads as complete and feeds a demotion decision. Writes return success, the CLI exits non-zero and the endpoint returns 500 when anything did not land.
- **Failures are not passes.** A symbol that errors still gets a row with a null verdict and its error text; the summary and schema doc both state that a null verdict means *never checked*, not *fine*. An unmodelled corporate action is recorded as a skip rather than a verdict, so a split never lands a symbol in the demote list.
- **Provenance in every row.** `config_hash` (16-char hash of the thresholds that shaped the verdict) and `known_biases`. Without the hash, a changed premium floor is indistinguishable from a changed symbol.
- **Endpoint is bounded on purpose.** Cloud Run's request timeout here is **300s** and the scheduler's attempt deadline **180s**. Measured cost is **~25 min per symbol** cold (~50 with the sensitivity pass) — `ChainStore` is never constructed, so the plan's warm-cache mitigation does not apply — which means no synchronous run finishes even one symbol. (A timeout does *not* corrupt the table: persistence is a single write after the loop, so it writes zero rows. An earlier version of this note claimed partial writes and ~1 min/symbol; both were asserted without measurement and are wrong.) The endpoint therefore ships **disabled** behind `ENABLE_SCREEN_ENDPOINT`, and the monthly run needs the Cloud Run Job, which is the deploy step still outstanding.
- `docs/bigquery/backtest_runs.md` — schema plus the queries that matter, including "symbols that were never actually checked".
- `docs/CLAUDE.md` Data Analysis Policy rewritten: it still pointed at the `/backtest` and `/cache` endpoints deleted in Phase 0. It now separates evidence of what the bot *did* (`trades_from_activities`) from a simulation of what it might have done, and says never to quote a backtest number without its bias footer.

- **The dividend caveat was one-directional.** It flatters the wheel on `excess_return` (a WARN) but *penalises* it on the absolute gates that actually demote. On a 5–7% yielder the missing dividends alone can push return-on-collateral under the risk-free floor, so on the income names the list is biased **toward** demoting while every operator-facing string said the opposite.

## Appendix: research summary (July 2026)

Condensed from independent research; kept here so the plan is self-contained.

**Vendor landscape.** Alpaca: Feb 2024+, free historical bars/trades, no historical quotes/greeks/OI/chains (confirmed via SDK source + forum + open feature request; Alpaca's own backtesting tutorials use Databento). ThetaData: options quotes/EOD to ~2012, ~$25–80/mo. ORATS: 2007+, near-EOD chains snapshotted 3:46pm ET with smoothed IV/greeks, $99/mo or $599 one-time history. Polygon/Massive: 5+ yr ticks, $29–199/mo. CBOE DataShop: a-la-carte, excludes delisted symbols (survivorship). OptionMetrics: academic gold standard, inaccessible to individuals.

**EOD is the right granularity** for a daily-decision wheel: the de-facto retail standard (spintwig; ORATS) is a single daily ~3:45pm ET snapshot with midpoint fills and documented slippage. Where EOD breaks: expiration-day ITM/OTM flips (settle off underlying close), intraday profit-target touches (EOD makes exits late ⇒ conservatively biased — acceptable).

**Assignment:** OCC auto-exercise at ≥$0.01 ITM; model ex-div early assignment of short calls (extrinsic < dividend); LEAN's heuristic (deep-ITM near expiry) is the reference implementation.

**Synthetic premiums (deferred FC-037):** BS with trailing realized vol underprices seller premiums badly — IV exceeds RV ~85% of days (VIX avg 19.3 vs realized 15.1, 1990–2018; VIX/RV ≈ 1.18), the variance risk premium concentrates at short maturities (worst exactly for weeklies), and OTM put skew adds 3–5 vol points (index) on top. Naive BS-with-RV understates a 30-delta weekly put premium by ~50–60%. Correction recipe if ever needed: Yang-Zhang 21d RV × per-symbol calibrated IV/HV factor (from our real 2024+ chains) + skew bump, binomial with discrete dividends for ITM/dividend cases — clearly labeled as regime extension, never mixed silently with real-data results.

**Prior art.** Nothing off-the-shelf replays *our* rule set through the full CSP→shares→CC lifecycle: optopsy (AGPL) and lambdaclass's backtester stop at leg-P&L with no assignment/state machine; backtrader/vectorbt have no chain concept; wheel-specific repos are 0-star notebooks. QuantConnect LEAN is the only full-lifecycle engine (2012+ minute options data, assignment models, worked wheel example) — steep adoption cost, but useful as an independent cross-check of our results on 1–2 symbols. Methodology to mimic: spintwig (EOD snapshot, mid-minus-slippage, buy-and-hold benchmark, attribution). Sobering benchmark: in spintwig's 17-year SPY wheel study no variant beat buy-and-hold, and the stock leg drove ~94–99% of returns — attribution reporting is mandatory.

**Pitfalls encoded in this plan:** survivorship in the ticker list (evaluate symbols as screened at the time), single-regime overconfidence (2024+ only), mid-fill + instant-redeployment optimism (bid-fill bound, real cash ledger), win-rate vanity (high win rate is a delta artifact; count expired-worthless correctly *and* report tail losses), attribution blindness (stock leg vs option leg), one -30% earnings gap can erase 1–2 years of weekly premiums (worst-gap stress note per symbol).

**Calibration anchors for sanity-checking results.** CBOE PUT index (systematic ATM put-writing, 1986–2018): 9.54%/yr vs S&P 9.80% at ~2/3 the volatility, max drawdown −32.7% vs −50.9% — the honest full-cycle pitch for premium selling is *similar return, lower vol*, not outperformance; it lags badly in melt-ups (2020: PUT +2.1% vs SPX +18.4%) and loses less in crashes (2008: −26.8% vs −38.5%). Realized win rates for low-delta short puts run well above priced probabilities (16-delta ≈ ~95% winners). If our per-symbol results look wildly better than these anchors, suspect the simulator before celebrating. Two knowingly unmodeled factors, to be noted in report footers: taxes (wheel income is short-term gains; ~1–2%/yr drag vs buy-and-hold's deferred LTCG) and single-path timing luck (one historical path per symbol; a shifted start date can flip marginal verdicts — worth a multi-start-date ensemble in a later iteration).
