## Decision: delete (design rationale + rejected alternatives)

**Chosen: delete the entire path** — poll, writer method, schema, log helper,
backfill script, and the empty table.

1. **Zero readers.** Dashboard, live views, committed SQL, tools, and pending
   FCs — nothing consumes `order_statuses` or the `order_*` events.
2. **Zero rows in ~3.5 months of live trading.** The poll has been a no-op
   since it shipped (three independent defects; any one sufficient).
3. **FC-012 already decided this.** It moved the dashboard to
   `trades_with_outcomes`, declared the table inert, and scheduled `bq rm` +
   a cleanup PR that never ran. Deletion completes a recorded decision;
   revival reverses it with no consumer to justify it.
4. **A superior source already exists.** `trades_from_activities` is the
   authoritative, idempotent fill/expiration record. A revived poll is a
   second, weaker, non-idempotent writer of the same facts.
5. **Revival has documented costs.** PR #47's own analysis: ~30 re-emissions
   per order, mitigated but *not* eliminated (BQ streaming-dedup window is
   minutes; polls are ~4h apart, so duplicates persist across polls), plus the
   revived `order_*` events leak into the shared live view
   `options_wheel_logs.trades_executed` (keyed on `event_category='trade'`) —
   new pollution of an ad-hoc analysis surface, purchasing a table nobody reads.

**Rejected — revive (PR #47).** Well-engineered, wrong direction, per 3/4/5.
Its engineering (order normalization, `_ts()`, `_classify_order_strategy()`,
`row_id` dedup) exists to make a redundant feed safe; the safest redundant
feed is none.

**Rejected — leave dormant** (FC-043's pin as a permanent state). Keeps ~180
lines of dead code containing the repo's only F821, one dead live API fetch
per `/run` cycle, a schema entry whose auto-create (`_ensure_all_tables`)
resurrects the FC-012-condemned table on every deploy, and standing doc
invitations (`docs/CLAUDE.md` example, eval catalog) to "finish" the path.
Dormant-but-present is exactly how this survived April → July.

**Rejected — fix the NameError only** (FC-035's original framing). Falsified
by PR #47's analysis: the import fix alone adds a wasted API call (the fetch
result is never iterated) and changes nothing else; making the path actually
work requires all of PR #47 — see "revive."

Both reviewers independently verified against production logs that the
"**never executed**" phrasing in this plan, the PR body and the in-code

in `jsonPayload.event`, **not** `jsonPayload.event_type`. Query the former or
the check returns nothing and looks like a regression. (Filed as its own FC.)
