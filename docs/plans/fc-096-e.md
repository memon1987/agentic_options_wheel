## Signed decisions in force (not reopened here)

## Goals

1. Every signed component renders from stored data (BigQuery aggregates + GCS artifacts), never by re-running anything, with the FC-060 guardrails carried over component by component.
2. A deep link addresses a run, a cell, or a comparison; a reload lands on the same screen.
3. A PM can tweak one field and get the comparison against base in seconds (warm) — through the sim service that already exists — and pin the question for the Saturday battery.
4. A CC artifact (Phase C, unbuilt) renders the wheel-shaped parts fully and the CC-specific parts by stamp, not by crash.
5. The IAP session refreshes in place.

## Non-goals

### D-2 — the bars path (the boundary PR-b deferred to this plan)

**Decision: the engine writes one small `bars` sidecar per (run, symbol, split) beside the cell artifacts**, at `sim-artifacts/v1/<run_id>/bars/<SYMBOL>__<split>.json.gz`, from `run_sweep`'s window loop immediately after a successful `_materialise_window` (`runner.py:707`, success path `:732`). It carries the decision-window bars the replay actually saw and the **engine-computed buy-and-hold curve** for that window.

Why this and not the alternatives (recorded so the build does not reopen it):

- *Read bars from the sim service on demand* — a viewer opening a finished run would pay the service's cold start (measured 23 s–4 min, `fc-096-b.md` §Context) for a chart. Rejected.
- *BigQuery `stock_history_from_alpaca`* — live symbols + SPY only, and from the ingest's start date; candidates (the FC's headline use-case) have no rows, and the series is not the one the replay used (the replay's `BarStore` clamps to settled sessions and carries the warm-up buffer). Kept as a captioned **fallback** for pre-Phase-E runs on live symbols. Not the primary path.
- *Embed bars in every cell artifact* — the PR-b reviewers' objection stands: ×arms×splits copies of one series. The sidecar is ×splits only, ~3–5 KB gz each, ≤ 36 objects on a 12-symbol run.
- *Client-computed B&H from closes* — the engine's `BuyAndHold` (`fitness.py:50`) is whole-share, dividend-inclusive with a half-open ex-date rule (`dividends.py:152`); a client copy would drift from the row's `benchmark_return`. The sidecar's curve is produced by the engine and its last point is asserted equal to `BuyAndHold.final_value`.

**Sidecar schema (`"schema": 1`, frozen-fixture-pinned like the cell artifact):**

```
{
  "schema": 1,
  "provenance": {run_id, symbol, split, window:{start,end}, engine_identity, generated_at,
                 source: "materialised bars", data_from, data_to, bars_in_window},
  "bars": [{date, open, high, low, close, volume}, ...],          // clipped to [w_start, w_end] — the same clip _score uses (evaluate.py:241)
  "buy_and_hold": null | {
      starting_cash, shares, entry_date, entry_price, exit_date, exit_price,
      dividends_per_share_total,
      daily: [{date, value}, ...]                                   // value_t = starting_cash + shares*(close_t - entry) + shares*div_ps(entry, t]
  }
}
```
`buy_and_hold` is `null` exactly when `_buy_and_hold` returns `None` (no entry/exit close, or `shares <= 0`), so the console's "no benchmark" state is the engine's, not a client guess. `div_ps(entry, t]` is `DividendSchedule.total_between(symbol, entry, t)` — the same half-open interval `_score` uses (`evaluate.py:226-230`), so `daily[-1].value == BuyAndHold.final_value` by construction and `(daily[-1].value - starting_cash)/starting_cash == row.benchmark_return`. Both are REQUIRED tests.

Writer: `ArtifactWriter.write_bars(payload)` (new method, `artifact_store.py`), name from a new `identity.bars_object_name(run_id, symbol, split)`; `bars_written`/`bars_failed` counters and a `sim_bars_write_failed` warning; **never on the critical path** (own `try`, like `_emit_artifact`). `artifacts_complete` semantics are unchanged — cells only; a missing sidecar is a chart-level absence, not a run-level flag (no schema change).

Reader: `services/artifacts.ArtifactStore.fetch_bars(run_id, symbol, split)` and `GET /api/v2/sweeps/{run_id}/bars/{symbol}/{split}` with the cell route's exact status semantics (400 path / 404 absent / 502 unreadable or bucket / 503 no bucket; sync `def`; `no-store`).

**Engine identity moves with PR-1** (`src/**` changes) — the accepted one-time invalidation class (`scenario_runs.md` §One-time invalidation). The first battery Saturday after PR-1 is the expensive one; stated in rollout.

### D-3 — sizes, latency, caching

- **Per cell open:** artifact (~10 KB gz, ~80 KB JSON) + base-cell artifact (for the vs-base overlay) + sidecar (~4 KB gz). Three GETs, parallel, each a single GCS download (~100–300 ms) on a warm dashboard; the dashboard itself is `--min-instances=0`, so the first request of a quiet hour pays its cold start (seconds) once.
- **Portfolio view:** N artifacts for one scenario+split, N ≤ 12, fetched with a concurrency cap of 4; progressive render (the index re-draws as symbols land; the caption names the symbols still loading / missing).
- **Cold sim-service tail** touches only the tweak bar (PR-5): a 202 lands in ≤ 150 s or the proxy 502s with the cold-start explanation, and the UI offers "retry" — the honest posture PR-c recorded; the console never blocks on it.
- **SPA cache** (`hooks/artifactCache.ts`): a module-level LRU (`Map<url, Promise<Result>>`, cap 48 entries ≈ 4 MB decompressed worst case) shared by `useArtifact` and `useBars`. A URL is memoised only when (a) it resolved 200, or (b) it resolved **404 and the run's status is terminal** — an in-flight run's 404 is exactly the case the endpoint's `no-store` exists for and is never cached. 5xx is never cached. `resetArtifactCacheForTests()` mirrors `resetSessionExpiredSignal`.

### D-4 — the client digest, and the line it must not cross

`components/v2/console/artifactDigest.ts` is a pure module: `digest(artifact) -> ArtifactDigest` with `grossPremium`, `fees`, `netOptionCash`, `cumulativeOptionCash[]`, `monthly[]` (in `MonthlyCashflow` shape so `MonthlyPremiumBars.tsx` is reused unchanged), `drawdownSeries[]`, `collateralSeries[]`, `avgReservedCollateral`, `reconcile: {optionPnl, maxDrawdown, putsSold, callsSold, cyclesCompleted, finalEquity}`.

The FC-060 rule "the UI computes nothing" was written about **ranking inputs** — medians, partition counts, deltas, window arithmetic — and it still holds: nothing in `digest` feeds a verdict, a median, a Δ, the forecast, or a cell's colour. What `digest` produces is chart-shaped series and three ledger sums the row does not carry. The `reconcile` block exists ONLY for a test: on the real captured fixture, each of its fields must equal the engine's row value (`option_pnl` = Σ `cycles[].option_pnl`, `max_drawdown` by the peak formula of `fitness.py:446`, `puts_sold`/`calls_sold` = counts of `sell_put_open`/`sell_call_open`, `cycles_completed` = cycles with `!is_open`, `final_equity` = `daily[-1].equity` = `counters.final_equity`). The strip DISPLAYS the row's values, never `reconcile`'s. Rejected alternative: an engine-side `summary` block on the artifact — it would not exist on the 20 objects already stored, and monthly buckets are a chart, not a fact the engine should own.

## Design decisions (made — do not relitigate in the build)

1. **Charting = recharts 2.15 (already installed), no new dependency.** Price chart = `ComposedChart` (`Line` for close + `Scatter` with a custom `shape` per event kind + a custom `Tooltip` listing that day's events); equity/B&H/base = `LineChart` (the `EquityCurve.tsx` idiom); monthly premium = the existing `MonthlyPremiumBars` component; drawdown and utilisation = `AreaChart`. Rejected: lightweight-charts / uPlot for candlesticks — a second chart runtime for one component, and daily OHLC candles at ≤ 730 points do not need it; a `Bar` high-low rendering is available in recharts if the operator later wants candles.
2. **Ledger/cycle tables aggregate client-side.** Bound: a 730-day cell is ~150–300 ledger rows (measured 72 for 189 days), ≤ 60 cycles. No virtualisation, no server paging. Sorting and kind filtering are pure functions (tested).
3. **Export = CSV (RFC-4180 quoting, `detail` JSON-stringified in one column) and JSON (the raw artifact, unmodified)**, both via the `SweepResults` Blob-download idiom. Every CSV starts with `#`-prefixed provenance lines (§Guardrails). Rejected: XLSX (a dependency for no reader that needs it).
4. **URL is the state.** Routes: `/sims` (newest run, as today), `/sims/:runId`, `/sims/:runId/:scenario/:symbol/:split`, `/sims/compare?a=run:scenario:symbol:split&b=…`. `:` is a safe separator (`SCENARIO_NAME_RE` and `SYMBOL_RE` in `identity.py:75,127` admit no colon). Selection changes call `navigate(…, {replace: true})`; the run list and results region read params, not component state. `SubmitSweep`'s `onSubmitted`/`onSelectRun` navigate.
5. **The B&H curve is engine-produced (sidecar), never client-produced.** See D-2.
6. **The client digest is display-only and reconciled by test.** See D-4.
7. **Forecast is server-computed in `shape_results`**, the UI only scales per-day by a horizon. See §Forecast.
8. **Compare is anchored to base by construction**: each side's panel always draws its own run's base curve; the headline deltas are each side's Δ vs ITS base; A-vs-B is shown only as overlaid curves, never as a number, unless both sides are the same run+split (then A−B is a plain subtraction of two served Δs and is labelled so).
9. **Tweak bar submits through `POST /api/v2/sims/run`, one field → one arm**, arm name derived from the key (`strategy.put_delta_range` → `put_delta_range`), window/symbols/holdout carried from the selected run, base value prefilled from `base_config_json.effective[key]` when present. Rejected: routing tweaks through the Job (3–4 min container start defeats "seconds").
10. **IAP refresh is click-triggered via `window.open`**, per Google's doc; never auto-opened (popup blockers), never an iframe (the FC note). See §IAP.
11. **No `whoami`.** Viewers see the write controls and get the backend's 403 verbatim — the FC-060 "server's own words" discipline. A role hint is a non-blocking open question.
12. **Frontend fixtures are REAL captures**, not hand-written (the PR-b `roll_records` lesson, `fc-096-b.md` Execution PR-b fix 1). See §Fixtures.

## PR sequencing

Seven PRs. PR-1 is the data contract and lands first; PR-2..PR-6 are frontend and depend on PR-1's deploy only for the fields it adds (each degrades to "not served by this backend" when a field is missing, so a frontend PR can deploy ahead of PR-1 without breaking — but the order below is the intended one). **PR-7 (IAP refresh) is independent and may land at any point.** Each PR: `cd dashboard/frontend && npx tsc --noEmit` and `npx vitest run` green locally, pytest green in the CI-equivalent venv, two adversarial reviews, confirmation pass if fixes land.

## Compare view

- **What is compared:** two cells `a`, `b`, each `run:scenario:symbol:split`. Supported pairings: arm vs base within a run (default), arm vs arm within a run, the same arm across two runs (a pin's two Saturdays; a re-run after an engine change), any two cells that pass alignment.
- **Anchored to base (D-8):** each panel draws its run's base cell curve under its own; each panel's tiles are that cell's served `delta_vs_base`, sign agreement, and state badge. The A−B number appears only when `a.run === b.run && a.split === b.split` (both Δs are served against the same base; A−B = Δa − Δb, labelled "difference of two served Δs"). Otherwise curves overlay and no A−B number exists on the page.
- **Alignment checks, in order, each with its posture:**

| dimension | how checked | mismatch posture |
|---|---|---|
| symbol | `a.symbol !== b.symbol` | **refused** — the page says two symbols are not two configs; offers to open each cell |
| split | `a.split !== b.split` | **warning banner** ("in-sample vs holdout — not comparable"); Δ/return tiles withheld on both sides; curves shown |
| window | `windows[split].start/end` differ | warning; x-axis = union, non-overlap shaded; tiles withheld |
| starting cash | spec values differ | warning; equity axis switched to base-100 index; tiles kept (returns are fractions) |
| base config | `base_config_hash` differ | "different base configs — each side's Δ is against a different base"; A−B never shown |
| engine identity | `engine_identity` differ | note (not a warning): "replayed by different engine builds `x` / `y`"; kept because that is exactly what a pin's history compares |
| fill haircut | differs | the amber fill-model label on the side that varies |
| in-sample | either side | the banner, verbatim |

- **Curves:** equity (a, b, and each base), B&H once when both sidecars agree on the series (same symbol, same window) else per side; price chart with both sides' markers in two shades; cumulative option cash both sides.
- **URL:** `/sims/compare?a=…&b=…`; malformed → `/sims`.

## Forecast range (component 7)

Computed in `shape_results` (PR-1), per scenario × symbol, `null` unless the fit AND holdout cells are both `measured` (via `_measured_value`):

```
days(w)        = (window_end - window_start).days + 1            # calendar days of that split's window
rate_w         = option_pnl_w / days(w)                          # $ per calendar day, net premium (buybacks + fees inside)
low_pd, high_pd = min(rate_fit, rate_hold), max(rate_fit, rate_hold)
annual_low/high = low_pd * 365, high_pd * 365
```
Served per symbol: `{fit_per_day, holdout_per_day, low_per_day, high_per_day, annual_low, annual_high, capital: starting_cash, basis: "net_option_pnl"}`. Per scenario (portfolio): `{annual_low, annual_high, per_day_low, per_day_high, included: [symbols], excluded: {symbol: state}}` = sums over included symbols. Refusals: `in_sample_only` ⇒ `forecast: null`, `forecast_refusal: "IN-SAMPLE ONLY — no holdout, no forecast. …"`; a scenario with no included symbol ⇒ portfolio `null` with reason `no symbol measured in both windows`. `option_pnl` (not `total_return`) because the FC asks for INCOME; stock P&L, assignment risk and dividends are excluded and the caveat says so.

**UI:** horizon selector 30 / 90 / 365 days; the panel shows `[low, high] × H` per symbol and the portfolio sum, `included`/`excluded` named, both windows' rates, and — mandatory, `data-testid="forecast-caveat"` — `forecast_caveat` verbatim followed by the run's `known_biases` titles. The panel never renders without the caveat (a test renders with `forecast_caveat: ""` and asserts the panel refuses).

**`FORECAST_CAVEAT`** (dashboard-only constant in `sweep_report_text.py`; the CLI report prints no forecast, so there is no `report.py` original — the fork test gains an explicit `DASHBOARD_ONLY_PROSE = {"FORECAST_CAVEAT"}` allowlist rather than silently skipping it). Text, pinned by test: *"Forecast = a premium run-rate extrapolated. The two bounds are the fit and holdout windows' net option P&L per calendar day scaled to the horizon; they are NOT a confidence interval — one regime, two windows, one engine whose premium is understated on both legs (see the biases below). Stock P&L, assignment losses and dividends are excluded; each symbol is an independent replay on its own $starting_cash and the portfolio line is a sum, not a portfolio. A symbol unmeasured in either window is excluded and named. An in-sample run has no forecast."*

## Risks & mitigations

- **Engine identity moves with PR-1** → every stored key misses once; the first Saturday battery after merge is the expensive one (~25–35 min, `fc-096-b.md` PR-d sizing). Stated in rollout; no `ENGINE_VERSION` bump (the sidecar cannot move replay numerics).
- **The digest drifts from the engine** → the `reconcile` equalities on a REAL fixture are the tripwire; the strip never displays digest values for anything the row carries.
- **A viewer draws a ranking from the console** → the guardrail matrix; every number that can rank is served, every non-measured cell is a badge, every comparison across splits withholds Δ.
- **Forecast read as a promise** → server-refused without holdout; caveat mandatory and tested; range not interval, in the words.
- **Fixture staleness** → real captures pinned to a named run id; the artifact schema is frozen separately by the engine's fixture, so a schema bump fails the engine test first.
- **Popup blockers** → refresh is click-triggered; `'blocked'` falls back to reload copy.
- **Seven PRs** → each ships behind the previous one's data contract with a degrade path, so a stalled PR leaves a working console, not a broken one.
