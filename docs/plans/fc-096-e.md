## Goals

1. Every signed component renders from stored data (BigQuery aggregates + GCS objects), never by re-running anything, with the FC-060 guardrails carried over component by component.
2. A deep link addresses a run, a cell, or a comparison; a reload lands on the same screen.
3. A PM can tweak one field and get the comparison against base in seconds (warm) through the sim service that already exists, and pin the question for the Saturday battery.
4. A CC artifact (Phase C, unbuilt) renders the wheel-shaped parts fully, reads its own capital base and benchmark from stamps, and SUPPRESSES what it cannot compute honestly.
5. The IAP session refreshes in place.

### D-2 — the bars path, and the B-alt evaluation

**Round-1 alternative (B-alt), evaluated against the tree:** a dashboard-side bars route reading a bar store the engine already keeps, plus a per-cell benchmark stamp, so the engine tree is not touched and no stored dedup key moves. Its precondition — bars readable by the dashboard from GCS without a new grant — is **false**: the bar cache is local parquet by explicit design (`bar_store.py:50-52`), each Job/service has its own (`sim_service.py:270-272`; no GCS volume in `cloudbuild.yaml`), neither bucket has a bars prefix (live listing above), and BigQuery's `stock_history_from_alpaca` holds live symbols + SPY only, from a 365-day initial backfill — never a candidate, and never the replay's own settled-clamped series. Building a durable bar store would be a Phase A-class change (a writer on the backfill Job, a new prefix, a coverage contract), larger than the sidecar. **Not adopted.** What B-alt got right is adopted in full: the per-cell benchmark stamp from the SCORED report (A2), and the requirement that the B&H curve be evaluated from engine scalars, never re-derived from the spec's cash.

**Decision: the engine writes one small `bars` sidecar per (run, symbol, split)** at `sim-artifacts/v1/<run_id>/bars/<SYMBOL>__<split>.json.gz`, emitted from `_replay_one` for the **base arm only** (base always runs first — `_with_base_first`, `runner.py:836`), right after the cell artifact, from that arm's `report.benchmark` (`fitness.BuyAndHold`: `shares`, `entry_price`, `exit_price`, `starting_cash`, `dividends_per_share`) and the materialised bars. It carries the decision-window closes the replay actually saw and the **engine-computed B&H curve**.

**The identity-move cost, made visible.** Any change under `src/**` moves `engine_identity` and invalidates every stored dedup key once (`scenario_runs.md` §One-time invalidation): the first re-submit of every old spec replays; the first Saturday battery after merge is the expensive one (~25–35 min, `fc-096-b.md` PR-d sizing). **PR-1 moves it regardless of the sidecar** — the A2-required `benchmark` stamp, the `capital_base` stamp and the `git_commit` fix all live in `src/backtesting/reporting/artifact.py` and `runner.py`. The sidecar's marginal identity cost is therefore zero; its real cost is that **every run replayed before PR-1 deploys has no sidecar** — those runs get the BQ fallback (live symbols, captioned) or the absent state (candidates), and their B&H curve is absent (the row's `benchmark_return` scalar still shows). Re-running a run is one submit; the dedup miss the identity move causes is exactly what makes that re-run produce a sidecar.

**Sidecar schema (`"schema": 1`, frozen-fixture-pinned like the cell artifact):**

```
{
  "schema": 1,
  "provenance": {run_id, symbol, split, window:{start,end}, first_decision_day, last_decision_day,
                 engine_identity, git_commit, generated_at, source: "materialised bars",
                 data_from, data_to, bars_in_window},
  "bars": [{date, open, high, low, close, volume}, ...],          // clipped to [first_decision_day, last_decision_day]
  "buy_and_hold": null | {
      capital_base, shares, entry_day, entry_price, exit_day, exit_price, dividends_per_share_total, final_value,
      daily: [{date, value}, ...]      // value_t = capital_base + shares*(close_t - entry_price) + shares*div_ps(entry_day, t]
  }
}
```
- The clip is the decision-day bounds `[daily[0].day, daily[-1].day]` — the same bounds `compute_fitness` uses for `days` and `_buy_and_hold` uses for entry/exit — so `daily[-1].value == BuyAndHold.final_value` holds by definition, not by coincidence.
- `capital_base`, `shares`, `entry_price`, `exit_price`, `dividends_per_share_total` are COPIED from `report.benchmark` (`capital_base` = `BuyAndHold.starting_cash`, which for a Phase C CC benchmark is the LOT value, not the spec's cash — the curve builder takes a `BuyAndHold` instance and never re-derives shares from spec cash). `div_ps(entry_day, t]` is `DividendSchedule.total_between(symbol, entry_day, t)` (`dividends.py:152`), the half-open interval `_score` uses.
- `buy_and_hold` is `null` exactly when `report.benchmark` is `None`.
- REQUIRED parity tests: (i) `daily[-1].value == report.benchmark.final_value` and `== capital_base × (1 + row.benchmark_return)` on the golden replay; (ii) **the CC hook, named for Phase C**: the curve builder parametrised over a hand-constructed `BuyAndHold(shares=100, starting_cash=<lot value>, …)` — the shape `fc-096-c.md` §C3 specifies — must satisfy (i) with `capital_base == lot value`; Phase C's build extends this test with a real CC replay.

**Per-cell stamps on the artifact (additive; `sim_artifact_schema_v1.json` updated; all REQUIRED):**
- `benchmark`: `{shares, entry_day, entry_price, exit_day, exit_price, dividends_per_share_total, capital_base, final_value, total_return}` from THIS cell's scored `report.benchmark`, or `null`. `_emit_artifact` receives `report`.
- `provenance.capital_base`: the denominator every ratio on this cell uses — `starting_cash` for a wheel replay; Phase C stamps its lot-based base. The console divides by THIS field, never by `starting_cash`.
- `provenance.git_commit`: populated (§Found while planning 1).
- The console cross-checks sidecar `buy_and_hold.final_value` against the cell's `benchmark.final_value`; a mismatch (which a same-spec run cannot produce) hides the curve with a "benchmark mismatch" flag rather than drawing it.

Writer: `ArtifactWriter.write_bars(payload)` (`artifact_store.py`), name from `identity.bars_object_name(run_id, symbol, split)`; `bars_written`/`bars_failed`; event `sim_bars_write_failed`; own `try`, never on the critical path. `artifacts_complete` is unchanged (cells only). Reader: `services/artifacts.ArtifactStore.fetch_bars` + `GET /api/v2/sweeps/{run_id}/bars/{symbol}/{split}` with the cell route's exact status semantics (400 / 404 / 502 / 503; sync `def`; `no-store`).

### D-3 — sizes, latency, caching

- **Per cell open:** artifact (~10 KB gz / ~80 KB JSON for a year) + base-cell artifact + sidecar (~5–7 KB gz for a year: 252 OHLCV rows + 252 curve points). Three parallel GETs, each one GCS download (~100–300 ms) on a warm dashboard; the dashboard is `--min-instances=0`, so the first request of a quiet hour pays one cold start.
- **Portfolio view:** N measured symbols' artifacts, 2N with the base overlay on, N ≤ 12, concurrency 4; progressive render with "k of N loaded" in the caption.
- **Cold sim-service tail** touches only the tweak bar (PR-4): a 202 lands in ≤ 150 s or the proxy 502s with the cold-start explanation and the UI offers "retry"; the console never blocks on it.
- **Wire errors carry status.** `getJson` (`useSweeps.ts:245-266`) throws a bare `Error` for non-401 failures; PR-2 extends it to throw `HttpError {status, detail}` (keeping `SessionExpiredError`/`UnauthorizedError` exactly as they are) so the cache can see a 404.
- **SPA cache** (`hooks/artifactCache.ts`): a module-level LRU (`Map<url, Promise<Result>>`, cap 48) shared by `useArtifact` and `useBars`, where `Result = {kind:'ok', artifact} | {kind:'absent', detail}`. Memoised only when the promise resolved 200, or resolved 404 **and the run's status is `done`** — the ONLY status under which a cell is fetched at all. `deduplicated` never fetches under its own `run_id`: the hook follows `deduplicated_to` (the console shows "answered by run X" and opens X). `submitted`/`running`/`failed` never fetch. **A rejected promise (any 5xx, network, 401) is evicted immediately**, so the next mount retries. The hooks take `status` from the caller (`useSweepDetail`'s row), never infer it. `resetArtifactCacheForTests()` mirrors `resetSessionExpiredSignal`.

### D-4 — the client digest, and the line it must not cross

`components/v2/console/artifactDigest.ts` is a pure module over `(artifact, sidecar | null)`. Definitions (each pinned on the real fixture by test):

- **Gross premium** = Σ (`cash_delta` + `fees`) over `sell_put_open` and `sell_call_open` events (cash received before the fee deduction). **Fees** = Σ `ledger[].fees`; the tile reads "regulatory pass-through @ $<rate>/contract (engine constant)" with the rate derived as Σ `fees` ÷ Σ contracts over the SAME event set — the fee-bearing events (`sell_*_open` AND `buy_to_close`); mixing the tile's all-events fee sum with an open-events contract count prints $0.047 on the committed fixture (1.68 ÷ 36) — the PR-2 digest test pins $0.040; not hardcoded (`BacktestBroker` default `fees_per_contract=0.04`, `broker.py:84`).
- **Net option cash** (cumulative series) = Σ `cash_delta` over option events by date.
- **Deployment** (dollar-weighted, all decision days) = mean over `daily` of `(reserved_collateral_t + shares_value_t) / capital_base`, where `shares_value_t = Σ shares_held × close_t` from the sidecar; with no sidecar, `shares × cost_basis` of the cycle open on that day (fallback, labelled "at cost"); with no artifact, nothing. On the fixture the two reserved-only readings the reviewer computed ($14,328 all-days mean vs $29,758 deployed-days mean) show why the definition is stated: the test pins the all-days dollar-weighted number the formula yields on the committed fixture, and the reserved-only component of it against $14,328.
- `capital_base` = `provenance.capital_base` when present; else `provenance.starting_cash` **only if the artifact is a wheel artifact** (§Degrading for CC); on a `covered_call` artifact with no `capital_base` every ratio tile is SUPPRESSED with "capital base not stamped on this artifact" — never divided by the $5k float.
- `monthly[]` in `MonthlyCashflow` shape (so `MonthlyPremiumBars.tsx` is reused unchanged); `drawdownSeries[]`; `deploymentSeries[]`.
- `reconcile: {optionPnl, maxDrawdown, putsSold, callsSold, cyclesCompleted, finalEquity}` — exists ONLY for the test: each field must equal the engine's row value on the real fixture (`option_pnl` = Σ `cycles[].option_pnl`; `max_drawdown` by the peak formula of `fitness.py:446`; `puts_sold`/`calls_sold` = counts of `sell_put_open`/`sell_call_open`; `cycles_completed` = cycles with `!is_open`; `final_equity` = `daily[-1].equity` = `counters.final_equity`). The strip DISPLAYS the row's values, never `reconcile`'s.

The FC-060 rule "the UI computes nothing" was written about **ranking inputs** and still holds: nothing in `digest` feeds a verdict, a median, a Δ, a colour, the forecast or a comparison; digest tiles are grey, uncoloured, labelled by source, and withheld in the compare view. Rejected alternative: an engine-side `summary` block — it would not exist on the objects already stored, and monthly buckets are a chart, not a fact the engine should own.

### Degrading for CC (Phase C, unbuilt)

Phase C stamps strategy/premise on artifacts (`fc-096-c.md` §C3) but its field names are not fixed. Phase E reads, in this order, and treats absence as **wheel**: `spec.strategy` on the sweep row (canonical-by-omission), then `artifact.provenance.strategy`. The fields Phase C MUST stamp for the console to compute anything on a CC cell: `provenance.capital_base` (the lot-based base; §D-4), `benchmark` (its lot B&H; §D-2). When `covered_call`: the "Synthetic lot — 100 shares at the window-start close" banner on every chart and table; `synthetic_lot_open` events get their own marker/badge; `premium_yield_on_lot` renders as the headline **when the grid cell carries it** and `annualized_return` is labelled "corrected equity return" per C3; CC footers print verbatim from `known_biases`; **every ratio tile, the deployment series and the portfolio index are SUPPRESSED (with the reason) when `capital_base` is absent** — labels are not a substitute for a denominator. Unknown ledger `kind`s render with a neutral badge and the raw kind string — never dropped, never crash (test: a ledger with a kind this build has never seen).

## Design decisions (made — do not relitigate in the build)

1. **Charting = recharts 2.15 (already installed), no new dependency.** Price chart = `ComposedChart` over ONE row array (one row per session: `{date, close, …markers}`), markers as `Scatter` series READING the same rows (marker y = that session's close) — never a `Scatter` with its own `data` on a category axis, which positions on its own domain. A pure `chartRows(bars, ledger, rollRecords)` builds the rows; a test asserts every marker's `x` equals its session's `x`, and an event date that is not a session is attached to the nearest prior session and flagged. Equity/B&H/base = `LineChart`; monthly premium = `MonthlyPremiumBars`; drawdown and deployment = `AreaChart`. Rejected: lightweight-charts / uPlot.
2. **Ledger/cycle tables aggregate client-side.** Bound: ~150–300 ledger rows for a 730-day cell (72 measured for 189 days), ≤ 60 cycles. No virtualisation.
3. **Exports.** CSV (RFC-4180: fields with `,`/`"`/newline quoted, quotes doubled; `detail` JSON-stringified in one column) with **trailing provenance columns on every row** — `run_id, scenario, symbol, split, engine_identity, fill_basis, fill_haircut, in_sample_only, strategy` — so the file is a plain table in Excel and pandas and cannot circulate unlabelled (no `#` comment lines). JSON export = `{"sweep_context": {run_id, cell, in_sample_only, in_sample_banner, known_biases, row: <the grid cell's scalars>, serialisation: "artifact re-serialised from the parsed object; not byte-identical to the endpoint response"}, "artifact": <object>}`. Rejected: XLSX; a paired meta file (two files to lose each other).
4. **URL is the state.** Routes `/sims`, `/sims/:runId`, `/sims/:runId/:scenario/:symbol/:split`, `/sims/compare?a=run:scenario:symbol:split&b=…` (`:` is safe: `SCENARIO_NAME_RE`/`SYMBOL_RE`, `identity.py:75,127`, admit no colon). **Navigation: `push` for every user selection (run, cell, split) so Back walks the history; `replace` only for the automatic newest-run / default-cell selection**, so Back never exits `/sims` through an auto-select. `SubmitSweep`'s `onSubmitted`/`onSelectRun` push.
5. **B&H curve is engine-produced** from the scored benchmark (§D-2).
6. **Client digest is display-only, reconciled by test, suppressed without a stamped capital base** (§D-4).
7. **Forecast is server-computed**, two bases, horizon-scaled in the UI (§Forecast).
8. **Compare is anchored to base by construction** (§Compare view).
9. **Tweak bar submits through `POST /api/v2/sims/run`, one field → one arm.** Controls come from `allowlist.allowed[].key` × `allowlist.value_types[key]` (`OVERRIDE_VALUE_TYPES`, `services/sweeps.py:399-421`: `band` / `number` / `int` / `bool` / `symbols`) — never from `described`, which is prose. `SweepAllowlist` (`types/v2.ts:599-604`) gains `value_types: Record<string,string>` and `defaults`. **`symbols`-typed keys (`universe.excluded_symbols`) get no control in v1** — it is a list, not a field, its natural UI is the symbol picker, and the JSON editor still accepts it; the bar says so in a footnote. Rejected: routing tweaks through the Job.
10. **IAP refresh is click-triggered via `window.open` called synchronously in the click handler**; never auto-opened; stops on `closed` (§IAP).
11. **No `whoami`.** Viewers see write controls and get the backend's 403 verbatim.
12. **Frontend fixtures are REAL captures** (§Fixtures).
13. **Naming.** The per-cell scalar is `delta_vs_base_annualized` (it is `annualized_return_arm − annualized_return_base`, through `_measured_value`, `sweeps.py:1604`); the existing per-scenario `delta_vs_base` (median) and the summary column keep their names. Per-cell `sign_agrees: true | false | null`.

## Compare view

- **What is compared:** two cells `a`, `b`, each `run:scenario:symbol:split` — arm vs base within a run (default), arm vs arm within a run, the same question across two runs (a pin's two Saturdays; a re-run after an engine change), any two cells that pass alignment.

An **A−B number appears only when `a.run === b.run && a.split === b.split`** (Δa − Δb, labelled "difference of two served Δs"). Otherwise curves overlay and no A−B number exists.
- **Alignment checks, in order:**

| dimension | how checked | mismatch posture |
|---|---|---|
| symbol | `a.symbol !== b.symbol` | **refused** — two symbols are not two configs; offers to open each cell |
| split | `a.split !== b.split` | **warning banner** ("in-sample vs holdout — not comparable"); return/Δ tiles withheld both sides; curves shown |
| window | `windows[split]` start/end differ | warning; x-axis = union, non-overlap shaded; tiles withheld |
| **arm identity** | `scenario_hash` differs for same-named arms (or overrides differ at all across runs) | warning "same name, different arm"; an **overrides diff** (key → a / b / base) rendered; tiles kept only if everything else aligns |
| starting cash / capital base | spec `starting_cash` (or stamped `capital_base`) differ | **tiles withheld** (sizing is `int(cash × max_position_size // strike × 100)` — a different cash is a different strategy, not a rescaled one); curves drawn base-100 |
| base config | `base_config_hash` differ | "each side's Δ is against a different base"; A−B never shown |
| engine identity | differ | note: "replayed by different engine builds `x`/`y`" (a pin's two Saturdays usually share identity — that is what dedup means — but an engine change between them is exactly what this note flags) |
| fill haircut | differ | amber fill-model label on the varying side |
| in-sample | either side | the banner, verbatim |

## Forecast range (component 7)

Computed in `shape_results` (PR-1), per scenario × symbol, `null` unless the fit AND holdout cells are both `measured` AND every input is non-null (`persist._finite` NaNs a bad value to NULL; a NULL input yields `null`, never `0`):

```
days(w)     = (window_end - window_start).days          # the ROW's requested window, calendar days — the dashboard cannot see the
                                                        # engine's decision-day bounds (fitness.py:144); the two differ by at most the
                                                        # non-session edges of the window, and the caveat says so
premium_w   = option_pnl_w / days(w)                    # $/calendar day, net premium: buybacks and fees inside; CASH basis — options
                                                        # still open at window end are counted at their sale price, unmarked
total_w     = total_return_w × capital_base / days(w)   # $/calendar day, TOTAL P&L incl. stock leg, marked at the last close
                                                        # capital_base = starting_cash (wheel); Phase C's stamped base once the row carries one — a covered_call row WITHOUT it ⇒ total_pnl null (suppress, never mis-scale; same posture as the digest)
per basis b ∈ {net_option_pnl, total_pnl}:
  low_pd_b, high_pd_b = min(fit_b, holdout_b), max(fit_b, holdout_b)
```
Served per symbol: `{fill: {basis: "mid", fill_haircut}, days: {fit, holdout}, net_option_pnl: {fit_per_day, holdout_per_day, low_per_day, high_per_day}, total_pnl: {…same…}, capital_base}`. Per scenario (portfolio): for each basis the SUMS over `included` symbols, plus `included: [symbols]`, `excluded: {symbol: state}`, `n_included`, `n_symbols`. Refusals: `in_sample_only` ⇒ `forecast: null` + `forecast_refusal`; a scenario with no included symbol ⇒ portfolio `null` with reason.

**Why two bases (round-1 A1, decided).** On this fixture the premium run-rate is $5.9k/yr fit vs $9.7k/yr holdout while total P&L orders the windows the other way: the wheel's stuck-long mode WRITES MORE CALLS on assigned shares while the position bleeds, so a premium-only range rises exactly when the strategy is doing worst. The signed range (premium) stands as the income view; the total-P&L range beside it is what keeps it from misleading. The panel renders both, never one.

**UI:** horizon selector — **default = the holdout window's length in days** (so the range reads as "the next period like the one you held out"); other choices 30 / 90 / 365; when `H > days(holdout)` a line says "extrapolated ×N beyond the holdout window". Values = `per_day × H` (display scaling only; a test pins `H = 365` against a server-supplied `annual_*` pair). Per symbol both ranges; portfolio row "n of N symbols" and both sums; **no arm-vs-arm portfolio comparison anywhere** (per-scenario `included` sets differ). Mandatory `forecast_caveat` (`data-testid="forecast-caveat"`) + the run's `known_biases` titles; a blank caveat makes the panel refuse to render.

**`FORECAST_CAVEAT`** (dashboard-only; `DASHBOARD_ONLY_PROSE = {"FORECAST_CAVEAT"}` in the fork test). Text, pinned: *"Two run-rates, extrapolated. The bounds of each are the fit and holdout windows' per-calendar-day rates over the row's requested window, scaled to the horizon; they are NOT a confidence interval — one regime, two windows, one engine whose premium is understated on both legs (see the biases below). PREMIUM is cash-basis net option P&L: buybacks and fees are inside, and options still open at window end are counted at their sale price, unmarked — a wheel holding assigned shares writes MORE calls while it loses, so this rate can rise while the strategy fails. TOTAL includes the stock leg marked at the last close. Each symbol is an independent replay on its own capital; the portfolio line is a sum over the symbols measured in both windows, named. An in-sample run has no forecast."*

**Alternatives considered, not adopted (deferred pending the operator):** a per-cycle block bootstrap over the artifact's `cycles[]` (resample cycles with replacement, re-sum to a horizon, report percentiles), and a rolling-90-day min–max of the run-rate over the full window. Both give a distribution instead of two points and both are honest about small samples; neither is the signed decision, and the bootstrap needs the whole-window artifact rather than the two split rows. Recorded here so the choice is visible; nothing in PR-1 precludes either.
