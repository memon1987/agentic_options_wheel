## Context

`ExecutionEngine.execute_batch` routes each opportunity on `opp.get('type', 'put')`
(`src/strategy/execution_engine.py:286`). Two producer families exist, and they use
disjoint vocabularies:

| producer | keys it sets | routed to |
|---|---|---|
| `options_scanner._create_put_opportunity` (`src/data/options_scanner.py:242`) | `'type': 'put'` (no `'strategy'`) | put — correct |
| `options_scanner._create_call_opportunity` (`src/data/options_scanner.py:340`) | `'type': 'call'` (no `'strategy'`) | call — correct |
| `put_seller.find_put_opportunity` (`src/strategy/put_seller.py:84`) | `'strategy': 'sell_put'` (no `'type'`) | put — correct **by accident of the default** |
| `call_seller.evaluate_covered_call_opportunity` (`src/strategy/call_seller.py:171`) | `'strategy': 'sell_call'` (no `'type'`) | **put — misrouted** |

The full misroute mechanism, verified in code on `main` @ `bd077a8`:

1. The backtest `Simulator._execute_opportunities` (`src/backtesting/engine/simulator.py:552-579`)
   mirrors production's `/run` phase but feeds it `run_strategy_cycle()`'s actions — i.e.
   the *seller-produced* dicts, which carry `'strategy'` but no `'type'`.
2. `execute_batch` defaults the missing key to `'put'` and hands the covered call to
   `put_seller.execute_put_sale`.
3. `execute_put_sale`'s safety guard (`src/strategy/put_seller.py:241-256`) parses the OCC
   symbol, sees a call, and rejects it with `non_retryable: True` — which also pushes the
   option symbol into the module-level `_failed_symbols` set.

Net effect: **every backtest ever run has modeled a put-only strategy.** Assigned shares
are never called away, cycles never complete, call premium is never earned. Evidence on
record: a 2-year NVDA replay reports 30 puts / 0 calls; the B2 study found 293 AAPL call
opportunities and 0 sold (`docs/investigations/fc-034-premium-floor-ab.md`, New findings §1).

**Why no test caught it:** the golden test `test_the_wheel_actually_turns`
(`tests/test_backtest_simulator.py:163`) asserts put → assignment → shares held and stops.
Its fixture (`falling_then_flat`) *cannot* produce a call even with correct routing: shares
are assigned at 92 while spot sits at 70, so the FC-029 drawdown pause (24% ≥ 5% threshold,
`call_seller.py:132-143`) blocks the write, and the cost-basis floor would find no strike ≥ 92
in the [0.15, 0.25] delta band anyway. FC-032's planned golden path ("…assigned → calls sold
→ called away") was never realized — the −30% crash fixture validated the call-*refusal*
path instead, and the suite covers exactly the half that works.

**Production is NOT affected.** The deployed path is `/scan` → `OptionsScanner` (types both
sides) → `OpportunityStore` → `/run` → `execute_batch`; 84 real covered calls exist in
`trades_from_activities`. But `execution_engine.py` and both sellers are live production
code, so this fix deploys to Cloud Run and the behavior contract below is binding.

**Consequence already recorded** (`docs/plans/fc-042.md` Closeout): this defect "gates
Track D: standing up the monthly screen while backtests model half a wheel would automate
demotion decisions on put-only evidence."

## Goals

- Kill the misroute *class*, not just this instance: routing can never again silently
  disagree with the contract actually traded, and a missing/unknown type fails loud.
- Add the test that was always missing: a replay assertion that a covered call is sold
  after assignment — and that a wheel cycle actually completes.
- Re-validate every downstream conclusion the put-only engine touched, with explicit
  acceptance criteria distinguishing "fix worked" from "fix introduced a new distortion."
- Give the owner a clear go/no-go sequencing for Track D (monthly screen Cloud Run Job).

## Non-goals

- **No change to `rank_opportunities` / `select_batch` collateral math.** Covered calls are
  still sized by put math and charged phantom cash collateral
  (`docs/investigations/covered-call-starvation-2026-07-18.md` F1, FC-038 scope). Real,
  adjacent, *separate* defect — see Design decision D3 and the re-validation attribution
  step that keeps it honest.
- No trade-journal labeling fix (`trade_journal.py` defaults `strategy → 'sell_put'`;
  starvation doc F3). Replay uses `NoOpTradeJournal`; production mislabeling is its own
  small FC.
- No live threshold, config, or scheduler changes. No Track D deploy in this PR.
- No opportunity-dict schema refactor (see rejected alternative D1-c).

## Proposed approach

### Part 1 — The fix

**D1. Route on the OCC option symbol, not on a dict key. Fail loud on "unknown".**

In `execute_batch` (`src/strategy/execution_engine.py:286`), replace

```python
opp_type = opp.get('type', 'put')
```

with routing derived from the contract itself:

```python
parsed_type = parse_option_symbol(opp.get('option_symbol') or '').get('option_type')
# parsed_type is 'put', 'call', or 'unknown' — parse_option_symbol never raises
```

- `'call'` → call path (unchanged internals: call_seller presence check, available-shares
  check, `execute_call_sale`).
- `'put'` → put path (unchanged: `execute_put_sale(opp, skip_buying_power_check=False)`).
- anything else (`'unknown'`, missing `option_symbol`) → **reject loudly**: append a
  structured failure to `execution_results` (`success: False`,
  `error_type: 'unroutable_opportunity'`, message naming the symbol,
  `non_retryable: True` so `_failed_symbols` suppresses retry storms), emit
  `log_error_event`, execute **neither** seller. Do not raise — one malformed opportunity
  must not kill the batch (existing per-opp `try/except` semantics preserved).
- If the opp carries a `'type'` or `'strategy'` key that **contradicts** the parsed symbol,
  log a warning (`event_type="opportunity_type_mismatch"`) and trust the parsed symbol —
  the OCC symbol is what `place_option_order` will actually trade, so routing by anything
  else can only ever be equally right or wrong-er.

Rationale: the OCC symbol is set by **all four** producers and is the one field that cannot
drift from the order placed. Routing on it eliminates both failure modes at once — the
missing key (this bug) and a future wrong key. `parse_option_symbol`
(`src/utils/option_symbols.py:227`) is the sanctioned parser (contra the substring-matching
bug family FC-041/FC-043/FC-045) and returns `option_type: 'unknown'` rather than raising.
`put_seller`'s existing wrong-seller guard already does this exact parse as a backstop —
this moves the authority to the router where it belongs, and keeps the guard as
defense-in-depth.

**Rejected alternatives (do not relitigate):**

- *(a) Just add `'type': 'call'` in `evaluate_covered_call_opportunity`.* Three lines, and
  it fixes this instance — but it leaves `opp.get('type', 'put')` in place, so a missing
  key still silently means "put". The next producer (or a store round-trip that drops the
  key) re-creates the bug invisibly. The default *is* the trap; a fix that preserves it
  invites the next occurrence.
- *(b) Route on `'strategy'`.* Both sellers set it correctly, but **neither scanner
  producer sets it at all** — production `/run` executes scanner-shaped dicts, so this
  would misroute production in the opposite direction unless the scanner is touched too,
  after which two parallel vocabularies still exist with the same drift risk.
- *(c) Normalize at the boundary — a validated `Opportunity` dataclass.* The right
  long-term shape, but it's an M-sized refactor across four producers, the GCS store's
  JSON round-trip, `RiskManager` (which reads `opportunity['strategy']` bare), and the
  journal. Disproportionate to the defect and it delays the re-validation, which is the
  actual deliverable. If wanted, file it as its own FC.

**D2. Wheel-symmetry changes** (required by `docs/CLAUDE.md` "Wheel Strategy Symmetry
Principle"):

- Add `'type': 'call'` to the opportunity dict in `evaluate_covered_call_opportunity`
  (`src/strategy/call_seller.py:169-189`) and `'type': 'put'` in `find_put_opportunity`
  (`src/strategy/put_seller.py:82-98`). Not load-bearing after D1 — documentation,
  telemetry, and belt-and-braces for any downstream consumer; also removes the vocabulary
  asymmetry that caused this bug.
- Add the mirrored wrong-seller guard to `call_seller.execute_call_sale`: parse the OCC
  symbol; if it is a **put**, reject with `error_type: 'wrong_seller'`,
  `non_retryable: True`, mirroring `put_seller.py:241-256` including the log event shape
  (`event_type="put_rejected_by_call_seller"`). Today the put side has this protection and
  the call side does not.

**D3. The phantom-collateral co-defect stays out — but cannot be ignored silently.**
`rank_opportunities` runs every opportunity through `put_seller._calculate_position_size`
(strike×100 capital, `max_position_size` = 0.35 of portfolio cap) and `select_batch`
charges `strike × 100 × contracts` against buying power **for calls too**, though a covered
call needs $0 cash. In a fresh single-symbol replay at the default $100k this does not
zero calls (post-assignment cash comfortably covers one contract for every universe symbol
except near the ~$350+ boundary, where 0.35 × portfolio bites), but it *can* silently drop
calls in exactly the scenarios that matter — expensive underlyings and depleted-cash paths.
It is production-shared code with its own investigation, FC linkage (FC-038), and required
fixes from that review (call-ranking metric, share reservation at selection). Bundling it
here would violate one-PR-per-FC and double the review surface. Instead, the re-validation
protocol below **attributes** any remaining zero-call symbol to its blocking gate, so this
decision is falsifiable rather than an assumption.

### Part 2 — Tests

All in existing files; no production-code test exemptions apply (this is behavior change →
tests required).

**T1. Routing unit tests** — `tests/test_execution_engine.py`, extend `TestExecuteBatch`:

| test | shape | asserts | regression caught |
|---|---|---|---|
| T1a | engine-shaped call: `{'strategy': 'sell_call', 'option_symbol': 'XYZ240621C00095000', ...}`, **no** `'type'` | `call_seller.execute_call_sale` called; `put_seller.execute_put_sale` NOT called | **the FC-048 bug itself** |
| T1b | scanner-shaped call: `{'type': 'call', 'option_symbol': ...C...}` | call path taken | production `/run` call routing must not change |
| T1c | scanner-shaped put (`'type': 'put'`) and seller-shaped put (`'strategy': 'sell_put'`), both with `...P...` symbols | put path taken, `skip_buying_power_check=False` preserved | production/engine put routing must not change |
| T1d | opp with missing `option_symbol`, and opp with garbage symbol (`'NOT_AN_OCC'`) | neither seller called; result `success=False`, `non_retryable=True`; batch continues to next opp | **the silent-default class** — a future untyped producer fails loud instead of trading as a put |
| T1e | contradictory keys: `'type': 'put'` with a `...C...` symbol | routes to call path; mismatch warning logged | key drift can no longer override the contract |

**T2. Producer-contract test** — `tests/test_put_seller.py` / `tests/test_call_seller.py`:
assert both sellers' opportunity dicts carry `'type'` and `'strategy'` with the correct
values. Catches a future producer edit that drops the vocabulary again (cheap canary; D1
means it can't misroute, but the mismatch warning in T1e would start firing).

**T3. Replay integration test — the missing golden path** — `tests/test_backtest_simulator.py`:

- **New fixture `dip_then_recovering`** (keep `falling_then_flat` untouched — it is
  load-bearing for the dividend/assignment tests and now *documents* the drawdown-pause
  path). Shape: ~45 warm-up sessions at 100 (GapDetector needs the history); slide fast
  enough to put the ~8%-OTM put strike (≈92) ITM by a Friday expiry (stay under the 5%
  overnight-gap block, as the existing fixture does); then **recover to ≈ cost basis
  (93–96) and hold flat** for ≥ 3 more weekly expiries. At spot ≥ basis the drawdown pause
  (5%) does not trigger and `find_suitable_calls(min_strike_price=basis)` has in-band
  candidates just above 92. The builder must verify with the ScriptedProvider pricing model
  that call deltas at strikes 93–97 actually land in `call_delta_range` [0.15, 0.25] and
  tune the recovery level / hold length until they do — the *contract* is the assertions,
  not the exact closes. End the fixture with spot **above** the sold call's strike at an
  expiry so the call assigns.
- **`test_a_covered_call_is_sold_after_assignment`**: run the sim; assert ledger contains
  `put_assignment`, then `sell_call_open` **after** it, and that every `sell_call_open`
  strike ≥ the cycle's assignment strike (cost-basis floor holds in replay). Catches: the
  misroute, and any future regression anywhere on the find→rank→select→execute call chain
  (drawdown pause misfiring, sizing silently dropping calls, adapter share-check failing).
- **`test_the_wheel_actually_completes_a_cycle`**: assert `call_assignment` in the ledger
  and `build_cycles(...)` yields ≥ 1 finished cycle with `called_away=True` and
  `calls_sold ≥ 1`. This is the FC-032-planned golden path, finally real. Catches: any
  break in the second half of the wheel lifecycle end-to-end.
- Assert the run's rejection summary contains **zero** `wrong_seller` /
  `unroutable_opportunity` rejections (guards against the fix half-working — calls found
  but still dying at execution).

**Suite baseline:** 645 green on `main` @ `bd077a8`; all 645 must stay green (any existing
test that asserted the old routing default is a test bug — fix it to the new contract and
say so in the PR).

### Part 3 — Re-validation (the substantive work)

Run **after** the fix merges, warm-cached (FC-042 Track A makes single-symbol re-runs
minutes, not the pre-cache ~25 min). Results go in a new
`docs/investigations/fc-048-revalidation.md`; each item below states what changes and what
verdict is / is not at risk.

**R1. NVDA 2-year evaluate re-run** (the "30 puts / 0 calls" evidence).
`python main.py --command backtest --symbol NVDA --start 2024-07-01 --end 2026-07-01`.
Expected: `calls_sold > 0` in stretches where an assignment was followed by recovery to
within 5% of basis; some cycles complete. Record puts/calls/cycles before vs after.

**R2. Screen re-run, full 14-symbol universe** (local `--command screen`; the endpoint
stays disabled — this is not Track D). The FC-032 Phase 5 finding at direct risk: **7 of 14
symbols (incl. SPY, QQQ) got `insufficient` verdicts purely for not closing a cycle** — a
put-only engine cannot close a cycle *by construction*, so that finding is plausibly 100%
artifact. Expected: symbols whose replays contain assignments now close at least some
cycles; verdicts may move in any direction (see acceptance criteria — completing the wheel
*caps* upside via the call strike while *adding* premium, so per-symbol returns can go
either way). Also: prior rows in `options_wheel.backtest_runs` are put-only evidence — add
a dated note to `docs/bigquery/backtest_runs.md` ("rows with `run_at` before the FC-048
merge date were produced by a put-only engine; do not compare across the boundary").
Deliberately *not* deleting or editing rows (synthetic-write rules don't apply to leaving
history in place; provenance is the timestamp + `config_hash`).

**R3. The three studies** — which conclusions are and aren't at risk:

| study | headline conclusion | rests on | at risk? |
|---|---|---|---|
| `fc-036-gap-gate-study.md` | **DO-NOT-ARM** (a working gate would have cost $5,021 net) | Layer 3: 330 **real fills** from BigQuery | **Not at risk.** Re-run the engine layers (`layer2`, `equiv` — one command each per the study doc) because rule (b)'s monotone return-on-collateral shape came from put-only replays; if the *engine* layer flips sign post-fix, surface to owner — but the real-fills verdict stands regardless. |
| `fc-002-gap-filter-ab.md` | anti-selective filter; **do not re-tune, resolve FC-049 first** ($8,691 forgone on real entries) | real-fills + overlay layers | **Not at risk** — the study says so itself. The one engine-supported arm (graduated response → delta band [0.10, 0.15]) is already flagged "contingent on a re-run after FC-048" in the FC-002 entry; re-run that arm. |
| `fc-034-premium-floor-ab.md` | **DEMOTE** F/PFE/KMI/VZ (richest in-band put pays $0.03–$0.08) | chain-level premium distributions + 330 real fills | **Not at risk.** But its open question 4 (call-side floor) was *unanswerable* in a put-only replay — it becomes answerable now; re-run the call-side observation. |

**R4. Track C (dividends / early assignment) numbers.**
- **C2 has never fired in a real replay.** `_assign_calls_before_ex_dividend` needs a short
  call to exist; none ever did. `early_assignments` and `unpriced_ex_div_calls` have read 0
  in every replay to date — the code is validated only by unit tests with hand-built broker
  state. After the fix, expect nonzero early assignments on dividend payers with ITM calls;
  spot-check one against `should_assign_early`'s extrinsic-vs-dividend rule by hand.
- **C1's wheel-side dividend totals will DROP** on symbols where calls now remove shares —
  the put-only wheel held shares indefinitely and over-collected dividends relative to a
  correct wheel. Re-run the KMI (or other payer) window and confirm attribution still
  reconciles to the cent (existing test machinery).

**R5. Fidelity claims (`docs/plans/fc-032.md`).** The 81% strike-reproduction parity check
covers **puts only** — its 204 decisions are defined as "every (date, underlying) with a
put sell-to-open fill" (`docs/investigations/fc-032-parity-check.md`, Method). **No
call-side selection fidelity has ever been measured.** Extend `tools/diagnostics/
parity_check.py` per the symmetry rule: same per-decision method against the 84 real
covered-call fills in `trades_from_activities` (rebuild the day's chain, run
`find_suitable_calls` with the live cost basis, compare strike). Note this is *selection*
fidelity and was never broken by FC-048 (only execution routing was), so it can run
independently of the fix — but it must exist before call-bearing verdicts are trusted.
Update fc-032.md's Execution notes to label the existing 81% as put-side.

**Acceptance criteria — "fix worked" vs "new distortion":**

Fix worked (all required):
1. T3 tests green; NVDA re-run shows `calls_sold > 0`; zero `wrong_seller` /
   `unroutable_opportunity` rejections in any replay's rejection summary.
2. **Put-side invariance:** a replay over a window with no assignments produces an
   **identical ledger** pre/post fix (calls can only exist after assignment, so any
   put-side delta means the routing change touched the wrong path). Concretely: re-run one
   assignment-free symbol-window from R2 on both commits and diff the ledgers.
3. For every R2 symbol with ≥1 assignment but **still zero calls**, attribute the block to
   a named gate from the logs — drawdown pause, cost-basis floor (no in-band strike ≥
   basis), stage-8 sizing, or select_batch collateral. The first two are *correct strategy
   behavior*; either of the last two is the D3 phantom-collateral defect surfacing — record
   it in the re-validation doc and escalate per Open question Q2. "Zero calls,
   unattributed" is a failed re-validation.

New-distortion tripwires (any of these blocks sign-off):
4. Any `sell_call_open` strike below its cycle's per-share assignment strike (cost-basis
   floor breached in replay — guaranteed-loss calls).
5. Any call sold while broker shares < 100 × contracts (naked call — the broker should
   make this impossible; assert it anyway).
6. Implausibly fast cycling: with weekly calls at delta 0.15–0.25, roughly 15–25% of calls
   should assign per expiry — if a large majority of cycles complete on their *first* call
   expiry across symbols, suspect systematically-ITM call selection (pricing/delta
   modeling) rather than celebrate the completed cycles.
7. Attribution/equity reconciliation failures anywhere (existing tests + R4).
8. Do **not** use "returns went up" as success evidence: completing the wheel adds call
   premium but caps rally upside at the strike; the sign of the per-symbol change is
   path-dependent and both directions are consistent with a correct fix.

### Part 4 — Sequencing: Track D waits

**Recommendation to the owner: do not deploy the monthly-screen Cloud Run Job until (1)
this fix is merged and (2) R1–R3 of the re-validation are done and written up.** The
fc-042 Closeout already states FC-048 gates Track D, and the Phase 5 smoke run is the
proof: 7 of 14 demotion-relevant verdicts were plausibly pure artifact. Deploying the job
first would persist monthly put-only verdicts into `backtest_runs` and normalize reading
them. R4/R5 (Track C re-checks, call-side parity) should be done before any screen result
drives an actual **demotion**, consistent with FC-032's standing rollout rule (two observed
cycles, human decision) — but they need not block the *deploy* itself if the owner wants
the job standing up earlier. FC-049 (stage-2 filter not wired into live) is an independent
credibility question about what the engine's gap filter *means* relative to production; it
does not make screen rows wrong and is not a Track D gate — flag it in the screen doc
rather than serializing on it.

## Behavior contract (what must NOT change)

- **Production routing is bit-identical for well-formed opportunities.** Scanner-shaped
  put/call dicts route exactly as today (T1b/T1c prove it): the parsed OCC type equals the
  existing `'type'` key by construction. The only behavior change for existing shapes is
  the engine-produced call dict, which goes from silent misroute-and-reject to correct
  execution.
- The put path still calls `execute_put_sale(opp, skip_buying_power_check=False)`.
- Call path internals unchanged: `call_seller is None` skip, available-shares /
  committed-shares check, non-addition to `_failed_symbols` on share shortfall.
- Failure bookkeeping unchanged: `non_retryable` results still feed `_failed_symbols`;
  journal writes, log event shapes, and the `(execution_results, trades_executed)` return
  contract are untouched.
- Opportunities that today execute successfully must not start being rejected: every
  producer sets a valid OCC `option_symbol`, so the unroutable branch fires only where
  today's code would *misroute* — strictly safer.
- `falling_then_flat` and all existing simulator/dividend tests unchanged.
- No changes to `RiskManager` (reads `'strategy'`, both sellers still set it), the
  opportunity store, or any scanner output shape.

## Risks & mitigations

- **Risk:** an OCC symbol some producer emits fails the parser in a way live data would
  expose (e.g., unusual roots). — *Mitigation:* the universe is 14 plain-root symbols; the
  fallback branch of `parse_option_symbol` handles hint-less extraction; T1d covers the
  reject path; production monitoring watches for `unroutable_opportunity` events
  post-deploy (expect zero).
- **Risk:** the new fixture can't hit the [0.15, 0.25] call delta band with the scripted
  pricing model. — *Mitigation:* the model is smooth and symmetric in moneyness; tune
  recovery level / strike ladder. If genuinely stuck, widen the fixture's config override
  for the test rather than weakening the assertion — flag in PR if so.
- **Risk:** post-fix replays surface the D3 phantom-collateral defect as zero-call symbols
  and the re-validation stalls. — *Mitigation:* acceptance criterion 3 makes attribution
  mandatory and Open question Q2 pre-defines the escalation path; the fix itself is not
  blocked.
- **Risk:** re-validation results get read as "the wheel is better than we thought"
  from a single bull regime. — *Mitigation:* criterion 8; the single-regime caveat from
  fc-032 applies verbatim and must appear in the re-validation doc.

## Review cadence

Production code paths touched → branch + PR, **two adversarial reviewers** (Fable, fresh
contexts, concurrent, standard template), then scoped confirmation pass if fixes land in
code. Suggested personas (genuinely different lenses): a senior options trader who has
watched a backtest lie to a real account, and a simulation/backtest-methodology engineer
who has debugged look-good-but-wrong replay results. Give at least one reviewer the
evidence trail (`fc-034-premium-floor-ab.md` New findings §1, the NVDA 30/0 report) and
have them verify the pre-fix zero-call behavior themselves rather than trusting this plan.
