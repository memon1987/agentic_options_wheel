## Context

`fc018_acb_timeline_per_symbol` is structurally broken across every symbol since FC-018 created it. It sources from `trades_with_outcomes`, which is filtered to opening sell_short FILLs only — so the view never emits `OPASN` (assignment / called-away), `OPEXP` (expiration), `FILL` buy-to-close (option_closed), or `OPTRD` (share movement) rows.

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| AAPL | 2 | 2 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| AMD | 55 | 46 | 9 | 0 | 0 | 0 | 0 | 0 | 0 |

| NVDA | 80 | 70 | 10 | 0 | 0 | 0 | 0 | 0 | 0 |
| UNH | 27 | 23 | 4 | 0 | 0 | 0 | 0 | 0 | 0 |

UNH actually has 3 OPASN puts, 3 OPASN calls, 1 OPEXP, 6 OPTRD events in `trades_from_activities` — none reach the view. `running_shares > 0` never occurs, and `acb_per_share` is therefore always NULL via the `WHEN running_shares > 0 THEN ... ELSE NULL` guard.

**Three downstream surfaces are silently broken by this:**

1. **ACB Walk chart** — yellow ACB line never renders; reference dots all collapse to y=0 on the ACB axis (line 119: `y={s.acb ?? 0}`); legend advertises 6 event colors but only 2 ever appear.
2. **Trade Log** — table title says "Includes opens, closes, assignments, and expirations" but only opens render.
3. **Phase Timing** — Python state machine in `get_phase_timing()` reads the same view; with no OPASN/OPEXP/buy_to_close events arriving, only the `short_put` phase is ever entered.

Per CLAUDE.md "accurate numbers are paramount for reporting" — this is a fundamental data-completeness bug, larger in scope than FC-023.

## Goals

- Rewrite `fc018_acb_timeline_per_symbol` to source from `trades_from_activities` directly so it emits **every** event type: opens, closes, assignments, called-aways, expirations.
- Restore `running_shares > 0` during share-holding periods so the yellow ACB line renders.
- Restore all 6 event-label colors (`put_sold`, `call_sold`, `option_closed`, `put_assigned`, `called_away`, `expired`).
- Fix the `AcbWalkChart` reference-dot positioning so dots during cash phases (no shares held) are placed on the cumulative-premium axis at their respective premium level instead of falling to y=0 on the ACB axis.
- Improve chart legibility: add a one-line subtitle explaining the chart, and a richer tooltip that surfaces event details (strike, qty, premium) at the hovered timestamp.
- Preserve `outcome` and `realized_pnl` projection on opening-fill rows so the Trade Log's "Outcome" and "Realized" columns continue to populate.
- Validate on UNH (the FC-023 trace symbol): expect 3 `put_assigned`, 3 `called_away`, 1 `expired`, multiple `option_closed` events; ACB transitions during cycles 1–3.

## Non-goals

- **Cycle-isolated ACB.** The wheel-community formula `(share_cost − cumulative_net_premium) / shares` is cumulative-since-inception. After a cycle's shares are called away, residual share_cost (e.g., UNH cycle 1's −$1,750 loss) carries forward and affects the next cycle's ACB. This is consistent with the documented formula and is a defensible interpretation; cycle-isolation is a separate (deferred) concern.
- **FIFO matching for overlapping share lots.** Already filed as FC-020; does not block this work.
- **Dividend-reinvested ACB / B&H.** Same-symbol dividends are not in our data pipeline; out of scope.
- **Phase Timing display tweaks.** Observation #4 graduates from "broken" to "needs verification" once this view is fixed; if any display tuning is required, it'll be a separate (small) FC.

## Proposed approach

**View rewrite** — `docs/bigquery/fc018_views.sql` (`fc018_acb_timeline_per_symbol`):

Source from `trades_from_activities` via four UNION-ALL blocks, one per event family:

1. **Opens (sell_short FILL)** — read from `trades_with_outcomes` to inherit the existing `outcome` + `realized_pnl` projection (Trade Log depends on these for opens). `net_premium_delta = +premium_total`. `shares_delta = 0`. `share_cost_delta = 0`. Label = `put_sold` / `call_sold`.

2. **Closes (buy_to_close FILL)** — read from `trades_from_activities`. `net_premium_delta = −premium_total`. `outcome`/`realized_pnl` = NULL on the close row (the *open* row already carries the realized P&L). Label = `option_closed`.

3. **OPASN (assignments / called-aways)** — read from `trades_from_activities`, LEFT JOIN to OPTRD on `(underlying, transaction_time within ±120s, qty sign matches direction)` to pick up `net_amount`. `net_premium_delta = 0`. `shares_delta = +qty*100` (put assignment) or `−qty*100` (called away). `share_cost_delta = −optrd.net_amount` so positive on assignment (cash out) and negative on called away (cash in). Fallback `share_cost_delta = strike_price * qty * 100` if no OPTRD row matches (keeps the view robust if OPTRD ingest is delayed). Label = `put_assigned` / `called_away`.

4. **OPEXP (expirations)** — read from `trades_from_activities`. All deltas = 0. Label = `expired`.

OPTRD events themselves are NOT emitted as their own dot — they are folded into the matching OPASN row's share-side data (per the design choice the user approved). This avoids double-rendering simultaneous events.

The outer SELECT applies the same window functions (`SUM(...) OVER (PARTITION BY underlying ORDER BY event_time, activity_id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)`) to compute `cumulative_net_premium`, `running_shares`, `running_share_cost`. ACB formula unchanged: `WHEN running_shares > 0 THEN SAFE_DIVIDE(running_share_cost − cumulative_net_premium, running_shares) ELSE NULL`.

`activity_id` is added as the secondary `ORDER BY` key inside the window so events with identical `event_time` (e.g., paper-engine OPASN+OPTRD with identical timestamps) sort deterministically.

## Reuse

- The window-function pattern (`SUM(...) OVER (PARTITION BY underlying ORDER BY event_time ...)`) is unchanged from the current view. Only the source CTE and per-row deltas change.
- `trades_with_outcomes` continues to be the source for opens (preserves `outcome` + `realized_pnl` derivation that Trade Log relies on). Closes/OPASN/OPEXP come from raw `trades_from_activities`.
- Recharts `<ReferenceDot yAxisId="..." />` already supports per-dot axis selection — no library swap needed.

## Risks & mitigations

- **Risk:** OPASN ↔ OPTRD timestamp-tolerance JOIN could mis-pair if two assignments on the same underlying happen within 120 seconds.
  - *Mitigation:* Add `qty` sign-matching as a secondary join condition (puts get OPTRD with positive qty, calls get OPTRD with negative qty). Same-day-same-direction collisions are extremely rare in practice; verified on full UNH/AMD/AMZN/NVDA/GOOGL/IWM/AAPL data — every OPASN/OPTRD pair is within 60 seconds of its match. Falls back to `strike_price * qty * 100` if no OPTRD found.
- **Risk:** Trade Log loses outcome/realized_pnl coverage for newly-emitted close/OPASN/OPEXP rows.
  - *Mitigation:* On those rows we emit `outcome=NULL` and `realized_pnl=NULL`. The Trade Log already renders `—` for null fields ([TradeLog.tsx:130,136](dashboard/frontend/src/components/v2/TradeLog.tsx#L130)). Net effect: the new close/assignment/expiration rows show `—` in the Outcome and Realized columns, while the corresponding *open* row (same OCC contract) still shows the eventual outcome — no regression.
- **Risk:** Phase Timing's state machine, currently silently broken (only enters `short_put`), starts producing different numbers post-fix and could surprise the user.
  - *Mitigation:* This is the *correct* behavior; observation #4 explicitly flags Phase Timing as broken. Document in the FC-024 PR description that this is an incidental fix; user already expects it.
- **Risk:** ACB walk's "cumulative-since-inception" interpretation lets prior-cycle share losses carry into current ACB.
  - *Mitigation:* Out of scope per Non-goals. The chart subtitle clarifies what the line shows. Cycle-isolated ACB can be a separate FC if requested.
- **Risk:** Existing `acb_per_symbol_current` view (downstream of this view) could change behavior.
  - *Mitigation:* Verify after deploy: `SELECT * FROM acb_per_symbol_current` should now show `running_shares > 0` for AMZN (the only symbol with currently-open shares) and 0 for others. Currently shows 0 for everyone (because the broken view never accumulated shares).
