## Design decisions (made)
- **Merge, don't choose.** In `ChainStore.get`, when a lake download lands but `_covers` rejects it, remember the rejected frame for that `(underlying, as_of)` (`_lake_rejected_frames`, in-memory, per store). In `put()`, if a rejected frame exists for the key: merge rows — union keyed by `symbol` (contract), new build wins on duplicates; provenance = (**equal `universe_dte`** — CORRECTED by review round 1, the original `max(universe_dte)` was a plan defect, see §Design correction — `min(strike_gte)`, `max(strike_lte)`, same `model`; if models differ, no merge); write the merged parquet locally (atomic), then `_mirror_to_lake` as today (now a superset → uploaded with the captured generation).
- **Gap rule:** if the two strike windows do not overlap (`new.strike_gte > old.strike_lte` or vice versa), skip the merge, upload nothing, log `chain_lake_merge_gap` with both windows. Never claim coverage the file does not contain.
- **Counters:** `lake_merged`, `lake_merge_gaps` in `summary()` and the run summary. Review round 1 added `lake_merge_refused` (the `dte_mismatch` and `overlap_conflict` refusals), kept separate because a gap uploads nothing while a refusal falls through to the monotone path; all three also trip `chain_lake_degraded`.
- **Empty-chain sentinel rows** are dropped from the union if the other side has real rows; kept if both are empty.
- Local-only runs (no lake) are unaffected: the rejected-frame path exists only when a download happened.

## Design correction (review round 1, 2026-08-28)

Both adversarial reviewers of PR #101 raised the same HIGH, against **the plan**, not the build: `max(universe_dte)` over-claims.

A build window is a rectangle in (DTE reach × strike range). The union of two rectangles is an **L**, and the provenance columns can only describe a rectangle — so a merge that widens *both* axes stamps the file with the **bounding box**, claiming a corner neither fetch ever covered. Concretely: old = reach 14 over [90, 110], new = reach 7 over [100, 130] → merged claim (14, 90, 130), while no 8–14 day contract above strike 110 was ever fetched by either side. A later request at reach 14 across the new strikes then passes `_covers` and returns a chain **silently missing rows** — precisely the "a chain missing the strikes the caller asked for looks exactly like a day on which those strikes did not trade" failure this module's docstring opens with. Both reviewers reproduced it.

**Rule as built:** only the **strike** axis may widen. `int(new.universe_dte) != int(old.universe_dte)` → refuse (`dte_mismatch`), fall through to the coverage-monotone path.

This does not cost the case the FC exists for. `universe_dte` is `max_dte + UNIVERSE_DTE_BUFFER` and neither term is path-dependent, while the strike anchors follow the session's price — so the observed SPY/IWM/PFE thrash is a pure strike move at a **constant reach of 8 on both sides**. The heal survives the fix intact.

**Second review finding (MEDIUM), also built:** where the two windows overlap, both files asked the same question of the same settled session and must have found the same contracts. Compared **by contract symbol**, not by count. A disagreement means one fetch was truncated, rate-limited or restated by the vendor; merging would absorb it into a file that is self-consistent, passes every check and is quietly missing rows. Refuse (`overlap_conflict`) and let the monotone path deal with it.

**Alternative considered and deferred** (raised by a reviewer): on a coverage rejection, *widen the request* and rebuild at the union window, so the file genuinely IS the rectangle it claims. That heals the DTE case too, and is strictly more general. Deferred because it enlarges the vendor fetch on exactly the days that are already the slowest (a thrash day would fetch the union of both windows rather than the run's own), and because it changes what the simulator asks for rather than only what the cache stores — a bigger blast radius than the observed defect warrants. The equality rule is the minimal regression-free fix for the case in production. If `lake_merge_refused` shows `dte_mismatch` recurring in the wild, that is the signal to revisit.

## Behavior contract
- A rejected-then-rebuilt day with overlapping strike windows **at the same DTE reach**, whose two fetches agree on the strikes they both cover, results in ONE lake object whose rows = union and whose provenance = (that reach, union of the strike windows); a later request within either window is a hit.
- Non-overlapping strike windows: lake object unchanged; logged; nothing uploaded.
- Differing DTE reaches, or two fetches that disagree on their overlap: no merge, lake object unchanged, logged; the day falls back to the coverage-monotone path. A later request the merged file would have over-claimed is a MISS, never a hit missing rows.
- No-lake behavior byte-identical to main.

## Tests

2. Old [90,100], new [120,130] → no merge, no upload, `lake_merge_gaps == 1`, log event.
3. Model mismatch → no merge (existing skip path).
4. Merged file passes `_covers` for both the old and the new request; `get` after merge is a local hit.
5. Sentinel handling (empty old + real new → real rows only, where the overlap holds no contracts on either side; a sentinel that contradicts the other side's rows is an `overlap_conflict`, not a merge).
6. Seed tool unaffected.
7. (review round 1) Differing DTE reaches → merge refused, and a later request at the longer reach over the newer strikes is a **MISS**, not a hit missing contracts.
8. (review round 1) The two fetches disagree on the strikes they both cover → refused; equal counts with different symbols must still refuse.

Mutations: (a) drop the union (keep new only) → test 4's old-request row assertion fails; (b) restore `max(universe_dte)` → test 7 fails; (c) drop the overlap check → test 8 fails; (d) compare the overlap by count instead of by symbol → test 8 fails.

## Alternatives (recorded from review)
- **Rebuild at the union window**: on a coverage rejection, widen the request to (max dte, min gte, max lte) and fetch that, so the file IS the rectangle it claims — heals gaps too, keeps one-request-one-file provenance; cost: a larger fetch on thrash days. Deferred; the equality rule is the minimal regression-free fix for the observed case.
- Healing is Job-only: a locally-rejected file (dev machine, scenario-runner multi-window loops) is not remembered; `_probe_remote` could remember frames — follow-up.
