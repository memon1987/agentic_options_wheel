## Design decisions (made)
- **Merge, don't choose.** In `ChainStore.get`, when a lake download lands but `_covers` rejects it, remember the rejected frame for that `(underlying, as_of)` (`_lake_rejected_frames`, in-memory, per store). In `put()`, if a rejected frame exists for the key: merge rows — union keyed by `symbol` (contract), new build wins on duplicates; provenance = (`max(universe_dte)`, `min(strike_gte)`, `max(strike_lte)`, same `model` — if models differ, no merge); write the merged parquet locally (atomic), then `_mirror_to_lake` as today (now a superset → uploaded with the captured generation).
- **Gap rule:** if the two strike windows do not overlap (`new.strike_gte > old.strike_lte` or vice versa), skip the merge, upload nothing, log `chain_lake_merge_gap` with both windows. Never claim coverage the file does not contain.
- **Counters:** `lake_merged`, `lake_merge_gaps` in `summary()` and the run summary.
- **Empty-chain sentinel rows** are dropped from the union if the other side has real rows; kept if both are empty.
- Local-only runs (no lake) are unaffected: the rejected-frame path exists only when a download happened.

## Behavior contract
- A rejected-then-rebuilt day with overlapping windows results in ONE lake object whose rows = union and whose provenance = union of windows; a later request within either window is a hit.
- Non-overlapping windows: lake object unchanged; logged.
- No-lake behavior byte-identical to main.

## Tests
1. Old window [90,110], new [100,130], overlapping → merged rows (dedup by symbol, new wins), provenance [90,130], uploaded, `lake_merged == 1`.
2. Old [90,100], new [120,130] → no merge, no upload, `lake_merge_gaps == 1`, log event.
3. Model mismatch → no merge (existing skip path).
4. Merged file passes `_covers` for both the old and the new request; `get` after merge is a local hit.
5. Sentinel handling (empty old + real new → real rows only).
6. Seed tool unaffected.
Mutation: drop the union (keep new only) → test 4's old-request `_covers` fails.

- **Deviations from the plan (all additive, none contradicting a stated decision):** (1) a merge is also refused when the two files were built against **different underlying closes** — the FC entry's "same session close" made explicit in code, and necessary because `get` checks `_covers` *before* the price, so a remembered frame's price has never been compared; (2) unknown provenance on either side refuses the merge (fails closed, mirroring `_window_regression`), as does an old frame missing a quote column; (3) row order in the merged file is **new-first**, which makes a merged file byte-equivalent to the plain build for any request the plain build could answer; (4) a `chain_lake_merged` info event was added alongside the plan's `chain_lake_merge_gap`, for symmetry with `chain_lake_overwrite_skipped`; (5) the rejected frame is **popped** by the put that consumes it, so a second put in the same run cannot resurrect merged-away rows.
