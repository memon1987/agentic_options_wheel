## Context

The dashboard is world-readable (`allUsers` invoker, `ingress=all`) and writes
are guarded only by the pasted `SWEEP_SUBMIT_TOKEN`. D3 (operator-signed):
IAP + Google SSO over the whole dashboard; invited accounts read-only; an
OPERATORS allowlist gets the writes; the token dies; the scheduler keeps
working; FC-094 closes.

**Round-1 verdicts (2026-09-02, both REQUEST_CHANGES) — the two blockers:**
(1) IAP signs assertions with **ES256**, and google-auth's ES256 verifier
silently binds `None` without the `cryptography` package (extras-only dep;
nothing fails until the operator is locked out at cutover); (2) **the
scheduler cannot pass IAP under the rev-1 grant** — Google-managed OAuth
clients (the `--iap` default) block programmatic OIDC outright, and Cloud
Scheduler cannot emit the self-signed JWTs that would work. Doc-verified
facts now pinned: direct Cloud Run IAP is GA (`--iap`); principal admission =
`roles/iap.httpsResourceAccessor` via `gcloud iap web add-iam-policy-binding
--resource-type=cloud-run`; the IAP service agent
(`service-799970961417@gcp-sa-iap.iam.gserviceaccount.com`) must be minted
and granted `run.invoker` (the gcloud flow does NOT auto-grant; console
does); assertion audience =
`/projects/799970961417/locations/us-central1/services/options-wheel-dashboard`
(leading slash, project NUMBER); keys at
`https://www.gstatic.com/iap/verify/public_key`; issuer
`https://cloud.google.com/iap`; a consent brand exists
(`orgInternalOnly: true`); the IAP OAuth Admin APIs are past their 2026-03
shutdown, so client creation is console-only. The one machine caller is
`drawdown-pause-alert-daily` (OIDC, compute SA, audience = the run.app URL
today). The IAP blast radius is exactly: browsers + that one scheduler job.

## The custom-OAuth-client decision (resolves the scheduler blocker, three ways)

The operator session creates ONE **custom OAuth client** (console-only) and
allowlists it for programmatic access (`gcloud iap settings` →
`access_settings.oauth_settings.programmaticClients`). This single artifact:
1. **Fixes the scheduler**: the job's OIDC audience changes to the CLIENT ID
   (`gcloud scheduler jobs update http drawdown-pause-alert-daily
   --oidc-token-audience=<CLIENT_ID>`), and the compute SA gets
   `iap.httpsResourceAccessor` — the documented programmatic path.
2. **Unlocks external invitees**: the Google-managed default is org-internal
   only; gmail viewers need the custom client + External consent.
3. **Becomes the post-token programmatic write recipe**: pins/sims-run are
   curl-only surfaces today whose sole credential dies with the token — the
   documented replacement is an IAP-admitted service account minting OIDC
   for the client-ID audience (`gcloud auth print-identity-token
   --impersonate-service-account=… --audiences=<CLIENT_ID> --include-email`), verified in
   the session and written into `docs/CLAUDE.md`'s recipes. (`--include-email` is REQUIRED: an impersonated identity token carries no `email` claim by default and IAP rejects it — confirmation-pass fix, applies to every appearance of the recipe incl. the docs.)
Rejected alternative (on the record): moving `pause-alert-check` off the
dashboard surface — deletes the scheduler problem but not the invitee or
programmatic-write problems, and costs real code motion.

## Goals

1. Every dashboard request authenticates via IAP; anonymous access dies
   (including the artifact endpoint — the FC-094 exposure).
2. OPERATORS (env allowlist) may write; every other authenticated identity
   is read-only with a clear 403.
3. Token retired via a safe two-step cutover (no open-writes window, no
   operator lockout).
4. The scheduler works before, during, and after — force-verified in the
   session, never left to the 17:45 run.
5. FC-094 closes.

## Non-goals

- No sims-only viewer gate (signed assumption: viewers see everything).
- No changes to bot / CC / sim services; the dashboard's OUTBOUND OIDC calls
  (`routers/live.py`, the sim proxy) are untouched by inbound IAP.
- No frontend redesign beyond: token UI removal + the minimum session-expiry
  error state (below).

## Two PRs + the operator session

**PR-1 — the roles layer (deployable BEFORE the flip; byte-identical until it):**
- `dashboard/backend/services/auth.py` (new): verifies
  `x-goog-iap-jwt-assertion` — ES256 signature against the IAP public keys,
  audience (env `IAP_AUDIENCE`, the exact string above), issuer, expiry —
  via `google.oauth2.id_token.verify_token(..., certs_url=...)`. NEVER the
  plain `X-Goog-Authenticated-User-Email` header. The verifier is
  **injectable** (unit tests monkeypatch it — a real `verify_token` fetches
  keys over the network, which the conftest ambient-env discipline forbids);
  ONE integration test round-trips a REAL ES256 JWT with a generated test
  key AND asserts `google.auth.crypt.es256 is not None` (the silent-None
  regression).
- **Chain semantics, pinned per route class:**
  - Write routes (`POST /sweeps`, `POST /sims/run`, `POST /sims/pins`,
    `DELETE /sims/pins/{id}`): assertion PRESENT+VALID → OPERATORS check
    (viewer → 403 naming the OPERATORS mechanism; token ignored — no
    fallback for valid-but-non-operator identities, else a leaked token
    defeats the migration); assertion PRESENT+INVALID → **401** with log
    event `iap_assertion_invalid` (a forged pre-flip header or a broken
    audience must be loud, never routed through the token path); assertion
    ABSENT → the existing token gate, unchanged.
  - `POST /bot-health/pause-alert-check`: **EXEMPT from the OPERATORS
    chain** — IAP admission of the SA is its auth (a uniform gate would 403
    the scheduler daily: the FC-030 silence class). Test pins that a valid
    non-operator assertion reaches it.
  - `POST /api/errors` (the frontend error sink — missed in rev 1):
    **ungated behind IAP, deliberately** (viewers' browsers post it; IAP
    already kills today's anonymous log-injection exposure). Stated, tested.
- **OPERATORS hygiene**: SPACE-separated emails (commas break
  `--set-env-vars` the day a second operator is invited), casefold+strip
  both sides, the JWT `email` claim (bare — the `accounts.google.com:`
  prefix belongs to the plain header and must not appear in examples).
  EMPTY/unset OPERATORS ⇒ writes 403 with "OPERATORS unset/empty on this
  revision" (never "you are a viewer"); unset/blank `IAP_AUDIENCE` ⇒ the
  assertion branch fails closed (every assertion treated invalid, distinct
  log event). Recovery path named in the docs: `gcloud run services update
  --update-env-vars OPERATORS=…` — a revision without a build, minutes.
- Deps: `google-auth` AND `cryptography` pinned in
  `dashboard/backend/requirements.txt`; `cryptography` added to the root
  `requirements.txt` (the ES256 round-trip test must run in CI). CI-venv
  rebuilt from the changed requirements (standing rule). NOTE: the root
  requirements change moves ENGINE IDENTITY — every cached sweep key misses
  once post-merge (the accepted one-time invalidation, as in prior phases).
- Env `IAP_AUDIENCE` + `OPERATORS` in the dashboard deploy flags (fixture
  re-freeze, `_deviations`). The operator's email thereby lands in the public repo's cloudbuild/fixture — already public in commits/docs; acknowledged here where the builder reads, not only in the disposition ledger.
- Delete the stale `dashboard/cloudbuild.yaml` (unused; carries
  `--allow-unauthenticated` and a wrong project — a footgun during exactly
  this work).
- Tests: JWT matrix (valid/expired/wrong-audience/garbage/absent) ×
  chain outcome per route class; the PR-1 no-op probe (no assertion ⇒
  byte-identical current behaviour); guards per `_HAS_FASTAPI`/
  `_HAS_TESTCLIENT` discipline.

**Operator console session (exact commands in the PR body; ORDER is the
lockout guard):**
1. Enable `iap.googleapis.com`; mint the IAP service agent
   (`gcloud beta services identity create --service=iap.googleapis.com`);
   grant it `roles/run.invoker` on the dashboard — BEFORE anything else
   (the gcloud flow does not auto-grant; skipping this then removing
   `allUsers` = full outage, operator included).
2. Console: create the custom OAuth client (Credentials page / IAP
   "Auto Generate"); allowlist it via `gcloud iap settings`
   (`programmaticClients`).
3. `gcloud run services update options-wheel-dashboard --iap` (attach the
   custom client per the console flow).
4. Accessor grants (`gcloud iap web add-iam-policy-binding
   --resource-type=cloud-run --service=options-wheel-dashboard`):
   the operator, invitees, and `799970961417-compute@…`.
5. Update the scheduler: `--oidc-token-audience=<CLIENT_ID>`.
6. Verify: anonymous → sign-in; invitee reads, 403s on a write with the
   friendly message; operator writes tokenlessly; **force-run the
   scheduler** (`gcloud scheduler jobs run drawdown-pause-alert-daily`) and
   confirm success; the programmatic recipe (impersonated SA id-token)
   submits a pin; the artifact endpoint anonymous → sign-in.
7. Only after 6: remove `allUsers` from run.invoker.

## Design decisions (made — do not relitigate in the build)

  scheduler's endpoint.

  non-operators; OPERATORS as space-separated env.

  record.

  delete ordering.
- Viewers see everything (signed assumption).
