## Context

The dashboard is world-readable (`allUsers` invoker, `ingress=all`) and writes
are guarded only by the pasted `SWEEP_SUBMIT_TOKEN`. D3 (operator-signed):
IAP + Google SSO over the whole dashboard; invited accounts read-only; an
OPERATORS allowlist gets the writes; the token dies; the scheduler keeps

**Round-1 verdicts (2026-09-02, both REQUEST_CHANGES) — the two blockers:**
(1) IAP signs assertions with **ES256**, and google-auth's ES256 verifier
silently binds `None` without the `cryptography` package (extras-only dep;
nothing fails until the operator is locked out at cutover); (2) **the
scheduler cannot pass IAP under the rev-1 grant** — Google-managed OAuth
clients (the `--iap` default) block programmatic OIDC outright, and Cloud
Scheduler cannot emit the self-signed JWTs that would work. Doc-verified
facts now pinned: direct Cloud Run IAP is GA (`--iap`); principal admission =
`roles/iap.httpsResourceAccessor` via `gcloud iap web add-iam-policy-binding
--resource-type=cloud-run`; the IAP service agent
(`service-799970961417@gcp-sa-iap.iam.gserviceaccount.com`) must be minted
and granted `run.invoker` (the gcloud flow does NOT auto-grant; console
does); assertion audience =
`/projects/799970961417/locations/us-central1/services/options-wheel-dashboard`
(leading slash, project NUMBER); keys at
`https://www.gstatic.com/iap/verify/public_key`; issuer
`https://cloud.google.com/iap`; a consent brand exists
(`orgInternalOnly: true`); the IAP OAuth Admin APIs are past their 2026-03
shutdown, so client creation is console-only. The one machine caller is
`drawdown-pause-alert-daily` (OIDC, compute SA, audience = the run.app URL
today). The IAP blast radius is exactly: browsers + that one scheduler job.

## The custom-OAuth-client decision (resolves the scheduler blocker, three ways)

The operator session creates ONE **custom OAuth client** (console-only) and
allowlists it for programmatic access (`gcloud iap settings` →
`access_settings.oauth_settings.programmaticClients`). This single artifact:
1. **Fixes the scheduler**: the job's OIDC audience changes to the CLIENT ID
   (`gcloud scheduler jobs update http drawdown-pause-alert-daily
   --oidc-token-audience=<CLIENT_ID>`), and the compute SA gets
   `iap.httpsResourceAccessor` — the documented programmatic path.
2. **Unlocks external invitees**: the Google-managed default is org-internal
   only; gmail viewers need the custom client + External consent.
3. **Becomes the post-token programmatic write recipe**: pins/sims-run are
   curl-only surfaces today whose sole credential dies with the token — the
   documented replacement is an IAP-admitted service account minting OIDC
   for the client-ID audience (`gcloud auth print-identity-token
   --impersonate-service-account=… --audiences=<CLIENT_ID> --include-email`), verified in
   the session and written into `docs/CLAUDE.md`'s recipes. (`--include-email` is REQUIRED: an impersonated identity token carries no `email` claim by default and IAP rejects it — confirmation-pass fix, applies to every appearance of the recipe incl. the docs.)
Rejected alternative (on the record): moving `pause-alert-check` off the
dashboard surface — deletes the scheduler problem but not the invitee or
programmatic-write problems, and costs real code motion.

## Goals

1. Every dashboard request authenticates via IAP; anonymous access dies
   (including the artifact endpoint — the FC-094 exposure).
2. OPERATORS (env allowlist) may write; every other authenticated identity
   is read-only with a clear 403.
3. Token retired via a safe two-step cutover (no open-writes window, no
   operator lockout).
4. The scheduler works before, during, and after — force-verified in the
   session, never left to the 17:45 run.
   Session note: treat pre-flip `iap_assertion_invalid` volume as UNTRUSTED (the origin is world-reachable until the flip; strangers can generate the event). A blank/whitespace assertion header is treated as ABSENT by design (IAP never stamps an empty header; an attacker gains nothing pre-flip).
5. FC-094 closes.

## Non-goals

- No sims-only viewer gate (signed assumption: viewers see everything).
- No changes to bot / CC / sim services; the dashboard's OUTBOUND OIDC calls
  (`routers/live.py`, the sim proxy) are untouched by inbound IAP.
- No frontend redesign beyond: token UI removal + the minimum session-expiry
  error state (below).
