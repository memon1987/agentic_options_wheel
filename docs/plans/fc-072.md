# Plan: FC-072 — Call-side limit pricing: stop donating 5% of mid on every covered-call write

**FC entry:** `docs/FUTURE_CONSIDERATIONS.md` FC-072
**Plan file:** `docs/plans/fc-072.md`
**Scope:** shared (`CallSeller.execute_call_sale` serves both the wheel and the covered-call service)
**Status:** Published — build-ready
**Size:** S (one pricing expression + one config key per profile + tests); money path → two adversarial reviews
**Author:** Fable (plan), for Opus (build)
**Last updated:** 2026-08-28

## Context

`CallSeller.execute_call_sale` prices every sell-to-open at `round(premium * 0.95, 2)`
(`src/strategy/call_seller.py:159`) — 5% below mid, unconditionally. `PutSeller` prices at
`round(premium + spread * 0.10, 2)` when bid/ask are usable (`src/strategy/put_seller.py:236-242`),
falling back to `premium * 0.95` only when they are not. The Symmetry Principle violation was
filed 2026-08-01; this plan quantifies it before changing it.

**Measured 2026-08-28:**

| Source | Finding |
|---|---|
| `options_wheel.trades` (journal, 74 call / 118 put sell rows) | call `limit` sits **5.0% below mid** on average; put `limit` sits **1.0% above mid** |
| `trades_from_activities` (138 call fills since 2025-10) | $44,670 call premium collected; pricing at mid would have been up to **~$2,350** more (ceiling — assumes every order still fills) |
| Alpaca closed orders (last 500, since 2026-02-25) | **calls: 104 filled / 9 expired / 6 canceled → 87% fill**; **puts: 119 filled / 43 expired → 73% fill** |

The last row is the one that matters. The put side — priced *above* mid — fills 14 points less
often than the call side priced *below* mid. Porting the put formula verbatim would likely trade
~5% more per fill for materially fewer fills, and an unfilled DAY order costs a full cycle of
theta (the next `/run` re-sells, an hour later at best, often the next day). The naive "port
the put formula" is therefore **not** the design; a measured step is.

## Design decisions (made)

- **Price calls at `mid + call_limit_spread_fraction × spread`, default `0.0`** — i.e. **at mid**,
  when bid and ask are both usable (`bid > 0`, `ask > bid`). Rationale: recovers the entire 5%
  discount (the whole $2.3k ceiling) while pricing no more aggressively than the market's own
  midpoint; the put side's +10%-of-spread bias is left as a **second, separately-measured step**
  (flip the knob after two weeks of fill data, no code change).
- **Fallback unchanged:** if bid/ask are unusable, `premium * 0.95` exactly as today (and as the
  put side does). Do not invent a third path.
- **Spread sanity cap:** if `spread / mid > 0.5` (a stale or crossed quote), use the fallback.
  The put side has no such cap; add it there too in this PR — *stated* asymmetry otherwise
  (Symmetry Principle: a fix on one leg is applied to both unless justified).
- **One new config key per profile**, `strategy.call_limit_spread_fraction` in
  `config/settings.yaml` **and** `config/covered_call.yaml` (both default `0.0`), read through
  `Config` like `call_target_dte` is. Consumer is `execute_call_sale`; name it in the census
  note (`docs/plans/fc-069.md` appendix — one line). A key without a consumer is a defect.
- **Log the inputs on the executing event** — `bid`, `ask`, `spread`, `limit_price`,
  `spread_fraction` on `call_sale_executing`, exactly the fields the put side already emits —
  so fill-rate vs pricing can be measured from logs and BigQuery without a second change.
- **No change to `/monitor` close pricing** (`ask * 0.95` on buy-to-close) — out of scope; FC-009
  territory.
- **Rounding:** `round(..., 2)` as today. Options tick at $0.01 for premiums < $3 and $0.05
  above on many chains — Alpaca rejects off-tick limits. **Verify** in the build: check
  `AlpacaClient.place_option_order` / existing tests for tick handling; if none, round the
  new limit to the $0.05 tick when `mid >= 3.00` (calls average $3.24 — this is the common
  case, and the put side at $1.44 has been hiding this because it rarely crosses $3).

## Files to touch

- `src/strategy/call_seller.py` `execute_call_sale` (`:155-166`): pricing block per above;
  read `bid`/`ask` from the opportunity dict (scanner emits them — confirm the keys against
  `options_scanner.py`'s call opportunity construction; if absent, the fallback path fires

- `src/strategy/put_seller.py` `:236-242`: add the spread sanity cap only. Formula unchanged.
- `src/utils/config.py`: property `call_limit_spread_fraction` (float, default 0.0, validated
  `0.0 ≤ x ≤ 0.5`).
- `config/settings.yaml`, `config/covered_call.yaml`: the key + a one-line comment naming the
  consumer.
- `docs/gates.md` is not affected (not a gate). `docs/CLAUDE.md` §Strategy Configuration: one
  bullet.

## Behavior contract

- Usable quote → limit = `round(mid + f × (ask − bid), 2)` with `f` from config (0.0 today).
- Unusable quote (missing, `bid <= 0`, `ask <= bid`, or `spread/mid > 0.5`) → `round(mid × 0.95, 2)`.
- Order type, TIF (DAY), qty, floor checks, event names, return shape: unchanged.
- Put side: only the sanity cap is new; a normal quote prices identically to today.
- Must NOT change: the execute-time cost-basis floor, contracts sizing, the wrong-seller
  rejection, anything in `/monitor`.

## Tests (`tests/test_call_seller.py`, extend; `tests/test_put_seller.py`, extend)

1. Usable quote, `f=0.0` → limit == mid (to the cent). *(Core regression: the 5% discount
   returning.)*
2. Usable quote, `f=0.10` via config → limit == mid + 10% of spread. *(Knob consumed.)*
3. Missing bid/ask → `mid × 0.95`. *(Fallback preserved.)*
4. Crossed quote (`ask <= bid`) and stale quote (`spread/mid > 0.5`) → fallback. *(Cap.)*
5. `call_sale_executing` event carries `bid`, `ask`, `spread`, `limit_price`, `spread_fraction`.
6. Put side: normal quote → identical limit to pre-change (pin with a fixture value); stale
   quote → fallback.
7. Config: default 0.0 when the key is absent; `0.6` rejected by validation.
8. If tick rounding is added: `mid=3.24, f=0` → `3.25` on a $0.05 chain — **only if** the build
   confirms Alpaca rejects `3.24`; otherwise omit and record why in §Execution.

Mutation checks: restore `premium * 0.95` on the usable-quote path → tests 1, 2 fail; drop the
cap → test 4 fails.

## Rollout

1. Merge (money path — both reviews must APPROVE; one reviewer should be a trader persona
   who will argue about the fill-rate trade-off; that argument is the point of the review).
2. Watch the first covered-call write on each service: `call_sale_executing` shows
   `limit_price == mid`; confirm the fill in `trades_from_activities`.
3. **Two weeks later** (operator to-do): compute call fill rate from Alpaca closed orders
   (script in §Execution) against the **87% baseline**. If ≥ 80%, consider flipping
   `call_limit_spread_fraction` to `0.10` on one profile; if it fell below 75%, revert the
   knob to a negative fraction is **not** allowed by validation — instead reopen this FC.
4. §Execution + FC entry.
