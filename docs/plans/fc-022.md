## Context

Three small UX improvements surfaced during AMD-trade investigation:

1. **Trade Log doesn't pinpoint contracts.** While diagnosing the 4/9 AMD covered call's −$915 line, the user had to bounce between the dashboard and Alpaca's web UI to find the contract. The Trade Log shows event date, type, strike, and qty — but not the OCC symbol (e.g. `AMD260417C00245000`), the option's expiration date, or any link out to Alpaca where the order detail lives.
2. **Date display is ambiguous.** Format helpers in [utils/format.ts](dashboard/frontend/src/utils/format.ts) use browser-default locale and timezone, which means dates rendered for users in a different TZ shift around. All trading is anchored to ET (NYSE hours). Some places display ET, some don't.
3. **`/symbol` landing page is a row of pills.** Today, when no symbol is selected, the page shows a flex-wrap of symbol pills — useful for navigation but uninformative. The same data needed to make this page rich (cycles, total premium, total P&L, last activity) is already returned by `/api/v2/scorecard`.

## Goals

- Make Trade Log rows uniquely identify the underlying option contract (expiration + OCC symbol) and provide a one-click jump to Alpaca's order page.
- Standardize all date/time rendering to America/New_York across the dashboard via shared helpers.
- Replace the `/symbol` (no-symbol-selected) pill grid with a sortable summary table that shows position state, trade count, cycles, total premium, total P&L, vs-B&H, and last activity per symbol — driven by existing scorecard data.

## Non-goals

- Backend SQL rewrites beyond projecting two extra columns (`order_id`, OCC `symbol`) on the existing `acb-timeline` endpoint.
- New tests for the table — visual change with reused data; existing vitest covers format helpers (which we'll extend).
- Per-symbol sparklines, charts, or other "rich card" treatments. Plain table for now; can graduate to cards in a follow-up if the table feels cramped.
- Changing the `/overview` scorecard table — unchanged in this work.

## Proposed approach

### 1. Trade Log: contract identifiers + Alpaca deep link

**Backend** ([dashboard/backend/services/bigquery.py](dashboard/backend/services/bigquery.py)):

The `acb-timeline` endpoint reads from `fc018_acb_timeline_per_symbol`. Extend that view (or the SQL string in `bigquery.py`, depending on which is canonical) to project:
- `symbol` (OCC contract symbol, e.g. `AMD260417C00245000`) — already in `trades_from_activities` as `symbol` column
- `expiration` (DATE) — already there
- `order_id` (STRING) — already there

**Frontend types** ([types/v2.ts](dashboard/frontend/src/types/v2.ts)):
- Extend `AcbTimelineRow` with `occ_symbol: string | null`, `expiration: string | null`, `order_id: string | null`.

**TradeLog component** ([components/v2/TradeLog.tsx](dashboard/frontend/src/components/v2/TradeLog.tsx)):
- Add an **Expiry** column between Strike and Qty.
- The Strike cell renders the OCC symbol below the strike price as small mono text (e.g. `$245.00\nAMD260417C00245000`), so users can copy it to find the contract anywhere.
- Add an **Action** column on the right with a small ↗ icon; clicking opens `https://app.alpaca.markets/paper/dashboard/orders/<order_id>` in a new tab when `order_id` is present, falls back to no link otherwise.
- Verify Alpaca's paper URL pattern works; if it doesn't, fall back to `https://app.alpaca.markets/paper/dashboard/activities` (the activities page) so the user has *some* deep-link.

### 2. Date standardization to ET

**Format helpers** ([utils/format.ts](dashboard/frontend/src/utils/format.ts)):
- Add `export const ET_TZ = 'America/New_York'` constant.
- Update `fmtDate`, `fmtDateShort`, `fmtDateTime` to pass `timeZone: ET_TZ` explicitly to `Intl.DateTimeFormat`.
- Add a small note in the docstring that this is intentional.

**Audit pass:**
- `grep -r 'toLocaleDateString\|toLocaleTimeString\|toLocaleString' dashboard/frontend/src` — replace any direct calls with the helpers, or pass `ET_TZ` if a one-off format is needed.
- `grep -r '\.toISOString\|new Date(' dashboard/frontend/src` — most are fine but check for places that slice date strings from ISO and might be off by a day at TZ boundaries.

**Tests:**
- Extend `format.test.ts` with one assertion per helper that confirms ET output stable regardless of system TZ (use `Intl.DateTimeFormat`-resolved `timeZone` to verify).

### 3. By-Symbol landing page → summary table

**Page** ([pages/v2/SymbolDeepDive.tsx](dashboard/frontend/src/pages/v2/SymbolDeepDive.tsx)):
- Inside the `if (skip)` block (no underlying selected), replace the pill-grid div with a new component `<SymbolUniverseTable rows={scorecard ?? []} />`.

**New component** (`components/v2/SymbolUniverseTable.tsx`):
- Fed by `ScorecardRow[]`. No new fetch.
- Columns:
  - **Symbol** (mono, blue, link to `/symbol/<u>`)
  - **State** (Cash / Short Put / Long Stock / Long + Short Call), color-coded — same logic as scorecard's `positionState()` so it stays consistent
  - **Trades**
  - **Cycles**
  - **Total Premium** (currency)
  - **Total P&L** (currency, color-coded)
  - **vs B&H** (currency, color-coded)
  - **Last activity** (date — uses `last_trade_time`, formatted via `fmtDate`)
- Sortable by any numeric column (reuse the sort pattern from existing `SymbolScorecard`).
- Default sort: total P&L descending.
- Empty state: "No traded symbols yet."

**Reuse:** `positionState()`, `stateColor()` from [SymbolScorecard.tsx](dashboard/frontend/src/components/v2/SymbolScorecard.tsx) — extract into a small util `components/v2/positionState.ts` so both components share.

## Risks & mitigations

- **Risk:** Alpaca paper-trading URL pattern may not exist or may differ. *Mitigation:* test the URL manually before shipping; if it 404s, fall back to a generic `app.alpaca.markets/paper/dashboard/activities` link or omit the icon when `order_id` is null. Document the fallback in the row's title attribute.
- **Risk:** `expiration` for non-option events (OPTRD share rows) is null — Trade Log column shows "—" for those rows. *Mitigation:* expected behavior; the column header makes it clear.
- **Risk:** Forcing ET on locale could surprise users in other timezones who *want* their local time. *Mitigation:* low risk for this app — all trading is NYSE-anchored. Add a tiny note in the dashboard footer or section headers ("All times ET") so users know what they're looking at.
- **Risk:** Synthetic FC-021 row doesn't have a real `order_id`. *Mitigation:* the `order_id` column on the synthetic row is `synthetic-fc-021-order-c212.5-2026-01-14`; the TradeLog will detect this and not render the Alpaca link (treat as null).
