## Context

`ExecutionEngine._available_shares` (`src/strategy/execution_engine.py:152-189`) computes
`owned − committed` per underlying. `owned` matches the equity position's `symbol` to the
underlying; `committed` matches `parse_option_symbol(opt_sym)['underlying']` to the same string.
Class-share tickers break the join: Alpaca's equity symbol is `BRK.B`, its OCC root is `BRKB`.
`OCC_STRICT_RE` (`src/utils/option_symbols.py:255`) explicitly excludes dotted roots, so a short
`BRKB…C…` never matches `BRK.B` → `committed = 0` → `available = owned` → the engine writes a
second call against shares already committed. **That is a naked call**, and nothing downstream
catches it: the execute-time floor checks price, not share count.

Latent in the wheel (no dotted ticker in `stocks.symbols`). **Not latent for the covered-call
account, which has no configured universe by design** — the operator buys whatever they like
through the Alpaca UI (FC-075). One `BRK.B` purchase arms it.

The regression monitor's `risk_naked_call` check (`tools/testing/regression_monitor.py`) would
flag it an hour later. Detective, not preventive.

## Design decisions (made)

1. **One normalization primitive, used everywhere an equity symbol meets an OCC root:**
   `occ_root(equity_symbol: str) -> str` in `src/utils/option_symbols.py` — uppercase, strip
   whitespace, drop `.` and `/` and `-` (`BRK.B` → `BRKB`, `BRK/B` → `BRKB`, `BF-B` → `BFB`).
   This is the OCC convention for class shares. Do **not** loosen `OCC_STRICT_RE` — a dotted
   OCC symbol does not exist; the equity side is what needs normalizing.
2. **`_available_shares` compares `occ_root(pos['symbol']) == occ_root(underlying)`** for the
   equity leg and `parse_option_symbol(opt_sym)['underlying'] == occ_root(underlying)` for the
   option leg. `underlying` arrives from the scanner as the equity symbol (`BRK.B`); after this
   change both legs meet on the OCC root.
3. **A parser-independent pre-submit invariant in `execute_batch`'s call path:** immediately
   before `CallSeller.execute_call_sale` is invoked, recompute from the positions snapshot
   `short_call_contracts(underlying) × 100 + contracts_about_to_sell × 100 ≤ owned_shares(underlying)`
   using **only** `strict_option_type` and `occ_root` — not `parse_option_symbol` (whose
   leading-letters fallback is a heuristic). On violation: drop the opportunity with a new
   reason `naked_call_invariant`, emit `log_error_event(error_type="naked_call_invariant_blocked", …)`
   with `owned`, `committed`, `requested`, and continue the batch. This is belt to
   `_available_shares`'s braces: it fails **closed** if the two disagree.
4. **Do not touch `_option_position_matches` in the scanner** (FC-069 S3) beyond making it use
   `occ_root` for the same equality — same defect class on the put-side skip (a `BRK.B` holding
   would not block a `BRKB` put; that leg is FC-079's neighbour but the one-line fix belongs
   with this primitive). State this in the PR as the only scanner change.
5. **`regression_monitor.risk_naked_call`** gets the same `occ_root` join so the detective
   mirrors the preventive (docs/CLAUDE.md: "if you change a policy, change its mirror in the
   same PR").

## Behavior contract

- Plain tickers: byte-identical behavior (ledger, drops, events) — pin with the existing
  golden-replay test (FC-038's 07-17 blob) unchanged.
- `BRK.B` equity + short `BRKB…C…`: `committed` counts it; a second call is dropped
  `insufficient_available_shares` as it would be for `AAPL`.
- If `_available_shares` were ever wrong (bug, malformed snapshot), the invariant blocks the
  order and logs `naked_call_invariant_blocked` — never a silent naked write.
- Must NOT change: put-side sizing/collateral, the cost-basis floor, `strict_option_type`
  semantics, `OCC_STRICT_RE`.

4. Invariant: monkeypatch `_available_shares` to return `(100, 100, 0)` while the snapshot
   holds a short call on the underlying → `execute_batch` drops with `naked_call_invariant`,
   emits `naked_call_invariant_blocked`, does **not** call `execute_call_sale`, and continues
   with the next opportunity. *(Regression: the belt is removed.)*
5. Invariant does not fire on a legitimate write (owned 200, committed 100, selling 1).
6. Scanner: holding `BRK.B` blocks a `BRK.B` put scan via `option_position` when the only
   position is a `BRKB` option; via `stock_position` when it is the equity.
7. Regression monitor: `risk_naked_call` passes for `BRK.B` + `BRKB` call; fails for a `BRKB`
   call with no equity.

Mutation checks: revert `occ_root` to identity → 2, 6, 7 fail; delete the invariant → 4 fails.
