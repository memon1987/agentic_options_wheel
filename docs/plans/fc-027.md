## Context

While walking through UNH cycle 1 in the FC-023/024/026 manual reconcile, the user flagged that the column labeled "Cycle P&L" on the per-symbol Cycle Table actually displays only `total_premium` (option-side net = put kept + sum of call realized after buybacks). It does NOT include `capital_gain` (the share-side cash flow during the cycle window).

For UNH Cycle 1 the column reads **$1,218** but the true cycle P&L is $1,218 − $1,750 = **−$532**. Same class of bug as FC-023 — option-only P&L masquerading as total P&L.

The data already exists on the payload: `total_premium` and `capital_gain` are both columns from `wheel_cycles_from_activities`. Nothing changes in the view or the API; just the display.

User-requested fix: two columns — "Total Premium" (the existing data, relabeled) and "Cycle P&L" (sum of total_premium + capital_gain).

## Goals

- Rename current "Cycle P&L" column → "Total Premium" so the label matches the displayed data (option-side net premium for the cycle).
- Add a new "Cycle P&L" column displaying `total_premium + capital_gain` — true cycle outcome including share-side capital gain/loss.
- Update the table description text to reflect the new column shape.
- Color the Cycle P&L column with `pnlColor` (so true negative cycles like UNH cycle 1 render red).

## Non-goals

- **No view change.** `wheel_cycles_from_activities.total_return` already computes the dollar-weighted return including capital_gain; we just expose the dollar amount alongside.
- **No API change.** Both `total_premium` and `capital_gain` already flow through `get_wheel_cycles_for_symbol`.
- **No type change.** `CycleRow` already has both fields.
- **Not renaming `total_premium` upstream.** The field name in the SQL view stays as-is to avoid churn for other consumers (Overview scorecard, etc.).

## Proposed approach

`dashboard/frontend/src/components/v2/CycleTable.tsx`:

1. Rename the column header at line 56 from `Cycle P&L` to `Total Premium`. Update its `title` tooltip from "Net realized P&L for the cycle: put kept + sum of call realized P&L (after roll buybacks)" to "Net option premium kept across the cycle: put kept + sum of call realized P&L (after roll buybacks)".
2. Add a new `<th>` column **between** Cap Gain and Return (logical reading order: cap gain → total premium → cycle P&L → return). Header: `Cycle P&L`. Tooltip: "True cycle P&L = Total Premium + Cap Gain. Includes both option-side (premium kept after rolls) and share-side (called-away vs assigned strike) cash flow."
3. Add a new `<td>` rendering `total_premium + capital_gain` with `pnlColor` and `font-semibold` (replace the bold styling currently on Total Premium so the eye lands on the cycle-level number, not the option-only one).
4. Update the table description ("Each row = one wheel from put assignment to called-away...") to call out that Cycle P&L = Total Premium + Cap Gain.
5. New vitest: assert that for a fixture row with `total_premium=1218, capital_gain=-1750`, the rendered table shows BOTH `$1,218` (Total Premium column) AND `−$532` (Cycle P&L column).

## Risks & mitigations

- **Risk:** Existing users reading the dashboard expect "Cycle P&L" to be a stable column. Changing it to mean a different number could be jarring.
  - *Mitigation:* The new "Cycle P&L" is what users would naturally expect from that label (option + share). Old "Cycle P&L" was misnamed, not a feature. Description text on the table updated to call out the change.
- **Risk:** A NULL `capital_gain` (cycle still in flight) would NaN the addition.
  - *Mitigation:* Use `(total_premium ?? 0) + (capital_gain ?? 0)` and render `—` only if both are null. Cycles with completed share movement always have capital_gain populated post-FC-019.
- **Risk:** The Return column's calculation uses `total_premium + capital_gain` already (line 67-69) — must not double-count by accidentally re-deriving from the new Cycle P&L column.
  - *Mitigation:* The Return column logic stays unchanged.
