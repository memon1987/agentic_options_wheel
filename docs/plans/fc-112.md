## Context

The wheel's daily credit-only roller (FC-078) fires when `close / strike ≥ rolling.itm_trigger_ratio`, and the wheel ships `0.98` (`config/settings.yaml:214`). A 0.15–0.25-delta short-dated call is born at 97–99 % of its strike, so at 0.98 the roller can re-write the engine's own call the day it was sold — buy back at the ask, sell a higher strike up to 14 days further out at any delta ≤ 0.60 — bypassing every entry gate. The covered-call profile was set to `1.00` (FC-100 DD-1, operator decision D-A, 2026-09-08: true-ITM-only defence), and the wheel's 0.98 was left **pending this study**. The operator's principle (2026-09-11, FC-117) is that the two profiles run the *same underlying mechanisms* unless a measured reason says otherwise — so the burden is on 0.98, stated once here and applied in DD-1: **0.98 keeps only by passing a rule written before the data is read; every other outcome except a measured conflict resolves to 1.00.**

## Goals

1. Decide, on measured evidence and a rule written down **before** the numbers are read, whether the wheel's `rolling.itm_trigger_ratio` moves 0.98 → 1.00 (same mechanism as the covered-call profile) or stays — with the burden on 0.98.

3. Name and neutralise (or bound and label) every bias that could decide the answer by itself: the 2.46× modeled spread, the resting-leg residual, the reach, the premium floor, coverage, the thin holdout, the single window.
4. Leave a re-runnable read (`tools/diagnostics/`) and a written record (`docs/investigations/`) an operator can read the verdict from, plus a rolling weekly series of the same comparison as a fragility check.

## Design decisions, with rejected alternatives (made — do not relitigate in the build)

### DD-1 — The question, the metric and the ONE-SIDED decision rule, fixed before the data is read

**Question.** Over the wheel's live universe, trailing year with a 90-day holdout, does replacing `rolling.itm_trigger_ratio: 0.98` with `1.00` — everything else identical — change the wheel's return, and is the change large and consistent enough to justify the wheel running a *different* mechanism from the covered-call profile?

**Default.** `1.00`. The burden is on 0.98 (§Context). The rule below is the only way 0.98 keeps.

**The reads.** Three paired contrasts, each `Δann_s = annualized_return(t100-arm) − annualized_return(base-arm)` per symbol `s`, FIT window (275 days = 365 − 90; the window that measures — 7 symbols vs the holdout's 3), on symbols where **both** cells of that read are `measured` (`M` = their count):

| read | base arm | t100 arm | pin | what it removes |
|---|---|---|---|---|
| `limit` | `base` (implicit) | `t100` | decision | — (the FC-116 default fill rule) |
| `haircut` | `base_haircut` | `t100_haircut` | decision | the other end of the spread bracket (DD-3) |
| `noimm` | `base_noimm` | `t100_noimm` | control | the imminence-mode resting residual (DD-3) |

Summary statistics per read: `N+ / N− / N0`, `median(Δann)`, and the empirical `σ_Δ` (sample s.d. of `Δann` across the `M` symbols — printed so the reader can place the read on the null-rate table below).

**Constants (PR-2, committed before any `t100` cell is replayed; the verdict block prints them and the commit SHA):**

```python
TIE_BREAK = "move"        # default outcome: 1.00 (D-1). Not a CLI flag.
MIN_EFFECT_PP = 0.5       # pp of annualised return on $100,000 = $500/yr ≈ two rolls' credit on these rows
MIN_SIGN_COUNT = {7: 6, 6: 5}   # N- required, by M. M < 6 -> VOID(insufficient_measured)
```

**KEEP rule (0.98 keeps) — all of:**

1. In **every** read (`limit`, `haircut`, `noimm`): `N− ≥ MIN_SIGN_COUNT[M]` AND `median(Δann) ≤ −MIN_EFFECT_PP`.
2. **Located in the option leg:** the same two conditions hold when recomputed on `Δopt_s = (option_pnl(t100) − option_pnl(base)) × (365 / 275) / starting_cash` in the `limit` read — the option leg alone would pass. (`stock_pnl_realized` / `stock_pnl_unrealized` are reported per arm; a "KEEP" carried by the stock legs is a call-strike/assignment-timing effect, which is the *roller's own claim* and must show up in `option_pnl` if it is real.)
3. The holdout does not refute: with `comparable ≥ 4` (report's own `sign_agreement`), sign agreement ≥ 50 %; with `comparable < 4` the holdout is declared *uninformative*, stated, and does not block. Today it is 3 (AAPL, IWM, NVDA); AMZN and GOOGL rolled 7 times each in the holdout and are `insufficient` — said in the record either way.
4. The out-of-sample read (DD-10), where it exists, does not refute: its `median(Δann)` is not `≥ +MIN_EFFECT_PP`.

**Verdicts:**

| verdict | condition | resolves to |
|---|---|---|
| **KEEP** | the KEEP rule passes in full | 0.98 stays; FC-078 amendment records the measured reason |
| **MOVE** | the mirror image passes in every read (`N+ ≥ MIN_SIGN_COUNT[M]`, `median ≥ +MIN_EFFECT_PP`) | 1.00, with evidence |
| **MIXED-NULL** | no read crosses either threshold; no sign conflict between reads | **1.00** (the default; "no measurable difference" is not a reason to differ) |
| **MIXED-CONFLICT** | any of: one read passes KEEP (or MOVE) and another read crosses the *opposite* threshold; the holdout refutes at `comparable ≥ 4`; the OOS read refutes; the primary `limit` sign of `median(Δann)` flips on any of the four monitor Saturdays | **0.98 stays (status quo)** + operator review with the data. The plan does not resolve a conflict by rule. |
| **VOID(reason)** | any structural check fails (below) or `M < 6` | file it; do not read further |

**Null base rate of the KEEP rule** (computed 2026-09-12, 200k draws per cell; `Δ_s` i.i.d. `N(0, σ²)` or with a common factor `Δ_s = σ(√ρ·Z + √(1−ρ)·ε_s)`, ρ = 0.5; the reviewer's construction):

| σ_Δ (pp) | i.i.d.: sign only | i.i.d.: sign AND median ≤ −0.5 | ρ = 0.5: sign only | ρ = 0.5: sign AND median ≤ −0.5 |
|---|---|---|---|---|
| exact binomial, M = 7 | **6.25 %** (8/128) | — | — | — |
| 0.5 | 6.2 % | 0.6 % | 25.0 % | 9.4 % |
| 1.0 | 6.3 % | 3.8 % | 25.1 % | 20.5 % |
| 2.0 | 6.3 % | 5.7 % | 25.0 % | 24.2 % |
| ≥ 4.0 | 6.3 % | 6.2 % | 25.0 % | 24.9 % |

For M = 6 the sign-only binomial is 7/64 = 10.9 %. Reading: the sign count alone is a 6 % test on independent symbols and a **25 % test** if the seven symbols share half their variance (one market, one year — they do); the median threshold is what pulls the rate down, and it only bites when `σ_Δ ≲ 1 pp`. The three reads are the same trades re-priced, so requiring all three buys essentially no multiplicity protection — the joint rate is the single-read rate. The tool prints `σ_Δ` and the matching row so the record states the base rate of the read it actually made. This is why the rule is one-sided with the default on the principle: at these sample sizes the study can *refuse* a large, consistent, option-leg effect; it cannot *find* a small one.

**Structural validity checks (VOID, not MIXED):** every `t100*` row has `otm_roll_outs == 0` (empty by construction at 1.00); every row's `roll_fill_mode` equals its arm's declared mode; `rolls_executed == itm_rolls + otm_roll_outs`; the `t100` arm differs from `base` on at least one roll-bearing row (placebo gate, FC-096-a); `engine_version` and `engine_identity` are uniform across every row of a read; every pin's `base` cell equals the standing wheel item's `base` cell for that symbol (`annualized_return`, `rolls_executed`, `option_pnl` byte-equal — the pin window is the standing window, DD-4); `M ≥ 6`.

**Reported but non-deciding (must be in the record):** the same contrast on `total_return`, `assignment_rate`, `cycles_completed`, `calls_sold`, `max_drawdown`; per arm `option_pnl`, `stock_pnl_realized`, `stock_pnl_unrealized`; the roll economics per arm — `rolls_executed`, `itm_rolls`, `otm_roll_outs`, `roll_net_credit` split, `failed_roll_btc_debit`, `roll_legs_resting / (resting + marketable)` **by roll kind** (from the artifacts, as §Context), `roll_skips` by reason; the `noroll` control's Δ vs base; the `t099` dose-response arm's Δ (one-shot only, DD-7); a secondary holdout line — `total_return` sign agreement on **all non-errored** holdout cells (AMZN/GOOGL included), non-deciding; **the paired-event table** (DD-6): each day on which `base` executed an `otm_roll_out` and `t100` recorded `not_itm_enough` for the same underlying — the base roll's `net_credit`, `old_strike → new_strike`, and the terminal outcome of the *un-rolled* call on the `t100` side (expired / assigned / closed, from that arm's ledger). That table is what the verdict *means* in trades.

*Rejected:* a symmetric rule with a free tie-break (rev 1; the tie-break chosen after reading is not pre-registered); deciding on `roll_net_credit` (1.00 rolls less by construction); the holdout sign-agreement alone (n = 3); a pooled portfolio number (the sweep's own guardrail); `annualized_return_on_collateral` (same ranking on this sizer); re-applying the rule to 4-week medians (four 51/52-overlapping windows are one read, not four — DD-4).

### DD-3 — The spread bias is bracketed; the resting residual is a THIRD read, not an unknown sign

The modeled half-spread is 2.46× the real RTH spread (`BACKTEST_ENGINE.md:125`). Under `roll_fill_mode: limit` a completed roll with two **marketable** legs pays the full modeled spread twice; under `haircut`, `0.5·hs` per roll; at the REAL spread about `0.81·hs` — inside the bracket, nearer the haircut end. Every trigger arm runs under both modes; a KEEP that holds at one end and not the other is MIXED-CONFLICT (DD-1).

**Correction to rev 1: the bracket holds only for marketable legs.** A leg the roller prices in imminence mode (`extrinsic ≤ rolling.imminence_extrinsic_threshold`, default $0.20, `call_roller.py:343`) is placed at `round(mid ± 0.05, 2)` (`engine/alpaca_adapter.py:428-429`) and, resting inside the modeled spread, is *assumed touched within the leg's 120 s window* and filled at its limit (`:434-436`; residual `hs − 0.05` per share, `engine/broker.py:44-48`). Such a roll costs **$0.10 per share per roll** — below **both** bracket ends whenever `hs > $0.20` (limit end `2·hs`, haircut end `0.5·hs`). Live, a resting limit that is not touched is `btc_timeout_canceled`: no roll at all. So the resting residual is **not of unknown sign — it is always favourable to the roller**, and it is outside the bracket, not inside it. Rev 1's "either sign" is withdrawn.

Handling — the no-imminence sensitivity: arms `base_noimm` and `t100_noimm` carry `rolling.imminence_extrinsic_threshold: 0` (allowlisted, `overrides.py:173`; `Config` requires `≥ 0`, `config.py:353-357`; the roller's test is `<=`, so it still fires at exactly-zero extrinsic — a deep-ITM dying call, rare and both arms), which prices every roll leg at the far quote. The KEEP rule must hold in that read too. **Pre-computed direction, from the 09-11 base arm (§Context):** resting legs are 36.1 % of `itm_defence` legs and **1.6 % of `otm_roll_out` legs**. The residual sits on ITM defence, which both arms execute; the roll-outs unique to 0.98 are marketable. Prediction, stated before the read: `Δann(noimm) ≈ Δann(limit)` — removing imminence pricing costs both arms about equally on their ITM defences and touches the contrast little. A `noimm` read that moves the contrast by more than `MIN_EFFECT_PP` against 0.98 would mean the extra 0.98 rolls *were* being carried by resting fills after PR-1 widened the ladder (more tenor → more imminence-mode candidates) — a finding about the model, recorded as such.

### DD-6 — Which cells feed which number, and the SQL that selects them (PR-2 builds exactly this)

Return contrasts use `measured` cells only, both arms of the read; roll economics on every non-errored cell. Selection rules, each verified against the tree 2026-09-12:

- **Latest status row per `run_id`.** `scenario_sweeps` is append-only, one row per status transition (`persist.py:503` "Insert-only, never updates"; `docs/bigquery/scenario_runs.md:44-70`): `ROW_NUMBER() OVER (PARTITION BY run_id ORDER BY written_at DESC, <STATUS_RANK case>)` = `persist.LATEST_STATUS_ORDER_BY` (mirrored `services/sweeps.py:336`), keep `rn = 1`, and **only `status = 'done'`** — after following `deduplicated_to`: a latest row with `status = 'deduplicated'` contributes the run named in `deduplicated_to` (which must itself resolve to `done`), else the read is VOID(`dedup_target_not_done`).
- **Pin rows by `pin_id`** (`scenario_sweeps.pin_id`, `persist.py:336`); standing rows by `pin_id IS NULL`. The 09-11 battery holds GOOGL twice (standing + proof pin) — a per-window aggregate that forgets this double-counts GOOGL (§Found 1).
- **Window on the SWEEP row, not the runs row.** `scenario_runs.window_end` is per split (`persist.py:426`, `cell.end`): fit cells carry `window_end = holdout_start − 1` (09-11's fit rows read `2026-06-12`). Filtering runs rows on the Saturday date silently drops every fit cell (found while verifying this rev). Select the sweep by its `window_end`, join runs on `run_id`.
- **Strategy:** `IFNULL(JSON_VALUE(spec_json, '$.strategy'), 'wheel') = 'wheel'` (`spec_json`, `persist.py:274`; an absent key means wheel — `identity.canonical_spec` omits the wheel case).
- **Arm column is `scenario_name`** (`persist.py:400`, clustering key `:553`), not `scenario`.
- **Uniformity → VOID:** `engine_version` (`persist.py:259/486`) and `engine_identity` (`:269/488`) must be single-valued across every row of a read (a pin point that straddled a deploy is not a read).
- The paired-event table (DD-1) is read from the **artifacts** of the two arms (`sim-artifacts/v1/<run_id>/<arm>__<SYM>__<split>.json.gz`, bucket `artifact_store.DEFAULT_ARTIFACT_BUCKET`; keys `roll_records[]` with `day, roll_kind, old_strike, new_strike, net_credit, itm_ratio, success, underlying`; `roll_skips`; `ledger[]` with `date, kind, symbol, price, detail.fill_rule`) — `--artifacts` opt-in, the BQ read alone still yields a verdict.

The query skeleton (the tool's SQL; also copied into `docs/bigquery/scenario_runs.md` §Useful queries):

```sql
WITH latest AS (
  SELECT * EXCEPT(rn) FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY run_id ORDER BY written_at DESC,
      CASE status WHEN 'deduplicated' THEN 2 WHEN 'done' THEN 4 WHEN 'failed' THEN 3
                  WHEN 'running' THEN 1 WHEN 'submitted' THEN 0 ELSE -1 END DESC) AS rn
    FROM `options_wheel.scenario_sweeps` WHERE submitted_at >= @since) WHERE rn = 1),
resolved AS (  -- follow deduplicated_to once; the target must be done
  SELECT l.pin_id, l.window_end, l.submitted_via,
         IFNULL(t.run_id, l.run_id) AS run_id, IFNULL(t.status, l.status) AS status,
         IFNULL(t.engine_version, l.engine_version) AS engine_version,
         IFNULL(t.engine_identity, l.engine_identity) AS engine_identity
  FROM latest l LEFT JOIN latest t ON t.run_id = l.deduplicated_to AND l.status = 'deduplicated'
  WHERE IFNULL(JSON_VALUE(l.spec_json, '$.strategy'), 'wheel') = 'wheel')
SELECT s.pin_id, s.window_end, s.engine_version, s.engine_identity,
       r.symbol, r.split, r.scenario_name, r.verdict, r.annualized_return, r.total_return,
       r.option_pnl, r.stock_pnl_realized, r.stock_pnl_unrealized,
       r.rolls_executed, r.itm_rolls, r.otm_roll_outs, r.roll_net_credit, r.itm_roll_credit,
       r.otm_roll_out_credit, r.failed_roll_btc_debit, r.roll_legs_resting, r.roll_legs_marketable,
       r.roll_skips, r.roll_fill_mode
FROM resolved s JOIN `options_wheel.scenario_runs` r USING (run_id)
WHERE s.status = 'done'  -- a pin whose deduplicated_to target is not done drops here; the VOID(dedup_target_not_done) comes from the tool's resolve_dedup (T-12c), not the query AND s.pin_id IN UNNEST(@pin_ids) AND s.window_end = @window_end
```
