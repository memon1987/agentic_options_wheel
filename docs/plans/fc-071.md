## Context

FC-065 Phase 2 (PR #76) fixed the `assignment_above_cost_basis` *flag* to `>=`, matching all
three safety gates (`market_data.py:447`, seller execute-time check, `risk_manager.validate_roll`):
an at-floor call — strike exactly equal to Alpaca `avg_entry_price` — is allowed and genuinely
profitable (both premiums kept, no capital given up; GOOGL's 370C on a 370.00 floor was the live
example). The *scoring* input was deliberately left for an operator decision (PR #76 review,
INFO finding): `_create_call_opportunity` still passes strict `strike > cost_basis_per_share`
into `_calculate_call_attractiveness_score`'s `above_cost_basis` parameter
(`src/data/options_scanner.py:426` at time of filing), so an at-floor candidate is *flagged*
at-or-above but *scored* below-basis (5 pts instead of 15 — a 10-point swing in a 0–100 score).

**Operator decision (2026-08-02): align.** Gate, flag, and score should agree that at-floor is good.

## The change

- **One predicate:** the `above_cost_basis` argument passed into
  `_calculate_call_attractiveness_score` becomes `strike >= cost_basis_per_share`
  (same comparison the flag at ~`:451` already uses; reuse the already-computed flag value
  rather than writing the comparison twice, if the code shape allows — one source of truth).
- **Nothing else.** The scoring weights themselves are FC-073's territory. The gates are
  untouched. Put-side scoring has no basis component (nothing to symmetrize).

## Behavior contract

- At-floor call candidate (`strike == floor`): `above_cost_basis` scoring input True → +15 not +5.
  Net effect: at-floor candidates rank 10 points higher, consistent with their flagged status.
- Above-floor: unchanged (was True, stays True). Below-floor: unchanged (False → +5) — and still
  **blocked** at the gates regardless of score; scoring below-floor candidates is moot in practice
  but the parameter contract is preserved.
- Must NOT change: the floor gates, the flag, `attractiveness_score` for any non-at-floor
  candidate, opportunity dict shape, blob schema.
- Edge realism: with premium-netted floors (e.g. 368.34) on $2.50 grids, exact equality is
  near measure-zero — this is consistency hygiene, not a behavior shift on today's book.
  Verified consequence is confined to future exact-equality candidates.

## Tests

1. At-floor candidate receives the 15-pt bonus (scoring-level or opportunity-level assert).

3. Existing suite green (no other assertions move — a strict-`>` fixture candidate above floor

### What was built

Single source of truth, as the plan preferred — the code shape allowed it cleanly. One
comparison is now computed once, above the scoring call:

```python
assignment_above_cost_basis = strike >= cost_basis_per_share
```

It feeds **both** the `above_cost_basis` argument of `_calculate_call_attractiveness_score`
(was `strike > cost_basis_per_share`) and the `assignment_above_cost_basis` key on the
opportunity dict (was a second, separately-written `strike >= cost_basis_per_share`). Two
predicates became one, so they cannot drift apart again. `src/data/options_scanner.py`, one
functional line; the FC-065 P2 comment block moved up with the hoisted comparison and gained
the FC-071 rationale.

**Deliberately not touched:** the `strike > cost_basis_per_share` branch at `:595` that splits
capital gain from capital loss. At exact equality both arms compute
`total_return_if_assigned == premium_income` (gain and loss are each 0), so it is already
equality-correct and lies outside FC-071's one-predicate scope. Scoring weights (FC-073),
the gates, and put-side scoring are untouched.

### Tests

Three new tests (6 cases with parametrization) in
`tests/test_options_scanner.py::TestAtFloorStrikesAreScoredTheWayTheyAreFlagged`, using the
same GOOGL 368.34-floor fixture as the FC-065 P2 flag class directly above it:

1. `test_a_strike_exactly_at_the_floor_earns_the_above_basis_bonus` — the plan's test 1.
   Re-scores the emitted opportunity from its own published components with the basis input
   forced True and False, asserts the spread is 10 points (`pytest.approx`) and that the
   opportunity carries the with-bonus score. This is a **pin, not a derivation**: if FC-073
   retunes the basis weights the assert must be updated deliberately, which is the intended
   prompt to re-confirm that at-floor still ranks with the above-basis cohort.
2. `test_an_at_floor_strike_scores_the_same_as_one_cent_above` — the boundary is no longer a
   scoring cliff: 368.34 and 368.35 now score within 1 point (residual is the OTM/return
   effect of the extra cent), not 10 apart.
3. `test_the_flag_and_the_scoring_input_are_the_same_value` — the plan's test 2, the
   boundary-semantics pin. Spies on the scoring call, asserts the recorded `above_cost_basis`
   argument **is the same value** as the emitted `assignment_above_cost_basis` flag,
   parametrized across `[360.00, 368.34, 368.35, 375.00]` (below / at / just-above / above).
   Fails on any semantic divergence (`>` vs `>=`) at the boundary. It does **not** catch a
   semantics-preserving refactor that re-derives one side from an equivalent comparison —
   the single-source shape in the scanner is what guards against that.
