## Context

Every replay to date simulates the WHEEL: `src/backtesting/` has zero profile
awareness (verified 2026-08-31 and unchanged), the runner builds its base
`Config` from `config/settings.yaml`, and the sweep spec has no strategy
dimension. FC-096 D2 (operator-signed): covered-call sims run on a **synthetic
lot** — assume 100 shares bought at the window-start price — answering "is this
symbol a good covered-call underlier", symbol-comparable, candidate-friendly;
every CC chart labels the premise; "my actual basis" is a later overlay.

Facts this plan rides on (verified in-tree 2026-09-02): `Config` requires a
top-level `strategy_id` and validates profile-specific keys
(`config/covered_call.yaml` is complete: `call_target_dte: 14`,
`call_delta_range [0.15,0.25]`, `min_call_premium 0.30`, no
`put_target_dte`, its own earnings/risk blocks); PR-2's `config_target_dte`
already reads profiles where `put_target_dte` raises; the production
call-only gate is `deploy/cloud_run_server.py:_call_only_opportunities`
(run-side) with the put scan self-gating on `strategy_id` (FC-075);
`BacktestBroker` seeds shares only via private `_add_stock` (assignment path)
— a synthetic lot needs a public deposit API that EMITS A LEDGER EVENT so
cycles, artifacts, and reconciliation all see the acquisition;
`build_cycles` opens a cycle on any first event per underlying (no put-first
assumption); `BuyAndHold` takes entry price + starting cash — the same
window-start close the lot premise uses; `effective_max_dte` (PR-2) already
takes `max(put, call)` of the base config, so CC's 14-DTE reach materialises
correctly and the 22-reach lake covers it.

## Goals

1. The sweep spec gains `strategy: "wheel" | "covered_call"` (default wheel —
   every existing spec, key, and stored row is untouched).
2. A covered-call replay: base config from `config/covered_call.yaml`, put
   side fully disabled, calls written against a synthetic lot per symbol,
   rolls/earnings-span/profit-taking behaving exactly as the CC service's
   pipeline does.
3. The premise is stamped everywhere a number surfaces: rows, artifacts,
   reports, and the sweep-key identity.
4. Runs end-to-end on all four entry points: CLI, Job, sim service, dashboard
   submit — with the allowlist/value-types mirror updated.

## Non-goals

- No "my actual basis" overlay (fast-follow per D2), no live-position reads.
- No CC-vs-wheel combined sweeps (one strategy per sweep; comparing is a
  console concern in Phase E, reading two runs).
- No change to the live CC service, its scanner, or any trading path — the
  replay REUSES the strategy code the pipeline runs; it must not fork it.
- No new lake work: CC uses the same chains (call side of the same files),
  same 22-reach.
- No battery/standing-set expansion to CC yet (that was explicitly deferred
  "wheel-only until Phase C" — flipping it on is a ONE-LINE follow-up once
  this phase's replays are trusted; PR-2 of this plan includes the flip
  behind its own tests).

## Proposed approach

### C1 — profile plumbing (PR-1)

- `run_sweep`/`evaluate_symbol` take the base `Config` as today — the CHANGE
  is upstream: `main.py` and the sim service resolve the profile from the
  spec's `strategy` (`wheel` → `config/settings.yaml`, `covered_call` →
  `config/covered_call.yaml`; `--config` still wins for the CLI's explicit
  override, and a `--config` whose `strategy_id` contradicts the spec's
  `strategy` is refused loudly).
- `base_config_hash` already keys the effective snapshot per profile —
  verify a CC run's hash differs from a wheel run's (test), so dedup can
  never cross strategies even before the spec field joins the key.
- The spec's `strategy` field joins `canonical_spec` (and therefore
  `sweep_key` and `pin_identity`) explicitly — belt on top of the config
  hash, and what makes the stored rows self-describing. Absent → "wheel"
  in canonicalisation (legacy keys unchanged — REQUIRED test: a dateless
  legacy spec's key is byte-identical pre/post this PR).

### C2 — the synthetic lot (PR-1)

- `BacktestBroker.deposit_shares(underlying, shares, cost_basis, on_date)`
  (new, public): wraps `_add_stock`, emits `LedgerEvent(kind=
  "synthetic_lot_open", cash_delta=0, detail={"premise": "synthetic_lot",
  "shares": …, "cost_basis": …})`. Zero cash delta — the lot is an
  assumption, not a purchase; equity therefore starts at
  `starting_cash + shares × entry_close`, and the report's capital base for
  return math is that total (stated in the docstring and the report).
  Alternative rejected: debiting cash for the purchase — it would couple the
  premise to `starting_cash` sizing and understate CC yield on the lot
  (the question is income on shares HELD, not on shares bought today).
- `Simulator` gains `synthetic_lots: Optional[Dict[str, int]] = None`
  (shares per symbol; the CC path passes 100 per D2). Seeding happens on the
  first decision day, at that day's underlying close (the window-start
  price per D2), BEFORE the first scan — so day 1's call scan sees covered
  shares. A symbol with no bar on day 1 seeds on its first traded day
  (logged; the alternative — refusing the symbol — punishes candidates for
  IPO-week windows).
- Cost-basis floor: the lot's `cost_basis` is the entry close, so the
  execute-time floor (FC-050/065) and the scan-side floor bind against it
  exactly as production binds against `avg_entry_price`. This makes the
  replay's "hold-uncovered-until-recovery" behaviour reachable in sims —
  a symbol that gaps down below basis writes nothing, honestly.

### C3 — call-only replay (PR-1)

- The replay mirrors production's TWO gates, not a new one: (a) the scanner's
  put scan self-gates on `config.strategy_id` (same code path the CC service
  runs — verify it needs no backtest-side special-casing; if the scanner
  reads anything request-scoped, stop and report); (b) the run-side filter
  reuses `_call_only_opportunities` MOVED to a shared module
  (`src/strategy/strategy_gates.py`) so `deploy/cloud_run_server.py` and the
  simulator import ONE implementation (the FC-060 "imported, not restated"
  rule; moving it is behaviour-neutral for the service — pinned by test).
- The roller runs (the CC service rolls; `rolling.enabled` comes from the
  CC profile). Put-side machinery must be provably inert: REQUIRED test —
  a CC replay's ledger contains zero `sell_put_open` events across a window
  where the wheel replay writes several.
- Cycles: a CC "cycle" opens with `synthetic_lot_open` and never round-trips
  to flat unless called away. `build_cycles` handles this shape already
  (open-ended cycles are returned, not dropped); the VERDICT layer
  (`_score`/fitness) must not punish the permanently-open cycle — the CC
  verdict weighs premium capture + assignment terms against B&H of the same
  lot, not round-trip completion. Concretely: `compute_fitness` gains a
  strategy-aware branch for the deployment/idle metrics (capital deployed =
  the lot, always; "days in position" is meaningless) — the exact metric
  set: annualized premium yield on lot value, call coverage ratio (days
  covered / days), called-away rate, net P&L vs B&H. Anything more is
  Phase E's charting, not engine math.
- Report/artifact honesty: rows and artifacts carry `strategy` and, for CC,
  `premise: synthetic_lot_100` (provenance block + a `SYNTHETIC_LOT_BIAS`
  footer constant in `SWEEP_BIASES`' conditional mechanism — same
  `DTE_REACH_BIAS` plumbing, emitted iff strategy == covered_call, byte-
  pinned dashboard copy included).

### C4 — the surfaces (PR-2)

- `validate_spec`: `strategy` optional enum, default "wheel"; refusals name
  the two values. `OVERRIDE_VALUE_TYPES` unchanged (overrides still target
  the profile's own keys — a CC sweep overriding `put_delta_range` is
  refused by the CC profile's validator with a reason naming the strategy;
  REQUIRED test both directions).
- Sim service + Job: profile resolution per C1; the coverage guard and
  budget math are strategy-agnostic (same lake, same bars) — test a CC spec
  end-to-end through the service fake.
- Dashboard: allowlist payload gains the `strategy` field description; the
  `/sims` page needs NO change (the spec JSON passes through; rendering
  labels are Phase E).
- Battery: the standing set adds `strategy: covered_call` base per live
  symbol (doubling the standing set to ~28 sweeps; sizing note updated —
  still inside the 4 h cap by the recorded arithmetic).
- `docs/BACKTEST_ENGINE.md` + `docs/CLAUDE.md`: the CC replay's premise,
  metric definitions, and the "one strategy per sweep" rule.

## Behaviour contract

- Every existing wheel spec: identical keys, rows, hashes (legacy-identity
  test), identical replay output (golden: one wheel sweep byte-identical
  pre/post PR-1).
- A CC replay emits zero put events; its first ledger event per symbol is
  `synthetic_lot_open` at the window-start close; equity day 1 =
  starting_cash + lot value.
- CC and wheel runs of the same symbols/window can never dedup into each
  other (key + config hash both differ).
- The premise footer appears iff strategy == covered_call, on CLI and
  dashboard alike.
- The moved run-side gate leaves the CC service's behaviour byte-identical.

## Design decisions (made — do not relitigate in the build)

- **Zero-cash-delta lot** (assumption, not purchase) with equity base
  `cash + lot` — the yield question is income on held shares.
- **100 shares fixed** (D2): symbol-comparable; sizing knobs stay out of the
  premise. A `synthetic_lot_shares` override is NOT added (a knob here would
  fragment comparability; revisit only with operator sign-off).
- **Seed at window-start close, before day 1's scan.**
- **`strategy` in the key AND profile hash** — two belts, self-describing rows.
- **The run-side gate moves to a shared module** rather than being restated.
- **One strategy per sweep**; comparison is a read-side concern.
- **CC verdict = premium yield / coverage / called-away / vs-B&H** — no
  round-trip metrics.
