## The strategy/context split (the rule everything below follows)

A spec's `strategy` selects the **strategy profile** — the `Config` the
REPLAY runs under (gates, knobs, legs). It never selects the **service
context** — dataset, buckets, credentials, provenance — which belongs to the
PROCESS. All CC measurement rows therefore land in the process's own store
(`options_wheel.scenario_*` for our CLI/Job/sim-service), self-described by
the `strategy` column. **FC-075 DD-4 exception, argued on the record:** the
dataset-isolation doctrine protects TRADING writers from cross-contamination;
scenario tables are measurement stores of hypotheses — one store with a
strategy column is the design (splitting it would orphan CC trend rows from
every reader). The four writer sites that must obey the split: `main.py`
`run_sweep_cmd` (CLI+Job), the battery's `writer_override`, and
`deploy/sim_service.py`'s writer — each keeps its process dataset while the
replay config swaps.

## Proposed approach

### C1 — spec + identity (PR-1)

- `strategy` optional enum in `main.SPEC_FIELDS` and (PR-2) `validate_spec`;
  enum/case validation lives in the VALIDATORS — engine side: `load_spec_from_env` + the `SPEC_FIELDS` check and `scenarios_from_spec` in `main.py`; dashboard side:
  `validate_spec` — never in stdlib `identity.py`.
- **Canonicalisation by OMISSION**: absent OR explicit `"wheel"` → the field
  is omitted from the canonical dict; only `"covered_call"` is written.
  (Probe-verified: writing `"wheel"` in changes every legacy key; omission is
  byte-stable. Folding explicit-wheel matters because the dashboard's
  normalised spec may stamp it.) REQUIRED test: `canonical_spec` and
  `pin_identity` byte-stability for legacy specs — asserted on the canonical
  JSON, not on stored-row dedup (any `src/**` change moves engine identity
  anyway).
- Profile resolution per entry point: CLI — `--config` **default becomes
  None**; resolution order = spec's strategy → profile file, a SUPPLIED
  `--config` is an override, and a supplied config whose `strategy_id`
  contradicts the spec's strategy is refused loudly (three ambiguous
  implementations existed; this is the pinned one). **Two consequences pinned (confirmation-pass fixes):** (a) the PROCESS context — the pre-dispatch bootstrap at `main.py:80-88` (`Config(args.config)` → analytics writer), the battery's own config, and every writer dataset — resolves to `config/settings.yaml` (wheel) whenever `--config` is absent; only the REPLAY config follows the spec's strategy. (b) `run_sweep_cmd` keys the supplied-override refusal on **`args.config is not None`** (the CLI flag), NEVER on the positionally passed `Config` object — that object is process context, and reading it as an override would refuse every battery CC standing item (the deployed Jobs pass no `--config`). Job — same path
  (`run_sweep_cmd`), profile files ship in the image. Battery — resolution
  INSIDE `run_sweep_cmd` (the battery is the fourth entry point; its CC
  standing specs must not snapshot the wheel profile); the CC standing set
  iterates the WHEEL profile's live symbols (the CC profile deliberately has
  no `stocks:`). Sim service — `get_config()` becomes a per-strategy cached
  pair (both profiles loaded lazily once per process); per request, the
  spec's strategy selects the REPLAY config for `base_config_snapshot`/
  `base_config_hash`/`engine_config_hash`/`run_sweep`, while the writer
  dataset/artifact bucket stay process-context (the split above). The
  singleton docstring's "every request sees the same effective configuration"
  is rewritten to "…the same configuration PER STRATEGY".
- `base_config_hash` per profile = the dedup belt across strategies (test:
  wheel and CC runs of identical windows never dedup into each other).

- `Simulator(synthetic_lots=...)`; seed on each symbol's first traded day at

- **Post-call-away posture — OPERATOR-GATED (D2 addendum, surfaced

  continuing overwriting program; new `synthetic_lot_open`, new cycle,

### C3 — CC math, gates, and management fidelity (PR-1)

- **Spread gate**: on model-built chains `max_spread_pct: 0.10` rejects
  every premium-floor-clearing call by construction (probe: 10/10; model
  half-spread ≥ 5% of mark for OTM). The REPLAY suspends the spread gate
  (`max_spread_pct → None`) with (a) a `MODEL_SPREAD_BIAS` line in the CC
  footer stating the suspension and why, (b) a test pinning the suspension
  to the model hardcode (mirrors the FC-097 OI suspension: it fails loudly
  the day real spreads arrive so the gate is restored deliberately). Live
  divergence stamped, not hidden.
- **Return denominators**: `compute_fitness`/`SimulationResult` gain a
  strategy-aware capital base = `starting_cash + Σ seeded lot values` —
  the lot can never read as profit (REQUIRED test: a no-trade CC window
  returns 0.0%, not +lot%). The CC path pins `starting_cash` to a small
  stated buy-back float (`CC_CASH_FLOAT = 5_000`, documented: enough for
  BTC legs; keeps equity returns ≈ lot returns instead of diluted 20×).
  NEW row field `premium_yield_on_lot` (annualized net premium ÷ the
  TIME-WEIGHTED average seeded lot value — well-formed under both call-away postures: with a single lot it equals the lot value; under re-seed, each lot contributes value × days held ÷ window days) = the CC headline; `annualized_return` remains the corrected
  equity return; the CC footer + docs state which is which, and Phase E
  labels them (recorded in the FC entry's component note).
- **B&H**: CC branch constructs `BuyAndHold(shares=lot_shares,
  starting_cash=lot_value)` — the SAME lot, not a 100k-full-invest
  benchmark. `excess_return` is then honest.
- **Verdict (CC branch, cutoffs defined)**: `insufficient` = window <
  MIN_HOLDOUT-compatible length or chain coverage below the existing
  thresholds — NEVER "no closed cycle". Measured CC verdict from:
  `premium_yield_on_lot` vs the lot B&H's dividend-inclusive return
  (excess ≥ 0 → fit-leaning), coverage-by-reason, called-away terms
  (assignment P&L vs basis). `low_activity` for CC = writable-day coverage
  below 30% EXCLUDING hold-uncovered and earnings-span days (standing down
  below basis is the strategy working; the metric must not punish it).
- **Coverage, split by recorded reason** (the tally already labels them):
  covered / hold-uncovered (below basis) / earnings-span / gate-rejected /
  post-call-away. A single ratio is forbidden in the report; the split is
  the metric. Plus **net basis reduction** (cumulative net premium ÷ lot
  basis) — the number CC programs manage to.
- **Monitor leg (CC only)**: the replay adds `/monitor`-equivalent
  DTE-banded profit-taking into the day loop, gated to
  `strategy_id == "covered_call"`, using the CC profile's bands —
  `should_close_call_early` is deterministic config math over daily marks.
  Wheel replay untouched (golden). The wheel's own 52% early-close
  divergence keeps its existing footer line; a follow-up FC will own
  wheel-side modelling. NOTE (FC-086 carries it): the live bands are
  DTE-keyed ≤7 vs CC's 14-DTE target — the replay uses the profile's bands
  as configured and the footer names the gap.
- **Roller**: inert for CC — mirroring LIVE behaviour (FC-100: the live CC
  service has no rolling config; the operator decides wire-vs-declare).
  The plan tracks FC-100: if the operator wires CC rolling, a one-line
  profile change activates it here identically.
- **`build_cycles` IS touched** (rev-1's "untouched" struck): a
  `synthetic_lot_open` branch records shares/basis exactly as
  `put_assignment` does, so the cycle stays open, `cost_basis` is real,
  `call_assignment` books stock P&L, and re-seeding (if signed) opens a
  clean next cycle. Regression: wheel ledgers contain no such event —
  golden-pinned.
- **Splits**: `UnadjustedCorporateAction` refusal stands; the CC footer
  names the momentum-name selection bias it implies (12-month windows).
- **Stale wheel-calibrated bias copy**: the dividend/early-assignment and
  premium-parity lines in `SWEEP_BIASES` get strategy-conditional review in
  PR-1 (the 14-DTE payers may fire ex-div assignment for the first time).
