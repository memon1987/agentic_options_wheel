## Context

FC-096's console (Phases B–E) is only as good as the stored data under it. Today the
chain lake reaches **7-day DTE** (`universe_dte = max_dte + 1 = 8`), covers only the
14 live symbols, and grows only when a screen or sweep happens to run cold. Three
consequences Phase A removes: `put_target_dte` is allowlist-refused (the operator
signed DTE ≤ 21, FC-096 D1a); candidates have no evaluation path (FC-060's unshipped
Layer 3b); freshness is accidental (monthly-screen side effect).

Verified mechanics this plan rides on (round-1 reviews re-verified all of them):
chains are **model-built from bars** (`ChainBuilder`, per-contract IV solved from
that contract's own daily trade bar; `model_fingerprints` on `Materialised`) — so
historical DTE-21 chains are recomputable within Alpaca's 2024-02 option-history
floor; the lake's read path masks to the requested reach (`_rows_to_quotes`), so a
DTE-7 sweep against a 22-reach file sees identical inputs; coverage-monotone
replacement (`_covers` / `_window_regression`) is the only legal cross-DTE path —
FC-091's merge refuses `dte_mismatch` and must stay that way; the runner sets
`max_dte` from base config at `scenarios/runner.py:509` and `Simulator.replay`
raises on any mismatch; the monthly screen's scheduler (`monthly-performance-review`)
proves the jobs:run pattern — **async**, so its 180 s `attemptDeadline` is correct
against multi-hour Jobs and must not be "fixed".

**Round-1 review verdicts (2026-08-31): both REQUEST_CHANGES.** The two blockers —
backfill strike-window derivation unspecified (widened files would be *rejected* by
the coverage guard and thrash-symbols would churn cold weekly, forever: the live
SPY/IWM/PFE `rejected=231 skipped=231` pattern), and zero detectability of a failed
or silently-stopped weekly Job (no alert policy watches `cloud_run_job`; a paused
scheduler is invisible — FC-081's failure shape) — plus the sequencing findings are
addressed throughout; §Review disposition maps every finding.

## Goals

- A `stocks.candidates` universe beside `stocks.symbols`, invisible to the live
  scanner.
- A weekly Cloud Run Job (`data-backfill`) keeping bars + lake current for
  live ∪ candidates at **22-reach** (one file per day at `universe_dte = 22` —
  not three files; the FC entry's "7/14/21 reaches" phrasing is corrected to this),
  weekends only, with real failure detectability.
- A one-time, resumable, operator-supervised historical widening — **gated by a
  measurement that the DTE knob moves selection at all** before the deep history
  is paid for.
- A candidate onboarding path: config PR + one Job execution, idempotent.
- DTE ≤ 21 sweepable (**PR-2, gated**), with an honest fidelity caveat in the
  sweep footer.

## Non-goals

- No standing battery / pinning (Phase B — needs the dedup re-key first).
- No sim service, CC replay, IAP, console (Phases B–E).
- No change to any trading path; the candidates key has zero production readers.
- No new BigQuery tables. Observability = structured logs + one alert policy +
  one `/regression` check.
- No change to FC-091 merge semantics (`dte_mismatch` refusal stays verbatim).

## Two PRs (sequencing is a review requirement, not a preference)

- **PR-1 — the data machinery:** backfill module + CLI + Job + scheduler recipe +
  monitoring + candidates key. Ships with the allowlist **unchanged**: no DTE>7
  request is acceptable until the data exists (round-1 HIGH: flipping the knob at
  merge re-creates the FC-095 quota exposure — a Tuesday-10:00 dashboard submit
  materialising 21-reach cold on the live key for hours, past the sweep Job's own
  timeout).
- **PR-2 — the knob:** allowlist + value rules + `OVERRIDE_VALUE_TYPES` + runner
  arm-max + sweep-footer caveat + identity regression. Opens only after rollout
  §5's two gates pass (widening verified; placebo test shows DTE arms move rows).

## Proposed approach

### A1 — candidate universe (PR-1)

`config/settings.yaml` gains `stocks.candidates: []` (seed empty; add/graduate by
config PR). Consumers, named: `main.py --command backfill` (default symbol set) and
`Config.candidate_symbols` (new accessor, `[]` when absent). Not mirrored into
`covered_call.yaml` (two-profile drift hazard; the backfill Job always runs the
wheel profile). FC-069 census appendix gets a row.

**Guard test (respecified per review):** an AST test in the
`test_no_occ_substring.py` idiom asserting (a) no `ast.Attribute` access of
`.candidate_symbols` outside `main.py` / `src/backtesting/` / `src/utils/config.py`
/ `tests/`, and (b) no subscript/`.get` of the literal `"candidates"` key on the
stocks section outside `src/utils/config.py`. (The rev-1 "no import of the
accessor" spec was vacuous — nobody imports an accessor.)

### A2 — the backfill build contract (PR-1; resolves both round-1 blockers' data half)

New module `src/backtesting/data/backfill.py`:

- `BACKFILL_MAX_DTE` is **imported from `overrides.py`** where it lives as
  `MAX_SWEEPABLE_DTE = 21` — `overrides.py` is stdlib-only and flat-copied into
  the dashboard image, so it cannot import from `backfill.py`; the dependency
  points the only direction that works, and a parity test pins the Job and the
  dashboard copy to the same number.
- **Window rule (BLOCKER fix):** for each (symbol, day), `run_backfill` first
  reads the existing lake/local object's provenance window (`universe_dte`,
  `strike_gte`, `strike_lte`) and builds at the **union**: DTE reach 22, strike
  bounds `[min(old_gte, new_gte), max(old_lte, new_lte)]`, passed into the
  builder via the existing anchor parameters (`chain_builder.strike_window`'s
  `cost_basis`/`low_anchor` extension points). The written file is therefore a
  strict superset on both axes and `_covers`/`_window_regression` accept the
  replacement by construction. Anchor-widened files (positions history) and
  FC-091 merge-widened files are exactly the cases this handles. **Churn test
  (required):** a lake object whose window is wider than spot±25% on one bound
  is replaced, not skipped, and a second run writes zero objects.
- **New-day window (H5 fix):** fresh days build at
  `BACKFILL_STRIKE_WINDOW_PCT = 0.40` of spot (not the 7-DTE-sized 0.25):
  at DTE 21 / IV 90% the 0.10-delta put sits near K/S ≈ 0.78 — the 0.25 window's
  documented failure mode there is *silent nearer-strike substitution*, baked
  into shared files. 0.40 restores the ~3× band-edge margin the 0.25 constant
  was designed to have at 7 DTE, expressed via back-solved anchor parameters or a new builder parameter (builder's choice; `STRIKE_WINDOW_PCT` itself is not edited). **Pre-freeze probe (required build task):**
  re-run the band-edge probe (the NVDA-style check from the chain-builder work)
  at DTE 21 across the live universe; if any symbol's band edge exceeds the 0.40
  window, widen the constant before the first widening execution and record the
  measurement in the PR.
- **Model parity (BLOCKER fix):** the builder is constructed **byte-identically
  to the sweep path's** (same defaults: `r`, no `dividend_yields`, default
  `SpreadModel`). A test asserts `ChainBuilder` fingerprints from
  `run_backfill`'s construction equal the runner's on the same inputs. Wiring
  dividend yields in would be an "improvement" that silently forks the lake into
  an invisible second model — explicitly forbidden here; if the model ever
  changes, it changes for all writers in one PR.
- **Splits:** backfill builds per-day with per-day windows (never a whole-window
  anchor span), so a split inside the trailing window cannot inflate anchors.
  A day whose bars fail the split-adjustment check logs
  `backfill_day_skipped{reason=corporate_action}` and counts in `errors` —
  skip-and-report, not raise-and-die (one symbol's split must not kill the run).
- `run_backfill(...) -> BackfillSummary` — per-symbol counters
  (`days_checked/days_written/days_replaced_wider/days_skipped/errors`), derived
  from `ChainStore`'s counter deltas (`lake_puts`/`lake_skipped`/`lake_merged`)
  taken per-day — the store exposes aggregates only; the summary must not reach
  into store internals. Per-symbol progress log lines are emitted as they
  complete (a half-done run must be reconstructable from logs alone), then the
  terminal summary. Non-zero exit if any symbol failed.

### A3 — Job, scheduler, and detectability (PR-1; resolves the ops blocker)

- `main.py --command backfill` with `--symbols`, `--history-days`
  (**default 30** — the weekly run's job is freshness, not re-verifying 400
  covered days through thousands of lake GETs; historical widening passes
  explicit `--start/--end`), `--start/--end`. Env-driven in Job mode
  (`BACKFILL_SYMBOLS`, `BACKFILL_HISTORY_DAYS`, `BACKFILL_START/END`, all
  optional). SIGTERM pattern copied from the sweep Job: handler armed before
  work, per-symbol progress logs, terminal summary in `finally`, SIG_IGN around
  the final write.
- `cloudbuild.yaml`: `deploy-backfill-job` — bot image, marker check first line,
  `waitFor` all three promotes, `--max-retries=0`, `--task-timeout=21600`, same
  secrets/env as `backtest-sweep`. **Contract-test change named:** the existing
  `ids[-1] == "deploy-sweep-job"` assertion is redesigned to a tail-set
  assertion — the final steps are exactly `{deploy-sweep-job,
  deploy-backfill-job}`, each `waitFor` the three promotes, each marker-first —
  because "last step" is no longer a single step. No pre-existing `waitFor`
  edge changes. (Measured: the sweep tail step runs 4 s; a second tail step is
  noise against ~340 s of budget headroom.)
- **Alerting (required, was absent in rev 1):**
  `deploy/monitoring/job_failure_alert_policy.json` — log-based policy on
  `resource.type="cloud_run_job"` failed executions, matching **all three** Jobs
  (`backtest-screen`, `backtest-sweep`, `data-backfill`): the review verified
  none of the 11 live policies watches Jobs at all; fixing it once here pays
  three times. Rollout step creates it with the standard recipe.
- **`/regression` `lake_freshness` check (required, was absent):** the only
  control that catches a paused/deleted scheduler (scheduler `jobs:run` is
  async — it records success when the API call returns; a failed or missing
  execution never reaches it). Reads max chain-day date across the **live**
  universe via a GCS `list_blobs` prefix scan (neither `ChainStore` nor the lake exposes an index method — confirmation-pass note); `fail` when older than
  `LAKE_FRESHNESS_MAX_DAYS = 10` (one missed Saturday + grace), `warn` on
  read errors (never `fail` on GCS hiccups — deploy_freshness's posture),
  `deploy_freshness_degraded`-style nag event on every degraded path. Runs in
  the existing `:45` weekday cadence; documented in the `/regression` table in
  `docs/CLAUDE.md`.
- Scheduler `backfill-weekly`, `0 8 * * 6`, jobs:run URI, compute-SA OAuth —
  the `monthly-performance-review` recipe **plus `--max-retry-attempts=3`**
  (the live recipe has retryCount 0: a transient API error would silently skip
  a week) and an explicit note that `attemptDeadline` stays small *because*
  jobs:run is async — do not "fix" it to 6 h.
- Known residual (accepted, documented): on a 1st-of-month Saturday the monthly
  screen (06:00) can overlap the backfill (08:00) if the screen runs long cold;
  coverage-monotone puts make the race benign except the FC-093 item-5
  `if_generation_match=None` window — FC-093 rider, not fixed here; the same shape applies when a §4 manual widening execution overlaps the 08:00 weekly run on the same symbols — same disposition.

### A4 — onboarding (PR-1)

Config PR adding the symbol to `stocks.candidates`, then one Job execution with
`BACKFILL_SYMBOLS=<sym>` (or wait for Saturday). **Required first step on the
onboarding checklist (upgraded from "caveat" per review): refresh the committed

the per-replay `earnings_symbols_without_data` set into the sweep report header
(the runner holds each `SimulationResult`; today the field surfaces only in the
single-backtest report, so a candidate sweep would say nothing). Checklist lives
in `docs/BACKTEST_ENGINE.md`; FC-086 cross-reference included: DTE-band
profit-taking in *live* config breaks under target-DTE changes — a console-driven
"move to DTE 14" recommendation must route through FC-086 first.

### A5 — the DTE knob (PR-2, gated on rollout §5)

- `overrides.py`: `MAX_SWEEPABLE_DTE = 21` (single source, stdlib-local);
  `strategy.put_target_dte` allowed with value rule `1 ≤ int ≤ MAX_SWEEPABLE_DTE`;
  `strategy.call_target_dte`'s rule becomes the same static bound. The
  `chain_reach_dte` parameter and `DEFAULT_CHAIN_REACH_DTE` are **deleted** —
  the value rule no longer depends on the caller's reach. **Three** call sites
  drop the argument: `runner.py:484`, `overrides.py:338`, and `main.py:765-769` (the pre-launch validation pass — the confirmation pass caught that a two-site list would leave a `TypeError` on every sweep launch; the dashboard's `validate_override_key(key, value)` passes no kwarg and needs no change). Refusal messages
  name the constant.
- `dashboard/backend/services/sweeps.py`: `OVERRIDE_VALUE_TYPES` gains
  `strategy.put_target_dte` (int) — **service code, not fixtures**: an
  allowlisted key absent from that table is refused by the dashboard, which
  would kill the console's flagship knob. Reason-string fixtures refresh.
- `scenarios/runner.py`: `max_dte` = the **maximum across base config and every
  arm's `put_target_dte` AND `call_target_dte` overrides** (a call-DTE-14 arm on
  a cold window must materialise at ≥ 14 or it reads "no call ever qualified").
  One variable feeds materialise and every replay, so the simulator's equality
  guard stays satisfied.
- **Footer (corrected target and wording):** the caveat lands in
  `scenarios/report.py` `SWEEP_BIASES` **and** the byte-pinned dashboard copy
  (`services/sweep_report_text.py`) **and** the fixtures — the rev-1 target
  (`reporting/report.py` only) never reaches a sweep or Phase E. Emission is
  conditional on the run's effective `max_dte > 7`, with the plumbing specified (the runner makes no report call, and the dashboard emits `SWEEP_BIASES` unconditionally today): the caveat is its own constant (`DTE_REACH_BIAS`) in both `scenarios/report.py` and the dashboard copy — the byte-parity test pins the CONSTANT, not its emission; `SweepResult` gains `effective_max_dte`, which `render_markdown`/`render_json` read to append the entry; the dashboard derives the same condition per run from the persisted spec's DTE overrides (`persist.py` already maps them) and appends it to `known_biases` for that run only.

  "extrapolation": DTE-14/21 quotes are real prints of real contracts with
  per-contract solved IV, but longer-dated contracts trade thinly, the builder
  drops any contract with no trade that day (ladder holes read as "contract
  didn't exist" and bias selection), and the spread model was measured on
  short-dated OTM puts only.
- **Identity regression (required):** the same DTE-7 spec replayed against an
  8-reach lake and a 22-reach lake produces identical rows and hashes (the
  read-path mask makes it plausible; the test makes it a contract).

## Behaviour contract

- Live scanner byte-identical; candidates key unread in production (AST test A1).
- Backfill idempotent: second run over a covered window writes zero objects
  (test), **including** previously anchor-widened / merge-widened days (churn
  test — the rev-1 gap).
- An 8-reach object is replaced only by a strict two-axis superset; an 8 can
  never replace a 22 (existing tests extended with the 22-over-8 case).
- DTE-7 sweeps unaffected: identity regression above.
- FC-091 merge still refuses `dte_mismatch` (regression: widening must not
  enable cross-DTE unions).
- A failed weekly execution trips the Job alert policy; a lake older than 10
  days fails `/regression` on the next weekday `:45` run.

## Design decisions (made — do not relitigate in the build)

- Replacement-not-merge widens DTE; FC-091 refusal stays.
- **Union-with-existing windows, per day** — the only shape the coverage guard
  accepts; whole-window anchors are forbidden in backfill (split inflation).
- One 22-reach file per day, not per-DTE files.
- `MAX_SWEEPABLE_DTE` lives in `overrides.py`; everything else imports it. Import `backfill` by module path only and keep it OUT of `data/__init__.py` exports — `scenarios/__init__` → `runner` → `data` makes an `__init__`-level export a circular-import trap (confirmation-pass caution).
- Battery deferred to Phase B; candidates in the wheel profile only; Saturday
  cadence; constant-not-knob — all as rev 1, all re-verified by review.
- **PR-2 gated behind measurement** — the knob does not open on faith
  (overrides.py's own standard: keys graduate by measurement, not by reading).
- Weekly `--history-days` default 30; deep history only by explicit window.
- Builder model frozen equal to the sweep path's; model changes are their own
  PR across all writers.

     at IV 120%; the 0.25 window's 0.750 floor is crossed at ~IV 95% (the defect

     credentials. It remains a precondition of rollout §4's first widening
     execution, not of this merge.**

     split-sized move is a comparison between adjacent sessions, so a split on
     the window's first day is invisible without a predecessor bar — and the
     weekly window slides, so that blind spot would move. The extra bars are
     never built into chains.
  6. `split_days()` is a local multi-split variant of `detect_split` (which
     stops at the first move by design); a multi-year widening window can span
     two corporate actions.

  Not deviations, but decisions a reviewer should check: `days_replaced_wider`
  means "written over an object that already existed" (every such replacement is
  a superset by construction); the `errors` counter includes corporate-action
  skips, so a real split makes the Job exit non-zero — and page — for the ~4
  weekly runs it takes to age out of the trailing window. That is the plan's
  rule (§A2) applied literally, and is documented as intended in
  `SymbolBackfill.failed` and in the alert policy.
