Its pin bought no comparability (rows spanned four engine versions). Operator decision 2026-10-02.
- **Decommission in two PRs split on the engine-identity boundary.** PR-1 touched the live trading server and monitoring config and could not move `engine_identity`; PR-2 moved it once and bundled every `src/` comment edit into that one move (each later `src/` sweep would cost a cold Saturday). Rollback independence is one-directional and was recorded as such.
- **Keep `options_wheel.backtest_runs`** (D-1) as the evidence base FC-034/FC-055 cite; **delete the Job and scheduler** (D-2) — a Job whose code no longer exists is a trap; **full removal, not endpoint-only** (D-3) — "we don't want stale code sitting around".
- **`ENGINE_VERSION` lives in `engine_identity.py`**, already stdlib-only and already holding a pinned copy; a third `version.py` was rejected. The dashboard duplicate stays for now (FC-129 proposes single-sourcing by flat-copying the module into the dashboard image).
- **`config_hash` got a new module; `bq_writer.py` was deleted** rather than kept as a writer that writes nothing.
- **Report strings untouched** (`scenarios/report.py`, `sweep_report_text.py`): still true, and editing them moves report bytes and golden fixtures.
- **Alert filter keeps explicit Job names** (a name-free `cloud_run_job AND severity>=ERROR` filter was considered); the new contract test ties the set to the build's deploy steps so a future Job cannot go unwatched silently.
- **R-2 (deletes) moved before the merge** so the PR's docs state facts at merge time; **R-1 given an exact in-place `policies update` command, policy id and `mutateTime` baseline** after a reviewer showed the previous wording would have created a duplicate policy.

## Discoveries

- **The screen Job was SHA-pinned at a pre-FC-091 image** (`5e98ff7`, pinned hours before FC-091 merged on 08-28), so the 09-01 and 10-01 monthly screens never ran the merge code. "Verify on the next monthly screen" could never have passed. The weekly Jobs track `main`; only the screen was pinned.
- **FC-091 became unhealable the day the lake went to DTE 22** (FC-096 Phase A, 09-01). The screen built at DTE 8; the review-mandated DTE-equal rule refused every union (`dte_mismatch` × 1,138 on the 10-02 run). The code behaved exactly as designed; its premise had moved.
- **The battery never evaluates the full trailing year** — a ~9-month `fit` split and a 90-day `holdout`. AMZN flipped marginal/unfit/marginal/marginal/unfit across five Saturdays on the same engine (+5.3 %, +0.5 %, +5.0 %, +7.9 %, −4.5 % return on collateral), while the screen's full-year read stayed marginal. One week's `demote` is noise; several Saturdays and both splits are the signal.
- **`tools/monitoring/emergency_stop.sh` stops nothing** (FC-123): it pauses three scheduler names that do not exist, `&& echo` exempts the failures from `set -e`, it touches only the wheel service, and it prints "EMERGENCY STOP COMPLETE". Advertised in `README.md` as the emergency procedure.
- **Every push to `main` redeploys both bots** (FC-125): the build trigger is `^main$` with no path filter; three docs-only commits ran three full builds in one night.
- **Cloud Run Job stdout carries no LogEntry severity** (`src/utils/logger.py` emits `level`), so the Job-failure policy has only ever matched the platform's `system_event` "Execution … has failed to complete" entries — two in its life, both `NonZeroExitCode`. A Job that logs an error and exits 0 is invisible (FC-098).
- **`smoke-test-sim` has never run its authenticated half** — Cloud Build cannot mint the identity token; every build logs `SMOKE_SIM_HTTP_UNAVAILABLE` (FC-128). The real post-deploy check is an authenticated `/health` with the claude-operator SA token, which works.
- **`gcloud alpha monitoring policies update` silently no-ops** when the runbook exceeds 4000 bytes (fc-117 precedent); verify by re-reading `mutationRecord.mutateTime`.
- **A worktree under the repo root is not env-isolated:** `Config` calls bare `load_dotenv()`, which walks up to the operator's `.env`. CI-equivalent runs must come from a clone outside the repo root.
- **Every import of the deleted modules was a lazy in-function import** (eleven sites; ten re-pointed, one deleted with its function) — the failure mode is at call time on a Saturday, not at import. Hence T-1.
- **`engine_identity` hashes comment bytes** (FC-129): a `src/` docstring fix invalidates every stored sweep.
- **Audit `system_event` logs live 400 days; app logs 30.** The 09-01 screen's own logs were already gone on 10-01.
- **Concurrent sessions on the same repo:** FC-122 was taken by another session while this one was about to use the number — always `git pull` and re-read the highest FC number immediately before filing. Another session's worktree cleanup removed two finished reviewer worktrees (no loss) and reverted an index row (restored).
- **The auto-mode classifier denied `gcloud run jobs execute`** (production deploy) and once a read-only `jobs describe` batch; `gcloud logging read`, `bq query`, scheduler/job describes and `print-identity-token` were permitted. Job executions are the operator's.
