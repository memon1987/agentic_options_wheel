# Release Notes — 2026-07-18

## Summary

Operations session. Discovered that **FC-031 had never actually deployed** — it sat behind a red Cloud Build for 11 days while everyone believed the new dashboard was live. Root-caused and fixed that, deployed FC-031 for real, ran its outstanding backfills, then built the project's **first notification channel** so the same silence cannot recur: Cloud Build failure alerting plus FC-030's drawdown-pause alerting. Both alerts share one email channel.

The theme of the day was **silent failure**. Every significant find was something that looked healthy from the inside: a red build nobody saw, an alert policy that matched zero log entries while the endpoint reported success, a test suite that would have gone green while testing nothing, and 18 CI failures that passed locally. Three separate defects traced to the same root cause — *a test whose result depends on ambient environment* — which is now blocked structurally in `conftest.py`.

### Bug Fixes

- **FC-031 was never deployed (11 days).** Cloud Build failed on the merge commit: three `call_seller` tests left the FC-029 BigQuery cost-basis fallback unmocked and queried **live production BigQuery**. AAPL's real $305 assignment (2026-06-13) entered the 90-day lookback, so the fixtures' mocked $160 price read as a 47% drawdown, the R3 pause fired, and evaluation returned before `find_suitable_calls`. Latent since FC-029 — the May builds passed only because AAPL/MSFT had no assignments in the window then. Fixed by stubbing the lookup; FC-031 then deployed (dashboard `00201`, bot `00278`) and its SPY (274 bars) + FEE (1,017 rows) backfills ran.

- **The pause alert would never have fired.** Found by the mandatory fire drill. The policy filter carried `severity>=WARNING`, but Cloud Run only assigns a severity to *structured JSON* logs — Python's `logging.warning()` writes plain text, so entries land as `DEFAULT`. Unit tests green, endpoint returning `"alerted": true`, log line present and correctly formatted, policy matching nothing. Filter now matches on the marker string alone; the runbook documents why severity must not be re-added.

- **18 CI failures from the FC-032 merge (PR #35), main red ~20 min** ([#44](https://github.com/memon1987/agentic_options_wheel/pull/44)). `test_clock_seam.py` and `test_backtest_simulator.py` construct a real `Config()`, which validates Alpaca credentials — present in a developer `.env`, absent in Cloud Build. Fixed structurally with an autouse `conftest.py` fixture, beside the existing `_no_production_bigquery` sibling.

- **Misleading credential error message.** `Config` validation said *"check `ALPACA_API_KEY_ID` env var"* — **nothing reads that name.** `config/settings.yaml` substitutes `${ALPACA_API_KEY}` and `.env.example` documents `ALPACA_API_KEY`. Anyone debugging by following the message would set the wrong variable and stay broken. The pre-existing opt-in `mock_env_vars` fixture carried the same wrong name.

- **Flaky deploy smoke tests** ([#43](https://github.com/memon1987/agentic_options_wheel/pull/43)). Both the bot and dashboard smoke steps sampled revision status **once** and failed on anything `!= True`; a revision still coming up reports `Unknown`, so a healthy deploy could fail the build — observed once today. Now polls up to 150s, passing on `True` and failing fast on a genuine `False`. This matters more now that build failures page the operator: a flaky red build is how a new alerting channel dies of fatigue.

- **`--set-env-vars` silently wiped `PAUSE_ALERT_THRESHOLD_DAYS`.** It replaces the entire env set, so the fire-drill override applied via `--update-env-vars` vanished on the next deploy. Harmless only because the code default matched the desired value. The threshold is now declared in `cloudbuild.yaml`.

- **AMD known-reconciliation gap retired.** The paper-engine anomaly (−$1,594, FC-019) resolved upstream: AMD's OPTRD ledger nets to 0 shares, no share-count mismatches, and the raw residual reconciles to $223 without the allowance. The stale entry was itself tripping the warn banner — the stale-allowance detector catching its own allowance, exactly the rot mode the FC-031 adversarial review (F6) predicted.

- **FC ledger de-duplicated.** Two parallel sessions closed out FC-030 independently (PRs #41 and #42, equivalent fixes), and the merge duplicated the **entire Completed section** — 17 entries twice, with six active entries stranded between the two copies. Repaired to one Completed section with all 40 FCs preserved exactly once, verified programmatically.

## Key Decisions & Rationale

- **Build alerting before pause alerting.** The plan called for the pause alert first. The evidence said otherwise: the most expensive silent failure of the preceding two weeks was not a missed drawdown pause but a red build nobody saw, which cost 11 days of undeployed work at a ~10% historical failure rate. Same channel, so the sequencing was free — and it caught three failures the same day.

- **Fire drill on day one, not "when it naturally fires."** This is the decision that paid. Both the code and the endpoint response reported success; only end-to-end verification revealed the policy matched nothing. An alert believed to work but silent is worse than no alert, because it displaces vigilance.

- **Structural fixes over per-test patches.** Three defects shared one root cause — a test depending on ambient environment (live BigQuery, an absent FastAPI, missing credentials). Rather than patch each, the fixes moved to `conftest.py` fixtures and a dependency-free service module. Two of the three classes are now impossible by construction.

- **A rejected shortcut worth recording.** The natural fix for the FastAPI import was a module-level `pytest.importorskip`. Verified before adopting: it aborts collection of the *whole file*, silently skipping the 10 pure tests as well — CI would have gone green while testing nothing. Replaced with a class-scoped skip. The same failure mode this session exists to prevent, nearly introduced by the fix for it.

- **FC-033 stays deferred.** With only 1 completed cycle since FC-029, the regime split built to evaluate that re-tune has no signal. Changing strategy again — particularly a change that reverses FC-029 R2's cost-basis floor — before the previous change is measurable is how a parameter set becomes unattributable. Revisit at ~10 post-FC-029 cycles, with the pause-duration data this session started collecting.
