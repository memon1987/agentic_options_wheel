### Bug Fixes

- **FC-067 (PR #88): the trade journal labeled EVERY trade as a put.** Root
  cause: scanner opportunity dicts carry the leg under `type` (`put`|`call`) and
  no `strategy` key, while `record_trade` read `option_type`/`strategy` — keys
  the single caller's `{**opp}` never supplied — so both defaulted
  (`put`/`sell_put`). Puts were right by accident; covered calls were mislabeled
  (the 29 known bad rows). Fix, hardened by its adversarial review: derive the
  leg **OCC-symbol-first** (`strict_option_type(option_symbol)` → `option_type`
  → `type` → infer from strategy), because `execute_batch` routes by the symbol
  on declared/symbol drift (FC-048) and the audit row must record the leg
  actually traded. Strategy follows the resolved leg. Absent leg → null, never a
  guessed `put`. Forward-only; the 29 historical rows need a separate corrective
  UPDATE (deferred, see Known Issues).
- **DD-4 (in PR #89): cross-account cost-basis contamination.**
  `CostBasisResolver._lookup_assignment_basis` hardcoded
  `options_wheel.trades_from_activities`; on the covered-call service the
  divergence cross-check would reconstruct the **wheel account's** put-assignment
  lots for any shared underlying (e.g. both accounts holding AAPL), never match
  the CC account's `avg_entry_price`, and fail-close the symbol as
  `SOURCE_DIVERGENT` — **permanently blocking covered-call trading on it with
  wrong-strategy data**. Both read chokepoints (`CostBasisResolver`,
  `UncoveredDaysResolver`) now read `config.bigquery_dataset`. Found by the
  design pass, not by an outage.
- `Config.stock_symbols` now returns `[]` when there is no `stocks` section
  (covered-call profile) instead of `KeyError` — `getattr(config,
  'stock_symbols', [])` at `/config` did NOT swallow the property's KeyError
  (getattr only catches AttributeError), so `/config`, `/backtest/screen`, and
  `get_market_overview` would have 500'd on the CC service. Wheel unchanged
  (validation still requires non-empty for the wheel).

## Key Decisions & Rationale

- **No new engine file.** The parent plan sketched `covered_call_engine.py` + a
  state manager; the design pass, verifying the post-FC-068/069 tree, found the
  handlers already ARE the orchestrator and everything between them is
  call-capable. A wrapper would have duplicated the `/run` safety rails
  (idempotency, non-retryable filter, RunDecisionFlusher, mark-executed) — the
  fork-in-disguise the FC explicitly forbids. A state manager would recreate the
  fiction FC-069 just deleted.
- **Gate on `strategy_id`, not a `trades_puts` knob.** A strategy's legs are
  identity, not tunables; a second boolean that can contradict the required
  identity key is a new misconfiguration surface (the exact fail-open class
  Phase 1's review caught).
- **DD-7 as code, not process.** The reliability plan-reviewer's strongest
  finding: `/scan` and `/run` themselves write BQ (decision_events, trades,
  executions), and `main.py` bypasses route decorators entirely — so "don't
  deploy until Seam 4" was unenforceable. `writes_isolated` makes contamination
  structurally impossible; **Seam 4 removes the guard as its final step**.
- **FC-067 fixed at the journal, symbol-first.** One choke point rather than
  N producers; and label-from-declared-key would journal a leg the engine didn't
  trade on FC-048's drift path — the review caught my first attempt doing
  exactly that.
- **Backtest = optional, not a go-live gate** (operator decision): paper trading
  is itself a zero-capital forward test, and FC-056 (calls priced ~32% low,
  cause unknown) makes backtest output a conservative floor unusable for tuning.
  Reserved for pre-real-money.
- **Process note:** both code reviews returned REQUEST_CHANGES for an
  **under-delivered test contract + an overclaiming docstring**, while
  explicitly affirming the production code (no naked-call path, no over-write,
  no below-basis strike, wheel-neutral). The tests now exist; the lesson —
  deliver the full test contract before opening the PR — is recorded in memory.
